6.4.1 项目管理原则（12 条）
212 条原则 + 口诀
  • 用途：指导项目参与者的行为，帮助参与项目的组织和个人在项目执行过程中保持一致性
  • ① 勤勉、尊重和关心他人 ② 营造协作的项目团队环境 ③ 促进干系人有效参与 ④ 聚焦于价值 ⑤ 识别、评估和响应系统交互 ⑥ 展现领导力行为 ⑦ 根据环境进行裁剪 ⑧ 将质量融入到过程和成果中 ⑨ 驾驭复杂性 ⑩ 优化风险应对 ⑪ 拥抱适应性和韧性 ⑫ 为实现目标而驱动变革
  • 口诀「勤 · 营 · 促 · 价 · 系，展 · 裁 · 质 · 驾 · 优，拥 · 驱」
🚩 清单判断题套路：7 个编号句子混入「专注于工作过程的能力」「处理采购事宜」等不属于原则的表述——背全 12 条名称是唯一解法
3原则 1~4 关键点
  • ① 勤勉尊重关心：关注组织内部和外部职责；坚持诚信、关心、可信、合规；整体观综合考虑财务、社会、技术和可持续的发展环境（PMBOK 助记「管家式」）
  • ② 营造协作团队环境：项目由项目团队交付；团队在组织文化和准则范围内工作，通常建立自己的「本地文化」；协作环境有助一致性 + 个人和团队学习发展 + 最佳贡献
  • ③ 促进干系人有效参与：干系人影响项目、绩效和成果；通过互动为干系人服务；干系人参与可主动推进价值交付（最大化积极、最小化消极影响）
  • ④ 聚焦于价值：⭐价值是项目成功的最终指标；可在项目期间、结束或完成后实现；可定性 / 定量定义衡量；以成果为导向；评估进展并调整使价值最大化
高频判断：「价值只能在项目结束后实现」❌——项目期间也可以
4原则 5~8 关键点
  • ⑤ 系统交互：项目 = 多个相互依赖且相互作用的活动域组成的系统；需从系统角度思考（内部各部分 + 与外部系统交互）；系统不断变化，始终关注内外部环境
  • ⑥ 展现领导力行为：⭐任何项目团队成员都可以表现出领导力行为；领导力与职权不同；按情境调整风格、认识动机差异性；在诚实、正直和道德行为规范方面展现期望行为
  • ⑦ 根据环境进行裁剪：每个项目都具有独特性；成功取决于适合项目的独特环境和方法；裁剪应在整个项目进展过程中持续进行
  • ⑧ 将质量融入过程和成果：质量要求 = 达到干系人期望并满足项目和产品需求；通过成果的验收标准来衡量
🚩「领导力行为只属于项目经理」❌；「裁剪只在启动阶段一次完成」❌——持续进行
5原则 9~12 关键点
  • ⑨ 驾驭复杂性：四个来源 = 人类行为、系统交互、不确定性、技术创新；需持续识别并降低影响
  • ⑩ 优化风险应对：风险 = 影响目标的不确定事件，含机会和威胁；全生命周期识别评估；结合组织风险偏好；最大化机会、最小化威胁
  • ⑪ 拥抱适应性和韧性：适应性 = 应对变化的能力；韧性 = 从挫折中恢复的能力；可经较短反馈路径、持续学习、多样化团队提升
  • ⑫ 为实现目标驱动变革：结构化方法推动组织从当前状态过渡到未来状态；项目早期开始沟通愿景与目标；双向沟通营造环境、合作解决抵制；⭐变革饱和——太短时间过多变革会受抵制，须掌握变革节奏；实施后强化效果、避免回到初始状态
🚩「变革推进越快越好」❌；「风险只有负面含义」❌——机会与威胁两面
6.4.2 项目生命周期和项目阶段
6定义 + 通用结构 4 阶段
  • 项目生命周期 = 项目从启动到完成所经历的一系列阶段，阶段间关系可顺序、迭代或交叠进行；为项目管理提供基本框架，适用于任何类型的项目
  • 通用结构 4 阶段（不论大小繁简）：启动项目 → 组织与准备 → 执行项目工作 → 结束项目
  • 各阶段典型输出：启动（项目章程）→ 组织与准备（项目管理计划）→ 执行（验收的可交付成果）→ 结束（存档的项目文件）
🚩「阶段间只能顺序进行」❌；「生命周期只适用于大型项目」❌
7两大特征曲线
  • ① 成本与人力投入：开始时较低 → 工作执行期间最高 → 快要结束时迅速回落
  • ② 风险与不确定性：开始时最大，随决策的制定与可交付成果的验收逐步降低；同时变更和纠错成本随项目接近完成而显著增高
  • 补充：上述特征在几乎所有项目生命周期中都存在，但程度有所不同
三条曲线方向别接反：风险「始最高→渐低」、变更代价「越晚越高」、人力「低→高→回落」——判断题高发区
6.4.2 开发生命周期 5 种
85 种总览 + 预测型
  • 5 种：预测型（瀑布 / 计划驱动）· 迭代型 · 增量型 · 适应型（敏捷 / 变更驱动）· 混合型；采用不同开发生命周期的项目呈现不同的项目生命周期特点
  • 预测型适用：已经充分了解并明确确定需求的项目
  • 做法：早期阶段确定范围、时间和成本；对任何范围变更严格管理；每个阶段只进行一次，各阶段侧重特定类型的工作
  • 高度预测型：范围变更很少、干系人高度共识，受益于前期详细规划；但增加范围 / 需求变化 / 市场变化会导致某些阶段重复进行
「每个阶段只进行一次」是预测型独有表述——别把它安到适应型头上
9迭代型 vs 增量型
  • 迭代型：范围通常在早期确定，时间及成本随对产品理解的深入而定期修改——通过一系列重复的循环活动来开发产品
  • 增量型：在预定的时间区间内渐进增加产品功能的一系列迭代产出可交付成果；只有在最后一次迭代之后，可交付成果具有必要和足够能力才被视为完整
  • ⭐ 教材辨析金句：迭代方法 = 重复的循环活动开发产品；增量方法 = 渐进地增加产品的功能
蒙娜丽莎助记：迭代 = 先画整幅初稿再反复打磨；增量 = 先画头再画身体逐块构建
10适应型循环 + 混合型
  • 适应型又称敏捷型 / 变更驱动型，适合需求不确定、不断发展变化的项目
  • 完整循环：迭代前——项目和产品愿景的范围被明确定义和批准；迭代中——以迭代（又称「冲刺」）为单位交付；迭代后——客户审查功能性可交付物，关键干系人提供反馈，团队更新待办事项列表、确定下次迭代的优先级
  • 特点：先基于初始需求制定一套高层级计划，再逐渐把需求细化到特定规划周期所需详细程度
  • 混合型 = 预测型 + 适应型的组合；项目生命周期具有复杂性和多维性——特定项目不同阶段往往采用不同的生命周期，需确定各阶段最适合的生命周期
🚩「混合型 = 迭代型 + 增量型的组合」❌——是预测 + 适应；「一个项目只能用一种生命周期」❌
11表 6-6 五维对比
  • 需求：预测 = 开发前预先确定；迭代增量 = 交付期间定期细化；适应 = 交付期间频繁细化
  • 交付：预测 = 项目结束时一次交付最终产品；迭代增量 = 分次交付各个子集；适应 = 频繁交付对客户有价值的子集
  • 变更：预测 = 尽量限制；迭代增量 = 定期融入；适应 = 实时融入
  • 干系人参与：预测 = 特定里程碑点；迭代增量 = 定期；适应 = 持续参与
  • 风险成本控制：预测 = 对基本已知情况编制详细计划；迭代增量 = 用新信息逐渐细化计划；适应 = 随着需求和制约因素的显现而控制
三列节奏递进：预测「前定/一次/限制」→ 迭代增量「定期/分次」→ 适应「频繁/实时/持续」——适应型一列全是「快进」词
防坑与旧题甄别
12高频陷阱 + 旧题甄别
  • ① 「价值只能在项目结束后实现」❌（项目期间 / 结束 / 完成后均可）② 「领导力行为只属 PM」❌（任何成员）③ 「裁剪一次性动作」❌（持续进行）④ 「风险只有威胁」❌（机会 + 威胁）⑤ 「变革越快越好」❌（防变革饱和、掌握节奏）
  • ⑥ 「阶段只能顺序进行」❌（可顺序 / 迭代 / 交叠）⑦ 「每个阶段只进行一次」是预测型的表述 ⑧ 「混合型 = 迭代 + 增量」❌（预测 + 适应）⑨ 清单判断题混入「专注于工作过程的能力」「处理采购事宜」等非原则表述
  • 旧题甄别：12 原则与 5 种开发生命周期均为第 4 版（PMBOK 第 7 版口径）新增，2023 下之前旧真题无对应题；旧题考「49 过程」等第 6 版口径按教材为准

总结区 本段本质 + 考点地图
本段本质：全书项目管理知识的「宪法 + 进化论」——12 条原则是所有干系人在项目全生命周期的行为指南（勤营促价系，展裁质驾优，拥驱），5 种开发生命周期回答「不同需求确定度下项目怎么开发」（预测一次到位 / 迭代循环打磨 / 增量逐块拼装 / 适应冲刺反馈 / 混合两端组合）。生命周期两条铁律：风险开始最大、变更代价越晚越高——这是后续一切「尽早发现变更」类考题的出处。
