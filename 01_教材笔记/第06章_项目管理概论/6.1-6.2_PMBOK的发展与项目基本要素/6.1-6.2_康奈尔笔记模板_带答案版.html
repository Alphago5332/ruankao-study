6.1 PMBOK的发展
1PMBOK 定位与发展脉络 + 四个关键版本
  • PMBOK（项目管理知识体系）是美国项目管理协会（PMI）开发的项目管理知识框架，核心是总结项目管理的优秀实践、知识、技能和工具
  • 自 1981 年启动研发，多版更新，截至 2022 年已发布 7 版，其中 4 个版本变化最为突出：
  • 1996 第 1 版：定位「项目管理知识体系指南」，采用基于过程的标准，奠定项目管理专业化基础
  • 2004 第 3 版：首次标注 ANSI 标准，区分《项目的项目管理标准》和《项目管理框架和知识体系》
  • 2017 第 6 版：清晰区分 ANSI 标准和指南，首次将「敏捷」内容纳入正文，补充核心概念 / 新兴实践 / 裁剪因素
  • 2021 第 7 版：从系统视角论述项目管理，加入「价值交付系统」，新增 8 个绩效域和 12 个项目管理原则，兼容多种开发方法
记法「96 初版定专业 · 04 标 ANSI · 17 纳敏捷 · 21 转原则」；开发主体 = PMI；启动研发 = 1981
2第 6 版 → 第 7 版的架构转型
  • 第 6 版（2017）：架构 = 5 大过程组 + 10 大知识领域（49 个过程），过程导向，侧重「怎么做」（流程、ITTO）
  • 第 7 版（2021）：架构 = 12 个项目管理原则 + 8 个绩效域，系统视角，侧重「为什么做」（结果、价值、原则）
  • 第 7 版新增：价值交付系统（聚焦价值链与业务能力结合，交付价值给组织及干系人）
⚠️ 第 4 版教材以第 7 版为纲，但「5 过程组 + 10 知识领域」并未作废——仍在教材 6.4.3 / 6.4.4 讲述
6.2.1 项目基础
3项目定义 + 两大特性
  • 项目是为创造独特的产品、服务或成果而进行的临时性工作——两个关键词 = 独特性 + 临时性
  • 临时性：有明确的起点和终点；不一定意味着持续时间短；终止情形 = 达成目标 / 无法达成目标 / 资金耗尽 / 需求消失；可交付成果可能长期存在（如纪念碑）
  • 独特性：可交付成果（有形或无形）具有唯一性；即便元素相似，需求、环境、干系人等仍有差异
🚩 三大陷阱：「临时 = 时间短」❌；「项目临时 → 成果也临时」❌；「有重复元素 → 不独特」❌
4驱动变更 + 业务价值 + 启动背景 4 类
  • 项目驱动变更：从业务价值角度看，项目旨在推动组织从「当前状态」转换到「将来状态」
  • 创造业务价值两类效益：有形效益（货币资产、市场份额）/ 无形效益（商誉、品牌认知度、战略一致性）
  • 项目启动背景 4 类因素（记法「法 · 干 · 产 · 战」）：①符合法律法规或社会需求 ②满足干系人要求 ③创造 / 改进 / 修复产品、过程或服务 ④实施或变更业务或技术战略
「当前态 → 将来态」表述与 6.2.3 成功标准、6.4.1 原则 12 反复呼应，全章通用
6.2.2~6.2.3 重要性 / 成功标准
5项目管理定义 + 重要性正反对照
  • 项目管理是将知识、技能、工具与技术应用于项目活动，以满足项目的要求
  • 项目是组织创造价值的主要方式；有效高效的项目管理是组织的战略能力
  • 有效项目管理价值：达成业务目标 / 满足干系人期望 / 提高可预测性和成功率 / 按时交付合格产品 / 应对风险 / 优化资源使用 / 管理变更
  • 缺失项目管理后果：超时超支质量低劣 / 返工 / 范围失控 / 组织声誉受损 / 干系人不满 / 无法达成目标
出题套路：给一条描述问属于「价值」还是「后果」——抓「可预测性」「按时交付」代表词
6项目成功的标准
  • 项目成功不仅看时间、成本、范围、质量等传统指标，更需关注业务价值的实现
  • 判断维度：完成项目效益管理计划；达成财务指标（NPV、ROI）和非财务目标；组织从当前状态成功过渡到将来状态；履行合同条款、满足干系人期望、用户采纳度高、符合治理规则
  • ⚠️ 成功标准因项目而异，须由干系人认可；业务需求 / 市场环境变化时，可能出现「范围 / 进度 / 预算都达标但业务层面失败」
🚩 判断题「按期在预算内范围质量达标 = 项目一定成功」直接判错——项目需持续与组织战略对齐
6.2.4 四方关系
7项目 / 项目集 / 项目组合 / 运营管理
  • 项目：创造独特产品 / 服务 / 成果的临时性工作 → 正确地做事（按计划交付成果）
  • 项目集：相互关联且被协调管理的项目 / 子项目集 / 活动，获取单独管理无法获得的效益 → 正确地做事（协调组件实现整体效益）；例：通信卫星系统
  • 项目组合：为实现战略目标组合管理的项目 / 项目集 / 运营工作，组件不一定相关 → 做正确的事（选择符合战略的组件）
  • 运营管理：持续生产 / 提供服务，重复性、持续性 → 高效地做事；不属于项目管理范围
记法「项目、项目集都正确地做事，组合做正确的事，运营高效地做事」；项目组合包含运营工作是教材明确写法
8项目集 vs 项目组合 + OPM
  • 项目集管理注重项目之间的依赖关系，拥抱变更、通过变更寻求最优值与整体目标
  • 项目组合组件间不一定彼此依赖或直接相关（如文件夹与文件）；通过确定各组件优先级，让最有利于战略目标的部分获得财力 / 人力 / 实物资源
  • 项目与项目集管理聚焦「如何做好」，项目组合管理聚焦「做什么」；项目与运营在产品生命周期交叉（新产品开发 / 产品升级 / 生命周期结束）
  • 组织级项目管理（OPM）：通过对【项目组合、项目集和项目】进行系统化管理，确保项目符合组织战略业务目标，确保组织开展正确项目并合适地分配关键资源
教材原句「项目组合做正确的事，项目集和项目为正确地做事」；OPM 抓「系统化管理 + 战略业务目标」
6.2.5 项目内外部运行环境
9OPA 与 EEF
  • 定性：OPA「支持」项目（执行组织正式使用的计划、流程、政策、程序和数据，可复用）；EEF「制约」项目（内外部客观条件）
  • OPA 五类（记法「过 · 治 · 数 · 知 · 保」）：过程资产（工具 / 方法论 / 模板 / PMO 资源）/ 治理文件（政策、流程）/ 数据资产（以前项目的数据库、度量指标）/ 知识资产（员工隐性知识）/ 安保和安全
  • 内部 EEF：组织文化结构与治理 / 设施物理分布 / 基础设施 / 信息技术软件 / 资源可用性 / 员工能力
  • 外部 EEF（记法「市社监库研标财物」）：市场条件 / 社会文化因素 / 监管环境 / 商业数据库 / 学术研究 / 行业标准 / 财务因素 / 物理环境
🚩 「进度计划软件」属内部 EEF（信息技术软件），不是 OPA——最高频错点；「商业数据库 / 学术研究」属外部 EEF
6.2.6 组织系统
10治理框架 + 六大组织结构权力谱
  • 治理框架 = 组织行使职权的规则、政策、程序（影响目标设定 / 风险监控 / 绩效优化）；管理要素 = 关键职能或一般管理原则（部门设置、职责分配、统一指挥 / 统一领导、资源优化利用、沟通渠道）
  • 六大组织结构（项目经理职权由低到高）：职能（集中式）兼职·极少或无·职能经理管预算 → 弱矩阵 兼职·低·职能经理 → 均衡矩阵 兼职·低到中·「混合」 → 强矩阵 全职·中到高·项目经理 → 项目导向 全职·高到几乎全部·项目经理 → PMO 全职·高到几乎全部·项目经理
🚩 兼职 / 全职分界线 = 强矩阵（弱、均衡矩阵均兼职）；均衡矩阵预算管理者是「混合」；真题给「多少人全职 + 谁管预算」反推组织结构
11PMO 三类型 + 主要职能
  • PMO = 对项目相关治理过程进行标准化，并促进资源、方法论、工具和技术共享的组织结构
  • 三类型（记法「支低 · 控中 · 指高」）：支持型（顾问角色、项目资源库，控制程度低）/ 控制型（要求项目服从统一框架 / 工具 / 治理，控制程度中）/ 指令型（直接管理和控制项目、指定项目经理，控制程度高）
  • 主要职能 6 条（记法「资 · 法 · 导 · 审 · 文 · 通」）：①管理共享资源 ②识别制定项目管理方法、最佳实践和标准 ③指导、辅导、培训和监督 ④通过项目审计监督合规性 ⑤制定管理政策 / 程序 / 模板（组织过程资产）⑥协调跨项目的沟通
6.2.7 项目管理和产品管理
12产品生命周期 + 项目管理 vs 产品管理
  • 产品：可量化生产的工件（包括服务）；产品生命周期四阶段 = 引入、成长、成熟、衰退
  • 产品管理：在产品全生命周期内对产品进行创建、维护和开发
  • 三点关联：产品生命周期中可包含多个项目集 / 项目；项目可交付物可能是产品的初始版本或组件；产品管理可由产品生命周期内多个项目集 / 项目实现
  • 核心区别：项目管理聚焦「临时性成果交付」，产品管理聚焦「全生命周期价值实现」
⚠️ 产品生命周期（引入成长成熟衰退）≠ 项目生命周期（启动→组织与准备→执行→结束，6.4.2 讲）——两个「生命周期」不是一回事
