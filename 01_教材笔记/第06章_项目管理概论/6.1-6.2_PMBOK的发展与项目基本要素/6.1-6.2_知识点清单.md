### 模块 A ｜ PMBOK 的发展（6.1）

- [ ] **A0 · PMBOK 的定位与发展脉络** ⭕ 必背（总起）
  **PMBOK（项目管理知识体系）是美国项目管理协会（PMI）开发的项目管理知识框架**，核心是**总结**项目管理的优秀实践、知识、技能和工具。

### 模块 B ｜ 项目基础（6.2.1）

- [ ] **B0 · 项目的定义** ⭕ 必背（一切考题的起点）
  **项目是为创造独特的产品、服务或成果而进行的临时性工作。**
  - 两个关键词 = **独特性 + 临时性**，缺一不可
  > 高频：判断题给一个活动（如「流水线批量组装」「日常运维值班」）问是否项目 → 看是否有**明确的起点终点**（临时性）与**独特成果**（独特性）
- [ ] **B1 · 临时性与独特性的精确含义** ⭕ 必背（两大高频陷阱）
  - **临时性**：项目有**明确的起点和终点**；**「临时性」并不一定意味着项目的持续时间短**；项目终止的情形包括：**达成目标 / 无法达成目标 / 资金耗尽 / 需求消失**等；**可交付成果可能长期存在**（如纪念碑建成后矗立百年）
  - **独特性**：可交付成果（**有形或无形**）具有唯一性，即便元素相似，**需求、环境、干系人**等仍有差异（如同一团队开发的不同信息系统）
  > 陷阱 1：「临时 = 时间短」❌；陷阱 2：「项目临时 → 成果也临时」❌（成果可长期存在）；陷阱 3：「重复元素 → 不独特」❌（重复元素的项目本质仍独特）
- [ ] **B2 · 项目驱动变更与创造业务价值** ⭕ 必背（价值视角，第 7 版特色）
  - **项目驱动变更**：从业务价值角度看，项目旨在推动组织从「**当前状态**」转换到「**将来状态**」，实现特定目标和更高业务价值
  - **创造业务价值**：效益分为两类——
    | 类型 | 例子 |
    |---|---|
    | **有形效益** | 货币资产、市场份额等 |
    | **无形效益** | 商誉、品牌认知度、战略一致性等 |
  > 记法：「**当前态 → 将来态**」这个表述与 6.2.3 成功标准、6.4.1 原则 12 反复呼应，全章通用
- [ ] **B3 · 项目启动背景 4 类因素** ⭕ 必背（分类列举）
  | # | 因素 | 例子 |
  |---|---|---|
  | ① | **符合法律法规或社会需求** | 政策变革驱动战略调整 |
  | ② | **满足干系人要求** | 干系人提出新需求 |
  | ③ | **创造 / 改进 / 修复产品、过程或服务** | 市场需求驱动新产品研发 |
  | ④ | **实施或变更业务或技术战略** | 技术升级、业务转型 |
  > 记法：**「法 · 干 · 产 · 战」**（法律法规 / 干系人 / 产品过程服务 / 战略）

### 模块 C ｜ 项目管理的重要性与成功标准（6.2.2 + 6.2.3）

- [ ] **C0 · 项目管理的定义** ⭕ 必背（与 1996 年第 1 版一脉相承）
  **项目管理是将知识、技能、工具与技术应用于项目活动，以满足项目的要求。**
  > 与「项目」定义区分开：项目 = 临时性工作；项目管理 = 应用知识技能工具技术的**过程**
- [ ] **C1 · 项目管理的重要性（正反对照）** ⭕ 必背（价值罗列）
  - **项目是组织创造价值的主要方式**；有效高效的项目管理是**组织的战略能力**，帮助组织应对外部变化、保持竞争力
  - **有效项目管理的价值**：达成业务目标 / 满足干系人期望 / 提高可预测性和成功率 / 按时交付合格产品 / 应对风险 / 优化资源使用 / 管理变更等
  - **缺失项目管理的后果**：项目超时超支、质量低劣 / 返工 / 范围失控 / 组织声誉受损 / 干系人不满 / 无法达成目标
  > 出题套路：给一条描述（如「按时交付合格产品」）问属于「有效项目管理的价值」还是「缺失项目管理的后果」
- [ ] **C2 · 项目成功的标准** ⭕ 必背（第 7 版新口径）
  项目成功**不仅看时间、成本、范围、质量**等传统指标，**更需关注业务价值的实现**。核心判断维度包括：
  - 完成**项目效益管理计划**；达成**财务指标**（净现值 NPV、投资回报率 ROI 等）和**非财务目标**；组织从「当前状态」成功过渡到「**将来状态**」；履行合同条款、满足干系人期望、**用户采纳度高**、符合治理规则等
  - ⚠️ **成功标准因项目而异**，须由**干系人认可**；业务需求或市场环境变化时，可能出现「**范围 / 进度 / 预算都达标但业务层面失败**」的情况——因此项目需**持续与组织战略对齐**
  > 高频陷阱：「项目按期、在预算内、范围质量达标 = 项目一定成功」❌

### 模块 D ｜ 项目、项目集、项目组合和运营管理的关系（6.2.4）

- [ ] **D0 · 四方定义与管理重点** ⭕ 必背（全章最高频辨析表）
  | 类型 | 核心定义 | 核心特点 | 管理重点 |
  |---|---|---|---|
  | **项目** | 创造独特产品 / 服务 / 成果的**临时性**工作 | 范围渐进明晰、目标明确 | **正确地做事**（按计划交付成果） |
  | **项目集** | **相互关联**且被**协调管理**的项目 / 子项目集 / 活动 | 组件协调互补，获取**单独管理无法获得的效益** | **正确地做事**（协调组件实现整体效益） |
  | **项目组合** | 为实现**战略目标**，组合管理的项目 / 项目集 / 运营工作 | 范围随战略变化，**组件不一定相关** | **做正确的事**（选择符合战略的组件） |
  | **运营管理** | 持续生产产品 / 提供服务，维持组织日常运转 | 重复性、持续性、关注效率 | **高效地做事**（优化日常流程） |
  > 记法：**项目、项目集都「正确地做事」，组合「做正确的事」，运营「高效地做事」**；注意项目组合**包含运营工作**（这是教材明确写法）
- [ ] **D1 · 四方的关键关联** ⭕ 必背（结构关系）
  - 项目集包含多个**相关**项目；项目组合包含多个项目集 / 项目 / 运营工作，**组件间不一定彼此依赖或直接相关**（如文件夹与文件的关系）
  - **项目集管理注重项目之间的依赖关系**，拥抱变更、通过变更寻求最优值与整体目标（例：**通信卫星系统**包括卫星与地面站设计建造、卫星发射及系统整合）
  - 项目和项目集管理聚焦「**如何做好**」，项目组合管理聚焦「**做什么**」；项目组合通过**确定各组件优先级**，让最有利于战略目标的部分拥有所需的财力、人力和实物资源
  - 项目与运营在**产品生命周期**交叉（新产品开发、产品升级、生命周期结束等节点），可交付成果和知识会相互转移
  > 教材原句：**「项目组合做正确的事，项目集和项目为正确地做事」**
- [ ] **D2 · 组织级项目管理（OPM）** ⭕ 必背（一句定义）
  **组织级项目管理通过对【项目组合、项目集和项目】进行系统化管理，确保项目符合组织战略业务目标，确保组织开展正确项目并合适地分配关键资源。**
  > 抓「**系统化管理**」+「**战略业务目标**」两个关键词

### 模块 E ｜ 项目内外部运行环境（6.2.5）

- [ ] **E0 · 组织过程资产（OPA）** ⭕ 必背（支持性、可复用）
  组织过程资产是执行组织**正式使用的计划、流程、政策、程序和数据**，**影响具体项目管理活动的执行**。包括：
  - **过程资产**：工具、方法论、方法、模板、框架、模式或 **PMO 资源**
  - **治理文件**：政策和流程
  - **数据资产**：以前项目的数据库、文件库、度量指标、数据和工件
  - **知识资产**：项目团队成员、主题专家和其他员工的**隐性知识**
  - **安保和安全**：对设施访问、数据保护、保密级别和专有秘密的程序和实践
  > 记法：**「过 · 治 · 数 · 知 · 保」**五类
- [ ] **E1 · 内部事业环境因素（EEF）** ⭕ 必背（制约性、组织内部）
  - **组织文化、结构和治理**：愿景、使命、价值观、文化规范、领导风格、等级制度和职权关系等
  - **设施和资源的物理分布**：工作地点、虚拟项目团队、共享系统
  - **基础设施**：现有设施、设备、组织和电信通道、IT 硬件、可用性和功能
  - **信息技术软件**：进度计划软件、配置管理系统、信息系统网络接口、协作工具、工作授权系统
  - **资源可用性**：合同和采购制约因素、获得批准的供应商和协议
  - **员工能力**：现有员工的专业知识、技能、经验、胜任力
  > 高频：**OPA「支持」项目（可复用资产）vs EEF「制约」项目（客观条件）**；同一事物判断归属——「进度计划软件」是 EEF（内部）不是 OPA，最容易错
- [ ] **E2 · 外部事业环境因素** ⭕ 必背（制约性、组织外部）
  **市场条件**（竞争对手、技术趋势）/ **社会文化因素与趋势**（地域风俗、行为规范）/ **监管环境**（法律法规、非政府组织）/ **商业数据库**（标杆对照指标、风险数据库）/ **学术研究** / **行业标准** / **财务因素**（汇率、利率）/ **物理环境**（天气、工作条件）
  > 记法：**「市 · 社 · 监 · 库 · 研 · 标 · 财 · 物」**八类；「商业数据库」「学术研究」属**外部** EEF，别放内部

### 模块 F ｜ 组织系统（6.2.6）

- [ ] **F0 · 治理框架与管理要素** ⭕ 必背（两分法）
  - **治理框架**：组织**行使职权的规则、政策、程序**等；影响**目标设定与实现、风险监控与评估、绩效优化**
  - **管理要素**：组织**内部的关键职能或一般管理原则**——部门设置、工作职权、职责分配、行动纪律、**统一指挥 / 统一领导**原则、资源的**优化利用**、**沟通渠道**等
  > 抓关键词：「规则、政策、程序」→ 治理框架；「统一指挥、沟通渠道」→ 管理要素
- [ ] **F1 · 六大组织结构类型与项目经理权力谱** ⭕ 必背（全章必背表格）
  | 结构类型 | 项目经理 | 管理人员 | 项目经理职权 | 预算管理者 |
  |---|---|---|---|---|
  | **职能（集中式）** | 兼职 | 兼职 | **极少或无** | 职能经理 |
  | **弱矩阵** | 兼职 | 兼职 | **低** | 职能经理 |
  | **均衡矩阵** | 兼职 | 兼职 | **低到中** | **混合** |
  | **强矩阵** | **全职** | **全职** | **中到高** | **项目经理** |
  | **项目导向** | 全职 | 全职 | **高到几乎全部** | 项目经理 |
  | **PMO** | 全职 | 全职 | **高到几乎全部** | 项目经理 |
  > 记法：权力谱**「职能 → 弱 → 均衡 → 强 → 项目导向 / PMO」由低到高**；**均衡矩阵的预算管理者是「混合」**（职能经理与项目经理共同）——高频陷阱；真题套路：给「多少人全职 / 项目经理是否专职 / 谁管预算」三线索反推组织结构类型
- [ ] **F2 · PMO 三类型与主要职能** ⭕ 必背（类型 + 控制程度）
  PMO（项目管理办公室）是对项目相关治理过程进行**标准化**，并促进**资源、方法论、工具和技术共享**的组织结构。三种类型：
  | 类型 | 角色 | 控制程度 |
  |---|---|---|
  | **支持型** | 顾问角色、项目资源库（提供模板、培训、经验教训） | **低** |
  | **控制型** | **要求项目服从**（统一框架 / 工具 / 治理） | **中** |
  | **指令型** | **直接管理和控制项目**（指定项目经理并对其负责） | **高** |
  **主要职能**（提供支持）：①管理所辖全部项目的**共享资源**；②识别和制定项目管理**方法、最佳实践和标准**；③指导、辅导、培训和监督；④通过项目**审计**监督对标准 / 政策 / 程序 / 模板的**合规性**；⑤制定和管理项目政策、程序、模板及其他共享的文件（组织过程资产）；⑥协调**跨项目的沟通**
  > 记法：控制程度**「支低 · 控中 · 指高」**；主要职能 6 条记**「资·法·导·审·文·通」**

### 模块 G ｜ 项目管理和产品管理（6.2.7）

- [ ] **G0 · 产品与产品管理** ⭕ 必背（定义 + 生命周期）
  - **产品**：可量化生产的工件（包括服务）
  - **产品生命周期**：**引入、成长、成熟、衰退**四阶段（产品从出现到消亡的全过程）
  - **产品管理**：在**产品全生命周期**内对产品进行**创建、维护和开发**的活动（可包含多个项目集 / 项目）
  > 「引入 → 成长 → 成熟 → 衰退」是经典四阶段曲线，与「项目生命周期」（启动→组织与准备→执行→结束）**不是一回事**——后者在 6.4.2 讲
- [ ] **G1 · 项目管理与产品管理的关系** ⭕ 必背（三点关联 + 核心区别）
  - 产品生命周期中可包含**多个**项目集 / 项目（如产品升级通过项目实现）
  - 项目可交付物可能是产品的**初始版本或组件**，后续通过新项目集 / 项目优化
  - **核心区别**：项目管理聚焦「**临时性成果交付**」，产品管理聚焦「**全生命周期价值实现**」
  > 高频：「某产品负责人持续规划产品路线图、管理产品从上市到退市」→ 产品管理；「交付一个版本后项目组解散」→ 项目管理

## 三、自检题（合上清单，口答）

<details>
<summary>点击展开自检参考答案</summary>

1. **PMBOK 由谁开发？何时启动研发？截至 2022 年共几版？**
   答：PMI（美国项目管理协会）；1981 年启动研发；截至 2022 年已发布 7 版，其中 4 个版本变化最突出。
2. **四个关键版本分别是哪年、什么变化？**
   答：1996 第 1 版（基于过程的标准、专业化基础）；2004 第 3 版（首次标注 ANSI 标准）；2017 第 6 版（**首次将敏捷纳入正文**）；2021 第 7 版（价值交付系统 + 12 原则 + 8 绩效域、系统视角）。
3. **项目的定义？两个关键词？**
   答：为创造独特的产品、服务或成果而进行的临时性工作；关键词 = 独特性 + 临时性。
4. **「临时性」的两个高频误区？项目终止的 4 种情形？**
   答：临时 ≠ 持续时间短；临时 ≠ 成果临时（成果可长期存在）。终止情形：达成目标 / 无法达成目标 / 资金耗尽 / 需求消失。
5. **项目启动背景 4 类因素？**
   答：符合法律法规或社会需求 / 满足干系人要求 / 创造改进修复产品过程服务 / 实施或变更业务或技术战略（「法·干·产·战」）。
6. **项目管理的定义？**
   答：将知识、技能、工具与技术应用于项目活动，以满足项目的要求。
7. **项目成功只看时间成本范围质量对吗？**
   答：不对——更需关注业务价值实现（效益管理计划、NPV/ROI 等财务指标、当前态→将来态、用户采纳度等），且成功标准因项目而异、须干系人认可。
8. **项目 / 项目集 / 项目组合 / 运营管理各自的管理重点？**
   答：项目与项目集 = 正确地做事；项目组合 = 做正确的事；运营管理 = 高效地做事。
9. **项目集与项目组合的核心区别？**
   答：项目集组件「相互关联、协调管理、获取单独管理无法获得的效益」；项目组合组件「不一定彼此依赖或直接相关」，为战略目标而组合（可含运营工作）。
10. **OPA 与 EEF 的定性区别？「进度计划软件」属哪个？**
    答：OPA 支持（正式使用的计划流程政策程序数据、可复用）；EEF 制约（内外部客观条件）。「进度计划软件」属**内部 EEF**（信息技术软件），不是 OPA。
11. **六大组织结构类型中，项目经理从兼职变全职的分界在哪？**
    答：**强矩阵**——弱矩阵、均衡矩阵项目经理均为兼职；强矩阵起（含项目导向、PMO）项目经理与管理人员均为全职。
12. **均衡矩阵的预算管理者？PMO 三类型及控制程度？**
    答：均衡矩阵预算管理者是「混合」（职能经理与项目经理共同）；PMO = 支持型（低）/ 控制型（中，要求服从）/ 指令型（高，直接管理）。
13. **产品生命周期四阶段？项目管理与产品管理的核心区别？**
    答：引入、成长、成熟、衰退；项目管理聚焦「临时性成果交付」，产品管理聚焦「全生命周期价值实现」。
