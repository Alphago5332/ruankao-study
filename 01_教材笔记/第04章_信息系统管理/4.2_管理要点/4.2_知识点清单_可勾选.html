一、必背清单

模块 A ｜ 管理要点总览（4.2 引言）

信息系统管理涉及系统准备、设计、实施、运行等活动的众多方面，管理重点的范围和细致程度随各组织的战略和业务目标的不同而存在差异。从日常管理活动视角来看，各组织关注的管理内容主要聚焦在数据管理、运维管理和信息安全管理等方面的体系化管理。

口诀：管理要点三聚焦「数运安」（数据管理 · 运维管理 · 信息安全管理）——正好对应 4.2.1 / 4.2.2 / 4.2.3

模块 B ｜ 4.2.1 数据管理

在通常情况下，数据管理是指通过规划、控制与提供数据和信息资产的职能，包括开发、执行和监督有关数据的计划、策略、方案、项目、流程、方法和程序，以获取、控制、保护、交付和提高数据和信息资产价值。

• 国际数据管理协会（DAMA）指出，数据资源管理致力于发展和处理组织数据全生命周期的适当的构建、策略、实践和程序
• 数据管理框架是对组织的管理平台或者能够产生业务数据的平台产生的数据进行统一的跟踪、协调、管理的功能模型
记法：定义抓三个职能动词「规划 · 控制 · 提供」+ 五类价值动作「获取 · 控制 · 保护 · 交付 · 提高」；DAMA = 国际数据管理协会

数据管理能力成熟度评估模型（DCMM） 是国家标准 GB/T 36073《数据管理能力成熟度评估模型》中提出的，旨在帮助组织利用先进的数据管理理念和方法，建立和评价自身数据管理能力，持续完善数据管理组织、程序和制度，充分发挥数据在促进组织向信息化、数字化、智能化发展方面的价值。

DCMM 定义 8 个核心能力域（含主要能力项）：

#核心能力域主要能力项
1数据战略数据战略规划 / 数据战略实施 / 数据战略评估
2数据治理数据治理组织 / 数据制度建设 / 数据治理沟通
3数据架构数据模型 / 数据分布 / 数据集成与共享 / 元数据管理
4数据应用数据分析 / 数据开放共享 / 数据服务
5数据安全数据安全策略 / 数据安全管理 / 数据安全审计
6数据质量数据质量需求 / 数据质量检查 / 数据质量分析 / 数据质量提升
7数据标准业务术语 / 参考数据和主数据 / 数据元 / 指标数据
8数据生存周期数据需求 / 数据设计和开发 / 数据运维 / 数据退役
口诀：八能力域「战略治理架构 · 应用安全质量 · 标准生存周期」；能力项个数序列「三三四三三四四四」（战略3·治理3·架构4·应用3·安全3·质量4·标准4·生存周期4，共 28 项）
辨析：元数据管理属数据架构；指标数据属数据标准（别挂错域）

DCMM 将组织的管理成熟度划分为 5 个等级：

级别名称特征
1初始级数据需求的管理主要在项目级体现，没有统一的管理流程，主要被动式管理
2受管理级组织意识到数据是资产，根据管理策略的要求制定了管理流程，指定相关人员进行了初步管理
3稳健级数据已被当作实现组织绩效目标的重要资产，在组织层面制定系列的标准化管理流程，促进数据管理的规范化
4量化管理级数据被认为是获取竞争优势的重要资源，数据管理的效率能量化分析和监控
5优化级数据被认为是组织生存和发展的基础，相关管理流程能实时优化，能在行业内进行最佳实践分享
口诀：五等级「初受稳量优」。⭐ 真题落点：从稳健级开始强调「数据管理的规范化」「数据被当作实现组织绩效目标的重要资产」
辨析：稳健级 = 组织层面标准化流程 + 「绩效目标」重要资产；量化管理级 = 「竞争优势」重要资源 + 量化分析监控（两级别对调）

国内外常用的数据管理模型包括：

模型关键口径
DCMM（数据管理能力成熟度模型）5 个等级 + 8 个核心能力域
DGI（数据治理框架）从组织结构、治理规则和治理过程三个维度提出 10 个关键通用组件
DCAM（数据管理能力评价模型）4 个组件（基础组件 / 执行组件 / 分析组件 / 应用组件），强调团队协作（流程）、标准执行和资金支持
DAMA（数据管理模型）11 个数据管理职能领域 + 7 个基本环境要素，构成「DAMA 数据管理知识体系」
口诀：DCMM 五等级 · DGI 三维度 · DCAM 四组件 · DAMA 十一域（「等级 / 维度 / 组件 / 职能领域」四个量词别接错）

模块 C ｜ 4.2.2 运维管理 · 能力模型

国家标准 GB/T 28827.1《信息技术服务 运行维护 第 1 部分：通用要求》定义了 IT 运维能力模型，该模型包含治理要求、运行维护服务能力体系和价值实现三个部分。

• ⭐ 真题落点：运行维护服务能力体系为价值实现赋能
• 能力建设：组织需要考虑环境的内外部因素，在治理要求的指导下，根据服务场景识别服务能力需求，围绕人员、过程、技术、资源能力四要素，策划、实施、检查和改进运行维护能力体系，向各种服务场景赋能，通过服务提供实现服务价值
口诀：模型三部分「治理 · 能力体系 · 价值」；能力建设四要素「人过技资」；运维能力管理四阶段「策划 · 实施 · 检查 · 改进」
要素定位口诀内容
人员能力选人做事运维人员一般分为管理类、技术类和操作类三种人员岗位；依据运维能力策划要求，进行人员能力策划、岗位结构、人员储备、人员培训、绩效管理和能力评价
资源能力保障做事资源包括知识库、服务台、备件库以及运行维护工具
技术能力高效做事发现问题和解决问题的技术
过程正确做事服务级别、服务报告、事件、问题、变更、发布、配置等过程；把人员、技术和资源要素以过程为主线串接
口诀：四种「做事」配对 — 人员选人做事 · 资源保障做事 · 技术高效做事 · 过程正确做事（四者别对调）
人员三岗位「管技操」；资源四件「知识库 · 服务台 · 备件库 · 运维工具」

模块 D ｜ 4.2.2 运维管理 · 智能运维

中国电子工业标准化技术协会发布的团体标准 T/CESA 1172《信息技术服务 智能运维 通用要求》给出了智能运维能力框架，包括组织治理、智能特征、智能运维场景实现、能力域和能力要素，其中能力要素是构建智能运维能力的基础。

• 组织在组织治理的指导下，对智能运维场景实现提出能力建设要求，开展智能运维能力的规划和建设
• 组织通过场景分析、场景构建、场景交付和效果评估四个过程，基于数据管理能力域提供的高质量数据，结合分析决策能力域做出合理判断或结论，并根据需要驱动自动控制能力域执行运维操作，使运维场景具备智能特征，实现质量可靠、安全可控、效率提升、成本降低
口诀：框架五部分「治理 · 特征 · 场景 · 能力域 · 要素」（能力要素是基础，这是真题原句）

智能运维的能力要素共 7 项：人员 · 技术 · 过程 · 数据 · 算法 · 资源 · 知识

要素要点
人员运维团队需熟悉 IT 运维业务活动与流程，掌握自动化、大数据、人工智能、云计算、算法等技术
技术统一标准和规范、开放的基础公共资源与服务、数据与流程及服务的互联互通
过程需清晰界定人机界面，考虑权限控制、风险规避
数据加强数据治理，保证数据质量、规范数据接口
算法聚焦异常检测、根因分析、故障预测、知识图谱、健康诊断、决策分析，具备有穷性、确切性、有效性
资源按场景要求配置算力、带宽、存储
知识运维技术方案与方法步骤、经验沉淀、运维对象多维度描述、运维数据智能挖掘结果
口诀：七要素「人技过数算资知」。⚠️ 别与「能力建设四要素」（人过技资）混——四要素 ⊆ 七要素，智能运维多了数据、算法、知识三项

智能运维能力平台通常具备数据管理、分析决策、自动控制等能力域：

• 数据管理能力：用于采集、处理、存储、展示各种运维数据
• 分析决策能力：以感知到的数据作为输入，做出实时的运维决策，驱动自动化工具实施操作
• 自动控制能力：根据运维决策，实施具体的运维操作
口诀：能力平台三域「数管控」——数据管理提供高质量数据、分析决策做判断/结论、自动控制执行运维操作
• 能力应用：以运维场景为中心，通过场景分析、能力构建、服务交付、迭代调优四个关键环节，可以使运维场景具备智能特征
• 运维场景按复杂程度划分：单一场景 · 复合场景 · 全局场景
⚠️ 两组四环节别混：「智能运维场景实现」的四过程 = 场景分析 · 场景构建 · 场景交付 · 效果评估（能力框架层面的描述）；「能力应用」的四关键环节 = 场景分析 · 能力构建 · 服务交付 · 迭代调优（落地实施层面的描述）
口诀：场景三类「单复全」

智能运维需具备若干智能特征，共 7 项：能感知 · 会描述 · 自学习 · 会诊断 · 可决策 · 自执行 · 自适应

特征含义
能感知灵敏、准确、自动地识别和反映人、活动和对象的状态
会描述直观友好地编排、展现和表达运维场景中的各类信息
自学习挖掘数据、完善模型、总结规律，主动沉淀知识
会诊断对人、活动和对象进行分析定位并判断原因
可决策通过信息搜集、加工和综合分析，给出后续依据或解决方案
自执行对运维场景自动进行分析、判断、决策和处理
自适应自动识别环境变化，动态调配应对措施并优化处理
口诀：七特征「感描学诊决执适」（能感知 / 会描述 / 自学习 / 会诊断 / 可决策 / 自执行 / 自适应）

模块 E ｜ 4.2.3 信息安全管理

在数字时代，信息价值日益凸显、组织对信息系统的依赖度不断提升，信息安全管理成为重中之重，其核心是保障信息的保密性、完整性、可用性。信息安全三要素（CIA 三要素）：

要素英文含义
保密性Confidentiality确保信息只被授权者读取（如客户密码仅本人可查）
完整性Integrity确保信息不被篡改、真实有效（如合同文件内容完整）
可用性Availability确保信息和系统在需要时能正常使用（如网站 24 小时可访问）
• CIA 三要素是信息安全设计的基础，但并非全部，还需结合合规性、可追溯性等其他要求，形成全面的安全策略
口诀：CIA =「保完可」（保密 · 完整 · 可用）；⚠️ 教材口径是「保密性」（不是「机密性」）

信息安全管理是全生命周期的系统工程，核心内容包括：

  1. 建立安全管理机构和团队，明确角色与职责
  2. 制定安全策略和规划
  3. 实施风险管理，识别并防范安全风险
  4. 制定业务持续性计划和灾难恢复计划
  5. 选择和部署安全措施（如防火墙、加密技术）
  6. 规范配置和变更管理，确保安全可控
  7. 开展安全审计和监控，提供安全维护支持
  8. 处理安全事件
  9. 开展安全意识培训，规范人员安全行为
记法：一条主线「组织 → 策略 → 风险 → 持续性 → 措施 → 配置变更 → 审计监控 → 事件 → 培训」

网络安全等级保护（等保 2.0） 是我国网络安全的核心制度，将「信息系统安全」扩展为「网络安全」，覆盖信息系统、通信网络设施、数据资源等。等级保护对象的安全保护等级分为五级（按受破坏后的危害程度递增）：

级别受破坏后的后果
第一级对相关公民、法人和其他组织的合法权益造成损害，但不危害国家安全、社会秩序和公共利益
第二级对合法权益严重损害，或对社会秩序和公共利益造成危害，但不危害国家安全
第三级对社会秩序和公共利益造成严重危害，或对国家安全造成危害
第四级对社会秩序和公共利益造成特别严重危害，或对国家安全造成严重危害
第五级对国家安全造成特别严重危害
记法：五级「公民 → 社会 → 国家」逐级递进；两级出现「严重」、两级出现「特别严重」，第五级只挂「国家安全特别严重」
备注：部分教辅按《计算机信息系统安全保护等级划分准则》另给级别名称（用户自主保护级 / 系统审计保护级 / 安全标记保护级 / 结构化保护级 / 访问验证保护级），教材第 4 版以「第一级~第五级 + 危害后果」表述为主

GB/T 22239《信息安全技术 网络安全等级保护基本要求》规定了不同级别的等级保护对象应具备的基本安全保护能力：

级别防护的威胁源恢复能力
第一级个人的、拥有很少资源的威胁源受损后恢复部分功能
第二级外部小型组织、拥有少量资源的威胁源能发现重要安全漏洞并处置安全事件；受损后一段时间内恢复部分功能
第三级统一安全策略下，外部有组织的团体、拥有较为丰富资源的威胁源能及时发现、监测攻击行为并处置；受损后较快恢复绝大部分功能
第四级统一安全策略下，国家级别的、敌对组织的拥有丰富资源的威胁源能及时发现、监测发现攻击行为和安全事件；受损后迅速恢复所有功能
第五级（教材从略）—
口诀：能力五级看两列 —「威胁源」（个人 / 小型组织 / 有组织团体 / 国家级）+「恢复程度」（部分 / 一段时间内部分 / 绝大部分 / 所有）

DCMM 稳健级 vs 量化管理级稳健级 = 组织层面标准化流程 +「实现组织绩效目标」的重要资产；量化管理级 =「获取竞争优势」的重要资源 + 量化分析监控
「保密性」还是「机密性」教材 4.2.3 用「保密性（Confidentiality）」
智能运维两组四环节场景实现 = 场景分析 · 场景构建 · 场景交付 · 效果评估；能力应用 = 场景分析 · 能力构建 · 服务交付 · 迭代调优
等保「两个五级」安全保护等级五级（按破坏后果：公民→社会→国家）；安全保护能力五级（GB/T 22239，按威胁源 + 恢复程度）——别混为一谈
「能力要素」是不是基础是——能力要素是构建智能运维能力的基础（真题原句）

参考答案（先自己答完再展开）
  1. 数据管理 · 运维管理 · 信息安全管理（口诀「数运安」）。管理重点的范围和细致程度随各组织的战略和业务目标的不同而存在差异
  2. 数据管理是指通过规划、控制与提供数据和信息资产的职能，包括开发、执行和监督有关数据的计划、策略、方案、项目、流程、方法和程序，以获取、控制、保护、交付和提高数据和信息资产价值。DAMA = 国际数据管理协会（指出数据资源管理致力于发展和处理组织数据全生命周期的适当的构建、策略、实践和程序）。数据管理框架是对组织的管理平台或者能够产生业务数据的平台产生的数据进行统一的跟踪、协调、管理的功能模型
  3. 国家标准 GB/T 36073《数据管理能力成熟度评估模型》。8 个核心能力域：数据战略 · 数据治理 · 数据架构 · 数据应用 · 数据安全 · 数据质量 · 数据标准 · 数据生存周期
  4. 初始级 · 受管理级 · 稳健级 · 量化管理级 · 优化级（「初受稳量优」）。从稳健级开始强调「数据管理的规范化」「数据已被当作实现组织绩效目标的重要资产」
  5. DCMM（5 等级 + 8 能力域）· DGI（3 维度 + 10 组件）· DCAM（4 组件：基础 / 执行 / 分析 / 应用）· DAMA（11 个职能领域 + 7 个基本环境要素）
  6. 治理要求 · 运行维护服务能力体系 · 价值实现。运行维护服务能力体系为价值实现赋能
  7. 四要素 = 人员 · 过程 · 技术 · 资源（「人过技资」）。配对：人员能力 = 选人做事 · 资源能力 = 保障做事 · 技术能力 = 高效做事 · 过程 = 正确做事
  8. 三种岗位 = 管理类 · 技术类 · 操作类（「管技操」）。资源能力四类 = 知识库 · 服务台 · 备件库 · 运行维护工具
  9. 框架五部分 = 组织治理 · 智能特征 · 智能运维场景实现 · 能力域 · 能力要素。其中能力要素是构建智能运维能力的基础
  10. 能力要素 7 项 = 人员 · 技术 · 过程 · 数据 · 算法 · 资源 · 知识（「人技过数算资知」）。算法聚焦异常检测、根因分析、故障预测、知识图谱、健康诊断、决策分析，具备有穷性、确切性、有效性三个特点
  11. 能力平台三域 = 数据管理 · 分析决策 · 自动控制。数据管理能力用于采集、处理、存储、展示各种运维数据；自动控制能力根据运维决策实施具体的运维操作
  12. 「智能运维场景实现」四过程 = 场景分析 · 场景构建 · 场景交付 · 效果评估；「能力应用」四关键环节 = 场景分析 · 能力构建 · 服务交付 · 迭代调优。运维场景按复杂程度分 单一场景 · 复合场景 · 全局场景（「单复全」）
  13. 7 个智能特征 = 能感知 · 会描述 · 自学习 · 会诊断 · 可决策 · 自执行 · 自适应（「感描学诊决执适」）。会描述 = 直观友好地编排、展现和表达运维场景中的各类信息；会诊断 = 对人、活动和对象进行分析定位并判断原因
  14. 核心是保障信息的保密性、完整性、可用性。CIA = 保密性 Confidentiality（确保信息只被授权者读取）· 完整性 Integrity（确保信息不被篡改、真实有效）· 可用性 Availability（确保信息和系统在需要时能正常使用）。三要素是信息安全设计的基础，但并非全部，还需结合合规性、可追溯性等其他要求
  15. 主要包括：建立安全管理机构和团队 · 制定安全策略和规划 · 实施风险管理 · 制定业务持续性计划和灾难恢复计划 · 选择和部署安全措施 · 规范配置和变更管理 · 开展安全审计和监控 · 处理安全事件 · 开展安全意识培训
  16. 把「信息系统安全」扩展为「网络安全」，覆盖信息系统、通信网络设施、数据资源等
  17. 分 5 级。第三级：对社会秩序和公共利益造成严重危害，或对国家安全造成危害；第四级：对社会秩序和公共利益造成特别严重危害，或对国家安全造成严重危害
  18. 第一级防护来自个人的、拥有很少资源的威胁源，受损后能恢复部分功能；第四级在统一安全策略下防护来自国家级别的、敌对组织的拥有丰富资源的威胁源，受损后能迅速恢复所有功能
  19. 「元数据管理」属数据架构；「指标数据」属数据标准
  20. 稳健级强调「组织层面制定系列的标准化管理流程」「数据是实现组织绩效目标的重要资产」；量化管理级强调「数据是获取竞争优势的重要资源」「效率能量化分析和监控」
