3.1.1 IT治理基础
1IT 治理的定义与关注问题
  • 定义：IT 治理是描述组织采用有效的机制对信息技术和数据资源开发利用，平衡信息化发展和数字化转型过程中的风险，确保实现组织的战略目标的过程
  • 组织治理角度：为鼓励组织所期望的组织行为而明确决策权归属和责任担当的框架，通过 IT 治理的决策权和责任影响组织所期望的组织行为
  • 定位：IT 资产是组织资产的重要组成部分 → IT 治理是组织治理结构中不可分割的一部分；在数字化转型中起统筹、评估、指导和监督作用
  • 关注的问题：投资中获得价值 / 技术战略与组织战略融合 / 数字化能力制度安排 / 降低 IT 风险 / 利用最佳实践加快信息化数字化
定义抓三词：机制 · 平衡风险 · 战略目标；框架抓两词：决策权归属 · 责任担当
2驱动因素：两问题 + 八因素
  • 统一规划两问题：①分散开发或引进形成「信息孤岛」，缺乏共享的网络化信息资源，系统集成难题无法解决；②信息资源整合目标空泛，数据中心建设与数据集中管理规划缺乏可操作性，尤其缺少数据标准化建设规划
  • 八因素关键词：确保 IT 投资有效性 · 知识高度密集（价值弹性大）· 融入管理运行生产交付 · 新技术带来新机会 · 推动理解 IT 价值 · 需要良好价值管理 · 高管管理幅度有限（明确责权利）· 成熟度较高组织的治理效果
两问题记「孤岛 + 空泛」；八因素首词串「投资 / 密集 / 融入 / 机会 / 理解 / 管理 / 幅度 / 成熟」
3IT 治理的内涵（5 个方面）
  • ①组织上层管理的有机组成部分，由组织治理层或高级管理层负责，从全局高度对信息化与数字化转型做出制度安排
  • ②强调数字目标与组织战略目标保持一致，为战略规划提供技术或控制支持
  • ③保护利益相关者权益，管理风险、合理利用 IT 资源、平衡成本收益，增强核心竞争力
  • ④是一种制度和机制，主要涉及管理和制衡：信息系统与业务战略匹配 · 建设投资 · 信息系统安全 · 绩效评价
  • ⑤组成部分包括管理层、组织结构、制度、流程、人员、技术等多方面
记法：高层安排 · 目标一致 · 权益风险 · 制度制衡 · 多元组成；四类制衡「匹配 / 投资 / 安全 / 绩效评价」爱出多选
4目标价值：关系句 + 三大目标
  • 关系句：组织治理驱动和调整 IT 治理；IT 治理为战略计划提供关键输入，是组织治理的一个重要功能
  • 体制四要素：以组织战略为导向、以实现 IT 与业务匹配为重心、以价值交付为成果、以绩效管理为控制手段
  • 三大目标：与业务目标一致（抽取需求 → 形成 IT 治理框架和系统整体模型 → 跟上持续变化的业务目标）· 有效利用信息与数据资源（管理职责 → 保证投资回收、支持决策）· 风险管理（制定保护级别 → 关键资源有效监控和事件处理）
口诀 一有风。「组织治理驱动 IT 治理」方向别写反；「风险管理的抓手 = 保护级别 + 监控 + 事件处理」
5管理层次（三层）与职责归属
  • 最高管理层（如董事会）：证实 IT 战略与业务战略是否一致；证实通过明确的期望和衡量手段交付 IT 价值；指导 IT 战略、平衡投资；指导信息和数据资源的分配
  • 执行管理层：制定 IT 目标；分析新技术机遇和风险；建设关键过程与核心竞争力；分配责任、定义规程、衡量业绩；管理风险和获得可靠保证
  • 业务与服务执行层：信息和数据服务的提供和支持；IT 基础设施的建设和维护；IT 需求的提出和响应
口诀：最高层「证证导导」→ 执行层「制分建衡」→ 业务层「提建响」。⚠️ 两个「证实」是最高管理层专属；「需求的提出和响应」在业务与服务执行层
3.1.2 IT治理体系
6体系构成五项（图 3-1 五问）
  • 核心：IT 治理的核心是关注 IT 定位和信息化建设与数字化转型的责权利划分
  • IT 定位：期望行为与业务目标一致 →「目标是什么」
  • IT 治理架构：业务和 IT 在治理委员会中的构成、组织 IT 与各分支机构的权责边界 →「由谁来做」
  • IT 治理内容：投资、风险、绩效、标准和规范等 →「做什么」
  • IT 治理流程：统筹、评估、指导、监督 →「怎么做」
  • IT 治理效果：内外评价 →「效果如何」
五项串记：定位 · 架构 · 内容 · 流程 · 效果（定位目标 / 架构定人 / 内容定事 / 流程定法 / 效果定评）
7五项关键决策与驱动链条
  • IT 原则：组织高层关于如何使用 IT 的陈述
  • IT 架构：从政策、关系以及技术选择中捕获的数据、应用和基础设施的逻辑（标准化和一体化）
  • IT 基础设施：集中协调、共享 IT 服务，为组织 IT 能力提供基础
  • 业务应用需求：为购买或内部开发 IT 应用确定业务需求
  • IT 投资和优先顺序：在哪些方面投资及投资多少（含项目审批和论证）
  • 链条：IT 原则驱动整体架构 → 架构决定基础设施 → 基础设施能力决定应用构建 → 投资和优先顺序被以上所有决策驱动；同时要确定每个决策由谁输入、由谁决策
链条口诀：原则 → 架构 → 基础设施 → 应用 → 投资。「如何使用 IT 的陈述」= 原则（不是架构）
8体系框架六部分（运行闭环）
  • 以组织的战略目标为导向，架起组织战略与 IT 的桥梁，形成一整套 IT 治理运行闭环
  • ① IT 战略目标：针对 IT 与业务关系、IT 决策、资源利用、风险控制制定，从 IT 投入中获最大收益
  • ② IT 治理组织：核心是治理机构（如 IT 治理委员会）的设置和权限划分，对 IT 治理效率起决定性作用
  • ③ IT 治理机制：决策、执行、风险控制、协调四种机制的综合体，相辅相成相互促进
  • ④ IT 治理域：对 IT 资源整合与配置；内容 = 计划、构建、运维与监控
  • ⑤ IT 治理标准：基本规范、实施参照、评价体系、审计方法（最佳实践与对标依据）
  • ⑥ IT 绩效目标：关注 IT 价值的实现，评价是否满足业务需求及工期、成本、质量是否达标
口诀 组机域标绩；治理域四词 计划 · 构建 · 运维 · 监控。「决定性作用」挂在治理组织上
9核心内容：本质关心两点 + 六方面
  • 本质上关心：①实现 IT 的业务价值——通过 IT 与业务战略匹配来实现；②IT 风险的规避——通过在组织内部建立相关职责来实现
  • 六方面：组织职责（划分所有者 / 建设者 / 管理者 / 监控者）· 战略匹配（贡献业务价值的重要驱动力）· 资源管理（优化投资与资源分配）· 价值交付（IT 项目全生命周期管理）· 风险管理（资产安全 / 灾难恢复 / 信息资源安全 / 人员隐私安全）· 绩效管理（追踪监视战略 / 项目 / 资源 / 服务 / 流程绩效）
口诀 职匹源价风绩；固定配对：价值交付 = 创造业务价值，风险管理 = 保护业务价值（高频对调陷阱）
10建立 IT 治理机制的三原则
  • 简单：机制应该明确地定义特定个人和团体所承担的责任和目标
  • 透明：有效的机制依赖于正式的程序；机制如何工作需要非常清晰
  • 适合：机制鼓励处于最佳位置的个人去制定特定的决策
口诀 简透适；干扰项常用「复杂 / 公开 / 灵活」冒充
3.1.3 任务 · 3.1.4 方法与标准
11治理活动定义与五大任务
  • 活动定义：组织的 IT 治理活动 = 统筹、指导、监督和改进
  • 全局统筹：统筹目标范围 / 技术环境 / 发展趋势 / 人员责权利；制订满足可持续发展的 IT 蓝图；横向业务集成 + 纵向业务管控
  • 价值导向：认可 IT / 信息系统 / 数据的价值；识别投资目录；关键指标设定监督；权衡实施成本与预期效益
  • 机制保障：保证需求与实现协调发展；IT 安全和风险有效识别、管理、防范和处置；评审管理体系的适宜性、充分性和有效性；审计完整性 / 有效性 / 合规性；监督改进实施
  • 创新发展：IT 创新开拓业务领域，改进质量、绩效和降低成本；技术发展 / 管理创新 / 模式革新协调联动
  • 文化助推：与利益相关者沟通治理的目标、策略和职责，营造积极向上、沟通包容的组织文化
口诀 统价机创文。⚠️ 活动定义「统筹·指导·监督·改进」≠ 治理流程「统筹·评估·指导·监督」——差别在「改进 / 评估」
12三大方法与标准：ITSS · COBIT · ISO/IEC 38500
ITSS（GB/T 34960 系列）
  • 34960.1 通用要求：规定 IT 治理的模型和框架、实施原则，以及开展 IT 顶层设计、管理体系和资源的治理要求；可用于①建立治理体系并自我评价 ②开展信息技术审计 ③研发选择评价软件方案 ④第三方评价
  • 三大治理域：顶层设计（战略 + 支撑战略的组织和架构）· 管理体系（质量 / 项目 / 投资 / 服务 / 业务连续性 / 信息安全 / 风险 / 供方 / 资产等）· 资源（基础设施 / 应用系统 / 数据）
  • 34960.2 实施指南：实施框架、实施环境、实施过程
COBIT（ISACA · 1969 年成立）
  • 面向整个组织的信息和技术治理及管理框架，含 40 项核心治理和管理目标
  • 治理 = EDM（评估、指导和监控）领域，由董事会和执行管理层负责；管理 = APO 调整规划和组织 / BAI 内部构建外部采购和实施 / DSS 交付服务和支持 / MEA 监控评价评估，由高级和中级管理层负责（计划、构建、运行和监控）
  • 治理系统七组件：流程 / 组织结构 / 原则政策和程序 / 信息 / 文化道德和行为 / 人员技能和胜任能力 / 服务基础设施和应用程序
  • 设计流程四步：了解组织环境和战略 → 确定初步范围 → 优化范围 → 最终确定设计
ISO/IEC 38500（IT 治理国际标准）
  • 2008 年 4 月发布；标志着信息化正式进入 IT 治理时代
  • 六原则：责任 · 战略 · 收购 · 性能 · 一致性 · 人的行为；三任务：评估、指导、监督
归属题三连：国标看 ITSS · 美国协会看 COBIT · 国际标准看 38500。治理域口诀 顶管资；EDM 是治理（董事会），APO/BAI/DSS/MEA 是管理（高中级管理层）
总结区 本节本质 + 考点地图
本节本质：3.1 回答「谁来管、怎么管组织的信息技术与投资」。主线四步：基础（是什么）→ 体系（管什么）→ 任务（干什么）→ 方法与标准（用什么工具）。全节没有计算，题型是「框架组成部分归属 + 标准归属 + 职责层次归属」三类，数字型考点密集（3 目标 / 8 因素 / 5 内涵 / 3 层次 / 5 决策 / 6 部分 / 6 方面 / 5 任务 / 3 治理域 / 7 组件 / 6 原则 / 3 任务）。
考点地图（按考频排序）：① IT 治理三大目标「一有风」 → ② COBIT 治理 vs 管理区分（EDM 董事会 vs APO/BAI/DSS/MEA 高中级管理层）→ ③ 五项关键决策及驱动链条（原则 → 架构 → 基础设施 → 应用 → 投资）→ ④ 体系框架六部分「组机域标绩」 → ⑤ 核心内容六方面「职匹源价风绩」（价值交付 = 创造、风险管理 = 保护）→ ⑥ ISO 38500 六原则三任务 → ⑦ ITSS 三大治理域「顶管资」 → ⑧ 五大任务「统价机创文」 → ⑨ 管理层次三层职责归属（两个「证实」在最高管理层）→ ⑩ 治理机制三原则「简透适」→ ⑪ 治理活动定义（改进）vs 治理流程（评估）→ ⑫ 内涵 5 方面 + 驱动因素（孤岛 + 空泛）。
⚠️ 口径陷阱：① 第 3 章是第 4 版新增章，2023 上及以前旧真题无对应题，别拿旧题正确率评估掌握度；② 治理活动 =「统筹·指导·监督·改进」，治理流程 / 作用 =「统筹·评估·指导·监督」，两套四词别混；③ 价值交付 = 创造业务价值、风险管理 = 保护业务价值，别对调；④「如何使用 IT 的陈述」= IT 原则（不是 IT 架构）；⑤ 治理域四词 = 计划、构建、运维、监控（不是「统筹评估指导监督」）；⑥ 「对 IT 治理效率起决定性作用」的是治理组织；⑦ EDM 是治理领域（董事会 + 执行管理层），别答成管理领域；⑧ ISO 38500 三任务是「评估、指导、监督」，与五大任务「统价机创文」是两回事；⑨ 34960.**1 = 通用要求**、34960.**2 = 实施指南**，编号别接反。
