## 一、必背清单

### 模块 A ｜ IT 治理基础（3.1.1）

- [ ] **A0 · IT 治理的定义** ⭕ 必背（定义题原句）
  **IT 治理**是描述组织采用**有效的机制**对**信息技术和数据资源**开发利用，**平衡信息化发展和数字化转型过程中的风险**，确保实现组织的**战略目标**的过程。
  - 另一个角度（组织治理视角）：IT 治理是指组织在开发利用信息技术过程中，为鼓励组织所期望的组织行为而**明确决策权归属和责任担当的框架**，其目标是通过 IT 治理的**决策权和责任**影响组织所期望的组织行为
  - 位置定位：IT 资产是组织资产的重要组成部分 → **IT 治理是组织治理结构中不可分割的一部分**
  - IT 治理关注的问题：从信息系统投资中**获得价值** / 信息技术战略与**组织战略相融合** / 从组织治理高度对数字化能力做出**制度安排** / 降低 IT 风险 / 利用最佳实践加快信息化数字化推进
  > 记法：定义抓三个词——**机制 · 平衡风险 · 战略目标**；框架抓两个词——**决策权归属 · 责任担当**
- [ ] **A1 · 驱动因素** ⭕ 常考（「统一规划两问题」+「高质量治理八因素」）
  - 制订 **IT 资源统一规划**存在的两个问题：①分散开发或引进的信息系统形成许多「**信息孤岛**」，缺乏共享的、网络化的信息资源，**系统集成难题一直无法解决**；②**信息资源整合目标空泛**，没有整合「信息孤岛」的措施，数据中心建设和数据集中管理等规划**缺乏可操作性**，尤其是**缺少数据标准化建设**方面的建设规划
  - **驱动组织开展高质量 IT 治理的因素（8 条）**：①确保组织 **IT 投资有效性**；②IT 属于**知识高度密集型**领域，价值发挥**弹性较大**；③IT 已**融入组织管理、运行、生产和交付**等各领域；④新兴信息技术带来**新的发展空间和业务机会**；⑤推动组织充分**理解 IT 价值**，促进价值挖掘和融合利用；⑥IT 价值不仅取决于好技术，也需要**良好的价值管理**、场景化的业务融合应用；⑦高级管理层**管理幅度有限**，需要明确**责权利**；⑧**成熟度较高的组织**以不同方式治理 IT，获得行业领先效果
  > 记法：两问题 =「**孤岛 + 空泛**」；八因素记首词「**投资 / 密集 / 融入 / 机会 / 理解 / 管理 / 幅度 / 成熟**」
- [ ] **A2 · IT 治理的内涵（5 个方面）** ⭕ 必考
  1. IT 治理是组织**上层管理**的一个有机组成部分，由**组织治理层或高级管理层**负责，从组织**全局高度**对信息化与数字化转型做出**制度安排**
  2. 强调**数字目标与组织战略目标保持一致**，为组织战略规划提供技术或控制支持
  3. **保护利益相关者的权益**，对风险进行有效管理，合理利用 IT 资源，平衡成本和收益，**增强组织的核心竞争力**
  4. 是一种**制度和机制**，主要涉及**管理和制衡**：信息系统与业务战略**匹配**、信息系统建设**投资**、信息系统**安全**、信息系统**绩效评价**等内容
  5. 组成部分包括**管理层、组织结构、制度、流程、人员、技术**等多个方面，共同构建完善的 IT 治理架构
  > 记法：**高层安排 · 目标一致 · 权益风险 · 制度制衡 · 多元组成**
- [ ] **A3 · IT 治理的目标价值（三大目标）** ⭕ 必背（年年考）
  - 关系句：**组织治理驱动和调整 IT 治理**；IT 治理为战略计划提供关键输入，是组织治理的**一个重要功能**
  - IT 治理帮助组织建立：以**组织战略为导向**、以实现 **IT 与业务匹配为重心**、以**价值交付为成果**、以**绩效管理为控制手段**的 IT 管理体制
  - **三大主要目标**：
    | 目标 | 要点 |
    |---|---|
    | **与业务目标一致** | 从组织目标和数字战略中**抽取信息与数据需求和功能需求**，形成**总体的 IT 治理框架和系统整体模型**，保证信息技术开发利用**跟上持续变化的业务目标** |
    | **有效利用信息与数据资源** | 针对「工程超期 / 需求未满足 / 平台不支持业务 / 数据效能不高 / 融合深度不够」等问题，对信息与数据资源的**管理职责**进行有效管理，**保证投资回收，支持决策** |
    | **风险管理** | 组织越依赖信息网络、信息系统和数据资源，新风险越多；通过制定信息与数据资源的**保护级别**，强调对关键信息与数据资源实施**有效监控和事件处理** |
  > 口诀：**一有风**（与业务目标一致 · 有效利用资源 · 风险管理）
- [ ] **A4 · IT 治理的管理层次（三层）** ⭕ 必背（职责归属题）
  | 层次 | 主要职责 |
  |---|---|
  | **最高管理层**（如董事会） | **证实** IT 战略与业务战略是否一致；**证实**通过明确的期望和衡量手段交付 IT 价值；**指导** IT 战略、平衡支持组织当前和未来发展的投资；**指导**信息和数据资源的分配 |
  | **执行管理层** | **制定** IT 的目标；**分析**新技术的机遇和风险；**建设**关键过程与核心竞争力；**分配**责任、定义规程、衡量业绩；**管理**风险和获得可靠保证 |
  | **业务与服务执行层** | 信息和数据服务的**提供和支持**；IT 基础设施的**建设和维护**；IT 需求的**提出和响应** |
  > 口诀：最高层「**证证导导**」→ 执行层「**制分建衡**」→ 业务层「**提建响**」
  > ⚠️「证实」两连是**最高管理层**专属动词；「需求的提出和响应」在**业务与服务执行层**

### 模块 B ｜ IT 治理体系（3.1.2 · 本节最重的一小节）

- [ ] **B0 · IT 治理体系的构成（5 项）** ⭕ 必背
  IT 治理的**核心**是关注 **IT 定位**和信息化建设与数字化转型的**责权利划分**。体系构成五项（对应图 3-1 的五个问题）：
  | 构成 | 内容 | 对应问题 |
  |---|---|---|
  | **IT 定位** | IT 应用的期望行为与业务目标一致 | 目标是什么？ |
  | **IT 治理架构** | 业务和 IT 在治理委员会中的构成、组织 IT 与各分支机构的 IT 权责边界等 | 由谁来做？ |
  | **IT 治理内容** | **投资、风险、绩效、标准和规范**等 | 做什么？ |
  | **IT 治理流程** | **统筹、评估、指导、监督** | 怎么做？ |
  | **IT 治理效果** | 内外评价 | 效果如何？ |
  > 记法：**定位 · 架构 · 内容 · 流程 · 效果**（定位目标 / 架构定人 / 内容定事 / 流程定法 / 效果定评）
- [ ] **B1 · 五项关键决策** ⭕ 必背（教材图 3-2 + 表 3-1）
  | 决策 | 核心内容 |
  |---|---|
  | **IT 原则** | **组织高层关于如何使用 IT 的陈述** |
  | **IT 架构** | 组织从一系列**政策、关系以及技术选择**中捕获的**数据、应用和基础设施的逻辑**，以达到预期的商业、技术的**标准化和一体化** |
  | **IT 基础设施** | **集中协调、共享 IT 服务**，可以为组织的 IT 能力提供基础 |
  | **业务应用需求** | 为**购买或内部开发 IT 应用**确定业务需求 |
  | **IT 投资和优先顺序** | 关于应该在 IT 的**哪些方面投资以及投资多少**的决策，包括项目的**审批和论证** |
  - **驱动链条**：**IT 原则**驱动 IT 整体架构的形成 → IT 整体架构决定基础设施 → 基础设施确定的能力决定基于业务需求应用的构建 → **IT 投资和优先顺序**必须为 IT 原则、整体架构、基础设施和应用需求所驱动
  - 关键问题：IT 治理需要确定每个决策**由谁来负责输入**、**由谁来负责做出决策**
  > 链条口诀：**原则 → 架构 → 基础设施 → 应用 → 投资**（投资被前面所有决策驱动）
- [ ] **B2 · IT 治理体系框架（六部分）** ⭕ 必背（「组机域标绩」）
  IT 治理体系框架以组织的**战略目标为导向**，架起组织战略与 IT 的桥梁，实现 IT 风险的全面管理以及 IT 资源的合理利用。六部分形成一整套 **IT 治理运行闭环**：
  | # | 组成 | 要点 |
  |---|---|---|
  | 1 | **IT 战略目标** | 为实现 IT 价值和目标，使组织从 IT 投入中获得**最大收益**，针对 **IT 与业务关系、IT 决策、IT 资源利用、IT 风险控制**等方面制定的目标 |
  | 2 | **IT 治理组织** | 界定各相关主体的治理范围、**责权利**及相互关系的准则；核心是**治理机构（如 IT 治理委员会）的设置和权限划分**；其强弱**对 IT 治理效率起决定性作用** |
  | 3 | **IT 治理机制** | **决策机制、执行机制、风险控制机制、协调机制**的综合体，各机制相辅相成、相互促进 |
  | 4 | **IT 治理域** | 在治理规则之下对 IT 资源进行**整合与配置**、根据 IT 目标采取行动；内容包括 IT 信息系统的**计划、构建、运维与监控**（信息化「高效做事情」、数字化「敏捷的决策」） |
  | 5 | **IT 治理标准** | 包括**基本规范、实施参照、评价体系和审计方法**，作为组织实施 IT 治理最佳实践和**对标依据** |
  | 6 | **IT 绩效目标** | 关注 **IT 价值的实现**，评价 IT 规划与构建过程中是否满足业务需求以及**工期、成本、质量**是否达到目标 |
  > 口诀：**战略目标 · 治理组织 · 治理机制 · 治理域 · 治理标准 · 绩效目标**（组机域标绩）；治理域四词 = **计划 · 构建 · 运维 · 监控**
- [ ] **B3 · IT 治理的核心内容（六方面）** ⭕ 必背（高频）
  - IT 治理**本质上关心**：①实现 IT 的**业务价值**——通过 **IT 与业务战略匹配**来实现；②IT **风险的规避**——通过在组织内部**建立相关职责**来实现；两者都需要相关资源支持并对其绩效进行有效度量
  - **核心内容六方面**：
    | 内容 | 含义 | 价值定位 |
    |---|---|---|
    | **组织职责** | 明确信息部门和业务部门的关系和责任，划分信息系统的**所有者、建设者、管理者和监控者** | — |
    | **战略匹配** | 使 IT 建设与组织战略相匹配，是 IT **贡献业务价值的重要驱动力** | — |
    | **资源管理** | 确保用户对**应用系统和基础设施**有良好理解和应用，优化 IT 投资与资源（人、应用系统、信息、基础设施）分配，做好人员培训与发展 | — |
    | **价值交付** | 通过对 IT 项目**全生命周期**的管理，确保 IT 按照组织战略实现预期的业务价值；重点是**交付周期成本控制**与 IT 业务价值实现 | **创造业务价值** |
    | **风险管理** | 确保 **IT 资产安全、灾难恢复、组织信息资源安全和人员隐私安全** | **保护业务价值** |
    | **绩效管理** | **追踪和监视** IT 战略、项目实施、资源使用、服务提供和业务流程绩效 | — |
  > 口诀：**职匹源价风绩**；一对必背配对：**价值交付 = 创造业务价值，风险管理 = 保护业务价值**
- [ ] **B4 · 建立 IT 治理机制的三原则** ⭕ 常考
  | 原则 | 含义 |
  |---|---|
  | **简单** | 机制应该**明确地定义**特定个人和团体所承担的**责任和目标** |
  | **透明** | 有效的机制依赖于**正式的程序**；机制如何工作需要非常清晰 |
  | **适合** | 机制鼓励**处于最佳位置的个人**去制定特定的决策 |
  > 口诀：**简透适**（干扰项常用「复杂 / 公开 / 灵活」）

### 模块 C ｜ IT 治理任务（3.1.3）

- [ ] **C0 · IT 治理活动的定义** ⭕ 必背（易与「治理流程」混）
  组织的 IT 治理活动定义为：**统筹、指导、监督和改进**。
  > ⚠️ 两组四词别混：**治理流程 / 治理作用** =「统筹 · **评估** · 指导 · 监督」；**治理活动** =「统筹 · 指导 · 监督 · **改进**」——前者有「评估」、后者有「改进」
- [ ] **C1 · 五大任务** ⭕ 必背（「统价机创文」）
  | 任务 | 要点 |
  |---|---|
  | **全局统筹** | 统筹 IT 治理的**目标范围、技术环境、发展趋势和人员责权利**；制订满足可持续发展的 **IT 蓝图**；实施科学决策、集约管理，实现横向业务集成和纵向业务管控；建立持续改进和创新机制 |
  | **价值导向** | 认可信息技术、信息系统和数据在组织中的价值；**识别投资目录**并以相应方式评估管理；对**关键指标**设定和监督，对变化和偏差及时回应；**权衡实施成本与预期效益** |
  | **机制保障** | 保证 IT 需求与实现的**协调发展**，使 IT 安全和风险得到有效**识别、管理、防范和处置**；指导建立规范的过程管理和痕迹管理；**评审** IT 管理体系的**适宜性、充分性和有效性**；**审计** IT 完整性、有效性和合规性；**监督**改进内容的实施 |
  | **创新发展** | 利用 IT 创新开拓业务领域，提升管理水平，**改进质量、绩效和降低成本**；确保技术发展、管理创新、模式革新**协调联动**；对组织创新能力进行评估 |
  | **文化助推** | 与利益相关者**沟通 IT 治理的目标、策略和职责**，营造**积极向上、沟通包容**的组织文化 |
  > 口诀：**统价机创文**

### 模块 D ｜ IT 治理方法与标准（3.1.4）

- [ ] **D0 · 三大典型标准 / 框架总览** ⭕ 必背（归属题）
  | 名称 | 归属 / 制定者 |
  |---|---|
  | **ITSS 中 IT 治理系列标准** | 我国信息技术服务标准库（GB/T 34960 系列） |
  | **COBIT** | 信息和技术治理框架，由**美国信息系统审计与控制协会（ISACA）**设计并编制（ISACA 成立于 **1969 年**） |
  | **ISO/IEC 38500** | **IT 治理国际标准**（2008 年 4 月正式发布） |
  > 记法：**国标看 ITSS · 美国协会看 COBIT · 国际标准看 38500**
- [ ] **D1 · ITSS：GB/T 34960.1 / 34960.2** ⭕ 必背（「顶管资」）
  - **GB/T 34960.1《信息技术服务 治理 第 1 部分：通用要求》**：规定了 IT 治理的**模型和框架**、实施 IT 治理的**原则**，以及开展 IT **顶层设计、管理体系和资源**的治理要求。**该标准可用于**：①建立组织的 IT 治理体系并实施**自我评价**；②开展**信息技术审计**；③**研发、选择和评价** IT 治理相关的软件或解决方案；④**第三方**对组织的 IT 治理能力进行评价
  - **IT 治理框架三大治理域**：
    | 治理域 | 内容 |
    |---|---|
    | **顶层设计** | 信息技术**战略**，以及支撑战略的**组织和架构** |
    | **管理体系** | **质量管理、项目管理、投资管理、服务管理、业务连续性管理、信息安全管理、风险管理、供方管理、资产管理**和其他管理 |
    | **资源** | 信息技术相关的**基础设施、应用系统和数据** |
  - **GB/T 34960.2《信息技术服务 治理 第 2 部分：实施指南》**：分析了实施 IT 治理的**环境因素**，规定了 IT 治理的**实施框架、实施环境和实施过程**，并明确顶层设计治理、管理体系治理和资源治理的实施要求
  > 口诀：三大治理域 = **顶管资**；34960.**1 = 通用要求**、34960.**2 = 实施指南**
- [ ] **D2 · COBIT 框架** ⭕ 必背（治理 vs 管理区分是高频）
  - **COBIT（Control Objectives for Information and related Technology）**是面向**整个组织**的信息和技术治理及管理框架；框架介绍了 **40 项核心治理和管理目标**
  - **治理与管理的区分**：
    | 类别 | 领域 | 负责者 | 动词 |
    |---|---|---|---|
    | **治理** | **EDM**（评估、指导和监控） | **董事会和执行管理层** | **评估利益干系人的需求 → 设定方向（定优先级、指定决策）→ 监控绩效与合规** |
    | **管理** | **APO**（调整、规划和组织）· **BAI**（内部构建、外部采购和实施）· **DSS**（交付、服务和支持）· **MEA**（监控、评价和评估） | **高级和中级管理层** | 按治理设定的方向**计划、构建、运行和监控**活动 |
  - **COBIT 治理系统七大组件**：**流程 · 组织结构 · 原则政策和程序 · 信息 · 文化道德和行为 · 人员技能和胜任能力 · 服务基础设施和应用程序**
  - **治理系统设计流程四步**：①**了解组织环境和战略** → ②**确定治理系统的初步范围** → ③**优化治理系统的范围** → ④**最终确定治理系统的设计**
  > 口诀：治理 = **E**DM（董事会）；管理 = **A**PO/**B**AI/**D**SS/**M**EA（高级中级管理层）；设计四步 = **了解 → 定范围 → 优化 → 定设计**
- [ ] **D3 · ISO/IEC 38500** ⭕ 必背（六原则 + 三任务）
  - **2008 年 4 月**正式发布的 **IT 治理国际标准**；它的出台不仅标志着 IT 治理从概念模糊的探讨阶段进入正确认识的发展阶段，而且**标志着信息化正式进入 IT 治理时代**
  - **六项原则**：**责任 · 战略 · 收购 · 性能 · 一致性 · 人的行为**
  - **三大任务**：治理机构应通过**评估、指导和监督**三个主要任务来治理 IT（评估 = 审查判断当前和未来的 IT 使用；指导 = 负责战略和政策的编制和执行；监督 = 通过测量系统监测 IT 表现）
  > 口诀：六原则「**责战收性一人**」；三任务「**评指监**」

<summary>参考答案（先自己答完再展开）</summary>

1. IT 治理是描述组织采用**有效的机制**对**信息技术和数据资源**开发利用，**平衡信息化发展和数字化转型过程中的风险**，确保实现组织的**战略目标**的过程。组织治理角度：为鼓励组织所期望的组织行为而**明确决策权归属和责任担当的框架**
2. ①分散开发或引进的信息系统形成许多「**信息孤岛**」，缺乏共享的、网络化的信息资源，**系统集成难题一直无法解决**；②**信息资源整合目标空泛**，没有整合「信息孤岛」的措施，数据中心建设和数据集中管理规划缺乏可操作性，尤其缺少**数据标准化建设**规划
3. **8 条**。关键词：确保 IT 投资有效性 / 知识高度密集型（价值弹性大）/ 已融入管理运行生产交付 / 新技术带来新空间新机会 / 推动理解 IT 价值 / 需要良好价值管理 / 高级管理层管理幅度有限 / 成熟度较高组织以不同方式治理
4. ①上层管理的有机组成部分，由**治理层或高级管理层**负责，做**制度安排**；②强调**数字目标与组织战略目标保持一致**；③**保护利益相关者权益**、管理风险、平衡成本收益、增强核心竞争力；④是一种**制度和机制**；⑤组成部分包括**管理层、组织结构、制度、流程、人员、技术**。「制度机制」涉及四类制衡：信息系统与业务战略**匹配**、建设**投资**、信息**安全**、**绩效评价**
5. **组织治理驱动和调整 IT 治理**；IT 治理为战略计划提供关键输入，是组织治理的一个重要功能。体制四要素：以**组织战略为导向**、以**实现 IT 与业务匹配为重心**、以**价值交付为成果**、以**绩效管理为控制手段**
6. **与业务目标一致、有效利用信息与数据资源、风险管理**。口诀「**一有风**」
7. 「与业务目标一致」：从组织目标和数字战略中**抽取信息与数据需求和功能需求**，形成**总体的 IT 治理框架和系统整体模型**，保证开发利用跟上持续变化的业务目标。「风险管理」：制定信息与数据资源的**保护级别**，强调对关键的资源实施**有效监控和事件处理**
8. **最高管理层 / 执行管理层 / 业务与服务执行层**。最高管理层动词「证实 · 指导」：**证实 IT 战略与业务战略是否一致**、**证实通过明确的期望和衡量手段交付 IT 价值**，指导 IT 战略与投资平衡、指导信息与数据资源分配；执行层：制定目标 / 分析机遇风险 / 建设关键过程与核心竞争力 / 分配责任定义规程衡量业绩 / 管理风险；业务与服务执行层：服务提供和支持 / 基础设施建设和维护 / **需求的提出和响应**
9. **IT 定位 / IT 治理架构 / IT 治理内容 / IT 治理流程 / IT 治理效果**。对应五问：目标是什么（定位 = 期望行为与业务目标一致）/ 谁来做（架构 = 治理委员会构成与权责边界）/ 做什么（内容 = 投资、风险、绩效、标准和规范）/ 怎么做（流程 = 统筹、评估、指导、监督）/ 效果如何（效果 = 内外评价）
10. **IT 原则 · IT 架构 · IT 基础设施 · 业务应用需求 · IT 投资和优先顺序**。链条：**IT 原则驱动 IT 整体架构 → 架构决定基础设施 → 基础设施能力决定应用构建 → IT 投资和优先顺序被前面所有决策驱动**
11. 「组织高层关于如何使用 IT 的陈述」= **IT 原则**；「集中协调、共享 IT 服务」= **IT 基础设施**（「数据、应用和基础设施的逻辑，标准化一体化」= IT 架构；「为购买或内部开发 IT 应用确定业务需求」= 业务应用需求；「投资多少、审批论证」= IT 投资和优先顺序）
12. **IT 战略目标 / IT 治理组织 / IT 治理机制 / IT 治理域 / IT 治理标准 / IT 绩效目标**（口诀「组机域标绩」），形成一整套 IT 治理**运行闭环**。治理域内容 = **计划、构建、运维与监控**
13. **决策机制、执行机制、风险控制机制、协调机制**的综合体。治理机构设置与权限划分属 **IT 治理组织**；其强弱直接影响治理的效率和效能，**对 IT 治理效率起决定性作用**
14. ①实现 IT 的**业务价值**——通过 **IT 与业务战略匹配**实现；②IT **风险的规避**——通过在组织内部**建立相关职责**实现
15. **组织职责 · 战略匹配 · 资源管理 · 价值交付 · 风险管理 · 绩效管理**（职匹源价风绩）。**价值交付 = 创造业务价值；风险管理 = 保护业务价值**
16. **简单**（明确定义责任和目标）· **透明**（依赖正式的程序，机制如何工作需非常清晰）· **适合**（鼓励处于最佳位置的个人制定特定决策）。口诀「简透适」
17. 治理活动 = **统筹、指导、监督和改进**；治理流程 / 作用 = **统筹、评估、指导、监督**。差别：「评估」vs「改进」
18. **全局统筹 · 价值导向 · 机制保障 · 创新发展 · 文化助推**（统价机创文）。全局统筹制订满足可持续发展的 **IT 蓝图**；机制保障评审 IT 管理体系的**适宜性、充分性和有效性**
19. ①**ITSS 中 IT 治理系列标准**（我国标准库，GB/T 34960 系列）；②**COBIT**（美国信息系统审计与控制协会 ISACA，1969 年成立）；③**ISO/IEC 38500**（IT 治理国际标准）
20. 34960.1 规定了 IT 治理的**模型和框架**、实施原则，以及开展 **IT 顶层设计、管理体系和资源**的治理要求。三大治理域：**顶层设计**（战略 + 支撑战略的组织和架构）/ **管理体系**（质量、项目、投资、服务、业务连续性、信息安全、风险、供方、资产等）/ **资源**（基础设施、应用系统、数据）
21. **美国信息系统审计与控制协会（ISACA）**设计编制（1969 年成立）。治理 = **EDM 评估、指导和监控**领域，由**董事会和执行管理层**负责；管理 = **APO 调整规划组织 / BAI 内部构建外部采购和实施 / DSS 交付服务和支持 / MEA 监控评价评估**四个领域，由**高级和中级管理层**负责。七大组件：流程 / 组织结构 / 原则政策和程序 / 信息 / 文化道德和行为 / 人员技能和胜任能力 / 服务基础设施和应用程序。设计四步：了解组织环境和战略 → 确定初步范围 → 优化范围 → 最终确定设计
22. **2008 年 4 月**正式发布；标志着 IT 治理从概念模糊的探讨阶段进入正确认识的发展阶段，**标志着信息化正式进入 IT 治理时代**。六原则：**责任、战略、收购、性能、一致性、人的行为**（责战收性一人）；三任务：**评估、指导、监督**（评指监）

- **本节内部主线**：**基础（是什么）→ 体系（管什么）→ 任务（干什么）→ 方法与标准（用什么工具）**
- **向后打通**：
  - **3.2 IT 审计**：IT 审计是 IT 治理不可或缺的**评估和监督工具**；本节治理流程里的「评估、监督」由 3.2 的审计落地；GB/T 34960.1 的用途之一就是「开展信息技术审计」
  - **第 4 章信息系统管理**：治理定方向、管理做执行——4.1.2「规划和组织」与 IT 治理的组织安排直接衔接
  - **第 6 章项目管理概论 / 第 18 章绩效域**：本节「绩效目标关注工期、成本、质量」，是项目管理三约束在治理层的投影；「价值交付」与绩效域的交付绩效域思想同源
  - **第 22 章组织通用治理**：组织治理 ↔ IT 治理是上下位概念，本节「组织治理驱动和调整 IT 治理」的关系句会再见面
- **论文素材（实战映射）**：
