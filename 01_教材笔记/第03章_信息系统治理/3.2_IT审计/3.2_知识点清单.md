## 一、必背清单

### 模块 A ｜ IT 审计基础（3.2.1）

- [ ] **A0 · IT 审计的定义** ⭕ 必背（定义题原句）
  **IT 审计**（GB/T 34690.4《信息技术服务 治理 第 4 部分：审计导则》）是指根据 **IT 审计标准**的要求，对**信息系统及相关的 IT 内部控制和流程**进行**检查、评价**，并**发表审计意见**。
  - 引入句：为了有效控制 IT 风险，有必要对组织的**信息系统治理及 IT 内控与管理**等开展 IT 审计，充分发挥 IT 审计**监督**的作用
  - 定位：IT 审计是 IT 治理的**评估和监督工具**（3.1 治理流程里的「评估、监督」由审计落地）
  > 记法：定义抓四个词——**标准 · 检查评价 · 内部控制流程 · 发表意见**；出处记 **GB/T 34690.4 = 审计导则**（勿与 3.1 的 GB/T 34960 系列混：**4960 = 治理**，**4690 = 审计**）
- [ ] **A1 · IT 审计的重要性与目的** ⭕ 必背
  - **IT 审计重要性**：指 IT 审计风险（固有风险、控制风险、检查风险）对组织影响的**严重程度**，如：**财务损失、业务中断、失去客户信任、经济制裁**等
  - **IT 审计的目的**：通过开展 IT 审计工作，了解组织 IT 系统与 IT 活动的**总体状况**，对组织是否实现 **IT 目标**进行**审查和评价**，充分**识别与评估**相关 IT 风险，提出**评价意见及改进建议**，**促进组织实现 IT 目标**
  > ⚠️ 判断题眼：目的句的落点是「促进实现 IT 目标」——「保护信息资产安全」是 **IT 目标**之一，不是审计目的本身（真题考过「不属于审计目的」选「保护信息资产的安全」）
- [ ] **A2 · 组织的 IT 目标（四条）** ⭕ 必背（年年考）
  | # | IT 目标 |
  |---|---|
  | 1 | 组织的 **IT 战略应与业务战略保持一致** |
  | 2 | **保护信息资产**的安全及数据的**完整、可靠、有效** |
  | 3 | 提高信息系统的**安全性、可靠性及有效性** |
  | 4 | 合理保证信息系统及其运用**符合有关法律、法规及标准**等的要求 |
  > 口诀：**一致 · 安全 · 三性 · 合规**（数据三性「完整可靠有效」≠ 系统三性「安全可靠有效」，别对调）
- [ ] **A3 · IT 审计范围（四范围）** ⭕ 必背（配对题）
  | 范围 | 依据 / 内容 |
  |---|---|
  | **总体范围** | 根据**审计目的和投入的审计成本**来确定 |
  | **组织范围** | 审计涉及的**组织机构、主要流程、活动及人员**等 |
  | **物理范围** | 具体的**物理地点与边界** |
  | **逻辑范围** | 涉及的**信息系统和逻辑边界** |
  - 实施审计项目前，审计人员应先对组织与信息系统相关的总体情况进行**了解和风险评估**，确定主要 IT 风险，结合审计项目**预计的时间、配备的审计力量**等确定**重点审计范围**
  > 口诀：**总组物逻**；「目的 + 成本」只配**总体范围**，其余按各自内容配对
- [ ] **A4 · 对 IT 审计人员的要求** ⭕ 常考
  根据 **GB/T 34690.4**，对 IT 审计人员的要求包括：**职业道德**、**知识**、**技能**、**资格与经验**、**专业胜任能力**、**利用外部专家服务**等方面
  > 记法：六个词「**德 · 知 · 技 · 资 · 胜 · 外**」；出处仍是 34690.4（审计导则管审计人员）
- [ ] **A5 · IT 审计风险（四类）** ⭕ 必背（定义配对最高频）
  | 风险 | 定义 | 关键特点 |
  |---|---|---|
  | **固有风险** | **IT 活动不存在相关控制**的情况下，**易于导致重大错误**的风险 | IT 活动**本身所具有**；审计人员**只能评估，无法控制或影响**；衡量是**主观的、复杂的** |
  | **控制风险** | 与 IT 活动相关的**内部控制体系不能及时预防或检查出**存在的重大错误的风险 | 与**内部控制制度执行的有效性**有关，**与审计无关**；审计人员只能评估其风险水平 |
  | **检查风险** | 通过**预定的审计程序未能发现**重大、单个或与其他错误相结合的风险 | 影响因素：**IT 审计规范不完善、审计人员自身或技术原因**等 |
  | **总体审计风险** | 针对**单个控制目标**所产生的各类审计风险的**总和** | = 固有 + 控制 + 检查三者的综合体现 |
  > 口诀：**固有 = 没控制就出错（活动自带）· 控制 = 内控没拦住 · 检查 = 审计没查出 · 总体 = 单目标总和**
  > ⚠️ 题眼：「内部控制体系」字样 → **控制风险**；「不存在相关控制 / 活动本身」→ **固有风险**；「预定审计程序未发现」→ **检查风险**

### 模块 B ｜ 审计方法与技术（3.2.2）

- [ ] **B0 · IT 审计依据与准则** ⭕ 必背（归属题）
  IT 审计活动的开展需要结合相关**法律法规、准则与标准**。国际上发布的常用审计准则有四项：
  | 准则 | 说明 |
  |---|---|
  | **信息系统审计准则** | **ISACA（国际信息系统审计协会）**发布 |
  | **《内部控制——整体框架》报告** | 通称 **COSO** 报告（美国虚假财务报告委员会下属的发起人委员会） |
  | **《萨班斯法案》（SOX）** | 美国政府出台的涉及**会计职业监管、组织治理、证券市场监管**等方面改革的重要法律 |
  | **COBIT（信息及相关技术控制目标）** | 目前**国际上通用的**信息及相关技术控制规范 |
  > 记法：**ISACA 出准则 · COSO 出内控 · SOX 是美国法 · COBIT 是控制目标**（COBIT 在 3.1.4 是「治理框架」、在本节是「审计准则」——一个框架两处出场，不冲突）
- [ ] **B1 · IT 审计常用方法（六法）** ⭕ 必背
  **访谈法、调查法、检查法、观察法、测试法、程序代码检查法**
  > 口诀：**访调检观试码**；干扰项常用「穿行法 / 抽样法 / 复核法」——抽样是「审计**技术**」不是「常用方法」
- [ ] **B2 · IT 审计技术（四类）** ⭕ 必背（分类归属题）
  | 技术 | 内容 |
  |---|---|
  | **风险评估技术** | ①**风险识别**：德尔菲法、头脑风暴、检查表法、SWOT 技术及图解技术；②**风险分析**：定性分析 + 定量分析；③**风险评价**：单因素风险评价 + 总体风险评价；④**风险应对**：云计算、冗余链路、冗余资源、系统弹性伸缩、两地三中心灾备、业务熔断限流等 |
  | **审计抽样技术** | ①**属性抽样**（固定样本抽样 / 频率估计抽样）：估计总体中某种**属性的发生率**，回答「**有多少**」；②**变量抽样**（金额估计抽样 / 平均值估计抽样）：由样本估计总体的**货币金额或其他度量单位** |
  | **计算机辅助审计技术** | 利用计算机软件工具辅助完成审计工作（提取、分析、比对数据等） |
  | **大数据审计技术** | **大数据智能分析技术、大数据可视化分析技术、大数据多数据源综合分析技术** |
  > 记法：技术四类「**评抽辅数**」；属性抽样答「有多少」、变量抽样答「值多少」；大数据三技术「**智能 · 可视 · 多源**」
- [ ] **B3 · IT 审计证据（定义 + 五特性）** ⭕ 必背
  - **定义**：由审计机构和审计人员获取，用于确定所审计实体或数据是否遵循**既定标准或目标**，形成**审计结论的证明材料**；审计证据是**审计意见的支柱**，是审计人员形成**审计结论的基础**
  - **特性（五条）**：**充分性、客观性、相关性、可靠性、合法性**
  > 口诀：**充 · 客 · 相 · 可 · 合**
- [ ] **B4 · IT 审计底稿** ⭕ 必背（分类 + 三级复核高频）
  - **定义**：审计人员对**制订的审计计划、实施的审计程序、获取的相关审计证据、得出的审计结论**做出的记录
  - **分类（三类）**：**综合类工作底稿、业务类工作底稿、备查类工作底稿**
  - **编制要求**：①内容——**资料翔实、重点突出、繁简得当、结论明确**；②形式——**要素齐全、格式规范、标识一致、记录清晰**
  - **作用（四条）**：形成审计结论、发表审计意见的**直接依据**；评价考核审计人员的**主要依据**；审计**质量控制与监督的基础**；对未来审计业务具有**参考备查**作用
  - **三级复核制度**：**审计机构负责人、部门负责人、项目负责人（或项目经理）**为复核人
  - **保密例外（两种情况查阅不属于泄密）**：①**法院、检察院及国家其他部门依法查阅**并按规定办理了必要手续；②**审计协会或其委派单位**对审计机构执业情况进行检查
  - **归档后**由**档案管理部门**管理，确保安全、完整
  > 口诀：分类「**综业备**」；内容四条「**翔实 · 突出 · 得当 · 明确**」对形式四条「**齐全 · 规范 · 一致 · 清晰**」；三级复核「**机构 → 部门 → 项目**」由大到小

### 模块 C ｜ 审计流程（3.2.3 · 流程阶段归属题主力）

- [ ] **C0 · 审计流程的含义与作用** ⭕ 必背
  - **作用（四条）**：有效地**指导审计工作**；有利于**提高审计工作效率**；有利于**保证审计项目质量**；有利于**规范审计工作**
  - **狭义的审计流程**：审计人员在**取得审计证据、完成审计目标、得出审计结论**过程中所采取的步骤和方法
  - **广义的审计流程**：审计机构和审计人员对审计项目**从开始到结束的整个过程**采取的系统性工作步骤，分为**审计准备、审计实施、审计终结及后续审计**四个阶段
  > 记法：考「四阶段」默认问**广义**；狭义只管「证据 → 结论」一段
- [ ] **C1 · 审计流程四阶段** ⭕ 必背（工作清单归属年年考）
  | 阶段 | 定位句 | 工作清单 |
  |---|---|---|
  | **① 审计准备** | 从**计划开始到发出审计通知书**为止；整个审计过程的**起点和基础** | 1 明确审计目的及任务；2 **组建审计项目组**；3 搜集相关信息；4 **编制审计计划** |
  | **② 审计实施** | 将项目审计计划付诸实施；审计全过程的**中心环节**、整个流程的**关键阶段** | 1 深入调查并**调整审计计划**；2 了解并**初步评估 IT 内部控制**；3 进行**符合性测试**；4 进行**实质性测试** |
  | **③ 审计终结** | 整理审计工作底稿、总结审计工作、编写审计报告、做出审计结论的期间 | 1 整理与**复核**审计工作底稿；2 整理**审计证据**；3 评价相关 **IT 控制目标**的实现；4 判断并**报告审计发现**；5 **沟通**审计结果；6 **出具审计报告**；7 **归档管理** |
  | **④ 后续审计** | 审计报告发出后一定时间内，检查被审计单位是否采取**纠正措施**并取得预期效果的**跟踪审计** | **不是一次新的审计**，是前一次审计的**有机组成部分**；可不必遵守审计流程的每一过程和要求，但必须**依法依规**检查、调查、收集证据，写出**后续审计报告** |
  > 口诀：准备「**目组搜编**」→ 实施「**调评符实**」→ 终结七件事「**稿证评报沟档**」→ 后续「**跟踪纠错不重审**」
  > ⚠️ 题眼：「符合性测试 / 实质性测试」只出现在**实施**阶段；「发出审计通知书」是**准备**阶段的终点；「后续审计不是一次新的审计」是判断题常客

### 模块 D ｜ 审计内容（3.2.4 · 两大类归属题主力）

- [ ] **D0 · 审计内容总览（两大类）** ⭕ 必背
  IT 审计主要分为 **IT 内部控制审计** 和 **IT 专项审计** 两大类。
  - **IT 内部控制审计**：聚焦组织 IT 内部控制的**有效性**，包括**三类**
  - **IT 专项审计**：根据当前面临的**特殊风险或者需求**开展的 IT 审计，审计范围可为 IT 综合审计的**某一个或几个部分**，包括**六种**
  > 口诀：**内控三类 · 专项六种**
- [ ] **D1 · IT 内部控制审计（三类）** ⭕ 必背（层次归属题）
  | 类别 | 审计对象 |
  |---|---|
  | **组织层面 IT 控制审计** | **IT 战略、组织、架构、业务连续性、风险管理、外包管理、网络与信息安全、监督管理**等 |
  | **IT 一般控制审计** | 与**应用系统、数据库、操作系统、网络**相关的**策略和措施**等 |
  | **应用控制审计** | **业务流程层面运行的人工或自动化程序**，主要包括**输入控制、处理控制、输出控制**审计 |
  > 记法：从上到下 =「**组织 → 一般 → 应用**」三层；组织层面八项「**战组架连险包安监**」；应用控制三控制「**入 · 处 · 出**」
  > ⚠️ 题眼：「输入 / 处理 / 输出控制」是**应用控制审计**的内容，别答成一般控制；「操作系统、数据库的策略措施」是**一般控制**，别答成组织层面
- [ ] **D2 · IT 专项审计（六种）** ⭕ 必背（名称 - 内容配对题）
  | # | 专项审计 | 核心内容 |
  |---|---|---|
  | 1 | **信息系统生命周期审计** | 对信息系统的**规划、设计、开发、测试、运行和维护**等进行审计 |
  | 2 | **信息系统开发过程审计** | 围绕信息系统的**规划、设计、建设、实施**是否符合 **IT 架构和战略**进行评估和监督 |
  | 3 | **信息系统运行维护审计** | 针对 **IT 运维能力**、IT 运维**流程（策划、实施、监控、改进）**等情况；内容包括**基础设施的运行、系统的运行、维护、质量保证及 IT 服务管理**等 |
  | 4 | **网络与信息安全审计** | 以网络与信息安全为核心，围绕安全相关的**组织、人员、系统、设备和环境**等；重点关注**流程制度的执行情况**、对相关**法律法规的遵从性**（含数据保护、个人隐私保护等合规要求） |
  | 5 | **信息系统项目审计** | 通过对**信息系统项目管理过程**的评价，向管理层提供项目管理过程**得到控制、监督并遵循最佳实践要求**的**合理保证** |
  | 6 | **数据审计** | 通过控制活动，负责**定期分析、验证、讨论、改进**数据安全管理相关的**政策、标准和活动** |

- [ ] **D3 · 信息系统项目管理审计（专项示例）** ⭕ 常考
  信息系统项目审计聚焦项目管理全过程，示例四类别 + 三方法：

  | **项目启动与计划** | 启动会规范性、项目目标清晰度、团队组建与职责分工、计划完备性 |
  | **项目实施与控制** | 干系人参与、沟通机制、资源利用、配置管理、采购规范、风险管理、绩效评价、文档真实性、进度与质量控制 |

  - **常用审计方法**：**访谈**项目管理相关人员；**观察**项目现场环境；**检查**项目审查记录、发布通知、安全事件记录、测试资料等

<summary>参考答案（先自己答完再展开）</summary>

1. IT 审计是根据 **IT 审计标准**的要求，对**信息系统及相关的 IT 内部控制和流程**进行**检查、评价**，并**发表审计意见**。角色：IT 治理的**评估和监督工具**
2. IT 审计风险（固有、控制、检查）对组织影响的**严重程度**；后果：**财务损失、业务中断、失去客户信任、经济制裁**
3. 通过开展 IT 审计工作，了解组织 IT 系统与 IT 活动的**总体状况**，对组织是否实现 **IT 目标**进行**审查和评价**，充分**识别与评估**相关 IT 风险，提出**评价意见及改进建议**，**促进组织实现 IT 目标**。落点 = 促进实现 IT 目标（「保护信息资产安全」是 IT 目标，不是审计目的本身）
4. ①IT 战略与业务战略**保持一致**；②保护**信息资产**安全及数据的**完整、可靠、有效**；③提高**信息系统**的安全性、可靠性及有效性；④合理保证符合**法律、法规及标准**要求。「完整可靠有效」修饰**数据**；「安全可靠有效」修饰**信息系统**
5. **总体范围**（根据审计目的和投入的审计成本确定）/ **组织范围**（组织机构、主要流程、活动及人员）/ **物理范围**（具体的物理地点与边界）/ **逻辑范围**（涉及的信息系统和逻辑边界）
6. **职业道德、知识、技能、资格与经验、专业胜任能力、利用外部专家服务**；出自 **GB/T 34690.4《信息技术服务 治理 第 4 部分：审计导则》**
7. **固有风险**（IT 活动不存在相关控制的情况下，易于导致重大错误的风险）；**控制风险**（与 IT 活动相关的内部控制体系不能及时预防或检查出存在的重大错误的风险）；**检查风险**（通过预定的审计程序未能发现重大、单个或与其他错误相结合的风险）；**总体审计风险**（针对单个控制目标所产生的各类审计风险总和）
8. **固有风险与控制风险**都只能评估、无法控制或影响（固有 = 活动本身所具有；控制 = 内控范畴、与审计无关）。检查风险的影响因素：**IT 审计规范不完善、审计人员自身或技术原因**等
9. 「内部控制体系不能及时预防或检查出」= **控制风险**；「预定审计程序未能发现」= **检查风险**
10. ①**信息系统审计准则**（ISACA 国际信息系统审计协会发布）；②**《内部控制——整体框架》**（COSO 报告）；③**《萨班斯法案》SOX**（美国法律，管会计职业监管、组织治理、证券市场监管）；④**COBIT**（目前国际上通用的信息及相关技术控制规范）
11. **访谈法、调查法、检查法、观察法、测试法、程序代码检查法**。抽样法属于**审计技术**（审计抽样技术），不是常用方法
12. **风险评估技术、审计抽样技术、计算机辅助审计技术、大数据审计技术**
13. 风险识别：**德尔菲法、头脑风暴、检查表法、SWOT 技术及图解技术**；风险分析：**定性分析 + 定量分析**；风险评价：**单因素风险评价 + 总体风险评价**
14. 属性抽样 = **固定样本抽样 / 频率估计抽样**，回答「**有多少**」（总体中某种属性的发生率）；变量抽样 = **金额估计抽样 / 平均值估计抽样**，由样本估计总体的**货币金额或其他度量单位**
15. **大数据智能分析技术、大数据可视化分析技术、大数据多数据源综合分析技术**
16. **充分性、客观性、相关性、可靠性、合法性**；审计证据是**审计意见的支柱**、审计人员形成**审计结论的基础**
17. 审计人员对**制订的审计计划、实施的审计程序、获取的相关审计证据、得出的审计结论**做出的记录；分**综合类、业务类、备查类**三类
18. 内容：**资料翔实、重点突出、繁简得当、结论明确**；形式：**要素齐全、格式规范、标识一致、记录清晰**
19. **审计机构负责人、部门负责人、项目负责人（或项目经理）**；归档后由**档案管理部门**管理
20. 作用：有效**指导审计工作** / **提高审计工作效率** / **保证审计项目质量** / **规范审计工作**。狭义 = 取得证据、完成目标、得出结论过程中的步骤方法；广义 = 项目**从开始到结束的整个过程**的系统性工作步骤（四阶段）
21. **准备**（计划开始 → 发出审计通知书；起点和基础）：明确目的任务 / 组建项目组 / 搜集信息 / 编制计划。**实施**（中心环节、关键阶段）：深入调查并调整计划 / 了解并初步评估 IT 内部控制 / 符合性测试 / 实质性测试。**终结**（整理底稿、总结、编写报告、做出结论）：整理复核底稿 / 整理证据 / 评价控制目标实现 / 判断报告发现 / 沟通结果 / 出具报告 / 归档。**后续**（跟踪纠错）：不是一次新的审计，是前次的有机组成部分；依法依规收集证据、写后续审计报告
22. **IT 内部控制审计**（组织层面 IT 控制审计 / IT 一般控制审计 / 应用控制审计）+ **IT 专项审计**（生命周期 / 开发过程 / 运行维护 / 网络与信息安全 / 信息系统项目 / 数据审计 六种）。组织层面审 IT 战略、组织、架构、业务连续性、风险管理、外包管理、网络与信息安全、监督管理；一般控制审与应用系统、数据库、操作系统、网络相关的策略和措施；应用控制审业务流程层面的人工或自动化程序（输入 / 处理 / 输出控制）。「得到控制、监督并遵循最佳实践要求的合理保证」配**信息系统项目审计**
