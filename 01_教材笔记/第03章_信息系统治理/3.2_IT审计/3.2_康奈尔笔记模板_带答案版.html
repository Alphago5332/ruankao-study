3.2.1 IT审计基础
1IT 审计的定义、角色与重要性
  • 定义（GB/T 34690.4《信息技术服务 治理 第 4 部分：审计导则》）：IT 审计是根据 IT 审计标准的要求，对信息系统及相关的 IT 内部控制和流程进行检查、评价，并发表审计意见
  • 角色：IT 审计是 IT 治理的评估和监督工具（3.1 治理流程里的「评估、监督」由审计落地）；为有效控制 IT 风险而开展，发挥审计监督作用
  • 重要性：指 IT 审计风险（固有、控制、检查）对组织影响的严重程度，如：财务损失 · 业务中断 · 失去客户信任 · 经济制裁
定义抓四词：标准 · 检查评价 · 内部控制流程 · 发表意见。出处记法：4960 = 治理，4690 = 审计，两个国标号别互换
2审计目的与组织的 IT 目标
  • 目的：通过开展 IT 审计工作，了解组织 IT 系统与 IT 活动的总体状况，对组织是否实现 IT 目标进行审查和评价，充分识别与评估相关 IT 风险，提出评价意见及改进建议，促进组织实现 IT 目标
  • IT 目标四条：①IT 战略应与业务战略保持一致；②保护信息资产安全及数据的完整、可靠、有效；③提高信息系统的安全性、可靠性及有效性；④合理保证符合有关法律、法规及标准等要求
口诀：一致 · 安全 · 三性 · 合规。⚠️「完整可靠有效」修饰数据，「安全可靠有效」修饰信息系统；真题考过「不属于审计目的」——选「保护信息资产的安全」（那是 IT 目标，目的的落点是促进实现 IT 目标）
3审计范围四范围与审计人员要求
  • 总体范围：根据审计目的和投入的审计成本来确定
  • 组织范围：审计涉及的组织机构、主要流程、活动及人员等
  • 物理范围：具体的物理地点与边界
  • 逻辑范围：涉及的信息系统和逻辑边界
  • 定重点：实施前先了解 + 风险评估，确定主要 IT 风险，结合预计的时间、配备的审计力量确定重点审计范围
  • 人员要求六方面（GB/T 34690.4）：职业道德 · 知识 · 技能 · 资格与经验 · 专业胜任能力 · 利用外部专家服务
口诀：总组物逻；「目的 + 成本」只配总体范围。人员要求记「德知技资胜外」
4IT 审计风险（四类）
  • 固有风险：IT 活动不存在相关控制的情况下，易于导致重大错误的风险；IT 活动本身所具有，审计人员只能评估，无法控制或影响；衡量是主观的、复杂的
  • 控制风险：与 IT 活动相关的内部控制体系不能及时预防或检查出存在的重大错误的风险；与内控制度执行的有效性有关、与审计无关；审计人员只能评估其风险水平
  • 检查风险：通过预定的审计程序未能发现重大、单个或与其他错误相结合的风险；影响因素：IT 审计规范不完善、审计人员自身或技术原因等
  • 总体审计风险：针对单个控制目标所产生的各类审计风险的总和
口诀：固有 = 没控制就出错（自带）· 控制 = 内控没拦住 · 检查 = 审计没查出 · 总体 = 单目标总和。题眼：「内部控制」字样 → 控制风险；「活动本身」→ 固有；「预定程序未发现」→ 检查
3.2.2 审计方法与技术
5国际常用审计准则（四项）
  • 信息系统审计准则：ISACA（国际信息系统审计协会）发布
  • 《内部控制——整体框架》报告：通称 COSO 报告（美国虚假财务报告委员会下属的发起人委员会）
  • 《萨班斯法案》（SOX）：美国政府出台的涉及会计职业监管、组织治理、证券市场监管改革的重要法律
  • COBIT（信息及相关技术控制目标）：目前国际上通用的信息及相关技术控制规范
记法：ISACA 出准则 · COSO 出内控 · SOX 是美国法 · COBIT 是控制目标。COBIT 在 3.1.4 是「治理框架」、在本节是「审计准则」——一个框架两处出场，不冲突
6常用方法六法 + 审计技术四类
  • 常用方法六法：访谈法 · 调查法 · 检查法 · 观察法 · 测试法 · 程序代码检查法
  • 审计技术四类：风险评估技术 · 审计抽样技术 · 计算机辅助审计技术 · 大数据审计技术
口诀：方法「访调检观试码」、技术「评抽辅数」。⚠️ 抽样是技术不是方法；干扰项常用「穿行法 / 复核法」冒充方法
7风险评估技术 · 抽样 · 大数据审计
  • 风险评估技术四小类：①风险识别：德尔菲法、头脑风暴、检查表法、SWOT 技术及图解技术；②风险分析：定性分析 + 定量分析；③风险评价：单因素评价 + 总体风险评价；④风险应对：云计算、冗余链路、冗余资源、系统弹性伸缩、两地三中心灾备、业务熔断限流等
  • 属性抽样（固定样本抽样 / 频率估计抽样）：估计总体中某种属性的发生率，回答「有多少」
  • 变量抽样（金额估计抽样 / 平均值估计抽样）：由样本估计总体的货币金额或其他度量单位
  • 大数据审计三技术：大数据智能分析 · 大数据可视化分析 · 大数据多数据源综合分析
属性答「有多少」、变量答「值多少」；风险应对技术记「云 / 冗余 / 弹性 / 灾备 / 熔断限流」几个关键词即可
8IT 审计证据
  • 定义：由审计机构和审计人员获取，用于确定所审计实体或数据是否遵循既定标准或目标，形成审计结论的证明材料
  • 定位：审计证据是审计意见的支柱，是审计人员形成审计结论的基础
  • 特性五条：充分性 · 客观性 · 相关性 · 可靠性 · 合法性
口诀：充 · 客 · 相 · 可 · 合。干扰项常用「真实性 / 完整性 / 及时性」冒充
9IT 审计工作底稿
  • 定义：审计人员对制订的审计计划、实施的审计程序、获取的相关审计证据、得出的审计结论做出的记录
  • 分类三类：综合类 · 业务类 · 备查类工作底稿
  • 编制要求：内容——资料翔实、重点突出、繁简得当、结论明确；形式——要素齐全、格式规范、标识一致、记录清晰
  • 作用四条：形成审计结论、发表审计意见的直接依据；评价考核审计人员的主要依据；审计质量控制与监督的基础；对未来审计业务的参考备查作用
  • 三级复核：审计机构负责人 · 部门负责人 · 项目负责人（或项目经理）
  • 泄密例外两种：①法院、检察院及国家其他部门依法查阅并按规定办理必要手续；②审计协会或其委派单位对执业情况进行检查。归档后由档案管理部门管理
分类「综业备」；三级复核「机构 → 部门 → 项目」由大到小；内容四条「翔实 · 突出 · 得当 · 明确」对形式四条「齐全 · 规范 · 一致 · 清晰」
3.2.3 流程 · 3.2.4 内容
10审计流程的含义与作用
  • 作用四条：有效地指导审计工作；有利于提高审计工作效率；有利于保证审计项目质量；有利于规范审计工作
  • 狭义：审计人员在取得审计证据、完成审计目标、得出审计结论过程中所采取的步骤和方法
  • 广义：审计机构和审计人员对审计项目从开始到结束的整个过程采取的系统性工作步骤，分为审计准备、审计实施、审计终结及后续审计四个阶段
考「四阶段」默认问广义；狭义只管「证据 → 结论」一段
11审计流程四阶段（定位句 + 工作清单）
  • ① 准备（从计划开始到发出审计通知书为止；整个过程的起点和基础）：明确审计目的及任务 · 组建审计项目组 · 搜集相关信息 · 编制审计计划
  • ② 实施（将计划付诸实施；审计全过程的中心环节、关键阶段）：深入调查并调整审计计划 · 了解并初步评估 IT 内部控制 · 进行符合性测试 · 进行实质性测试
  • ③ 终结（整理底稿、总结工作、编写报告、做出结论期间）：整理与复核底稿 · 整理审计证据 · 评价相关 IT 控制目标的实现 · 判断并报告审计发现 · 沟通审计结果 · 出具审计报告 · 归档管理
  • ④ 后续审计（检查是否采取纠正措施并取得预期效果的跟踪审计）：不是一次新的审计，是前一次审计的有机组成部分；可不必遵守每一过程和要求，但必须依法依规检查调查、收集证据、写后续审计报告
口诀：准备「目组搜编」→ 实施「调评符实」→ 终结七件事「稿证评报沟档」→ 后续「跟踪纠错不重审」。⚠️「符合性 / 实质性测试」只在实施阶段；「发出审计通知书」是准备阶段终点
12审计内容：两大类 + 内控三类 + 专项六种
总览
  • IT 审计主要分为 IT 内部控制审计 和 IT 专项审计 两大类；专项审计 = 根据当前面临的特殊风险或需求开展，范围可为 IT 综合审计的某一个或几个部分
IT 内部控制审计（三类）
  • 组织层面 IT 控制审计：IT 战略、组织、架构、业务连续性、风险管理、外包管理、网络与信息安全、监督管理
  • IT 一般控制审计：与应用系统、数据库、操作系统、网络相关的策略和措施
  • 应用控制审计：业务流程层面运行的人工或自动化程序——输入控制、处理控制、输出控制
IT 专项审计（六种）
  • 信息系统生命周期审计（规划·设计·开发·测试·运行·维护）· 开发过程审计（规划·设计·建设·实施是否符合 IT 架构和战略）· 运行维护审计（运维能力 + 流程策实监改；含基础设施运行 / 系统运行 / 维护 / 质量保证 / IT 服务管理）· 网络与信息安全审计（组织·人员·系统·设备·环境；流程制度执行 + 法律遵从）· 信息系统项目审计（项目管理过程得到控制、监督并遵循最佳实践的合理保证）· 数据审计（定期分析·验证·讨论·改进数据安全管理相关政策标准活动）
项目管理审计示例
  • 四类别：组织管理 · 项目启动与计划 · 项目实施与控制 · 项目收尾管理；三方法：访谈 · 观察 · 检查
口诀：内控三类「组织→一般→应用」、专项六种「生开运网项数」。「入处出」三控制属应用控制；「合理保证」配项目审计
总结区 本节本质 + 考点地图
本节本质：3.2 回答「谁来看住 IT 治理的效果」。主线四步：基础（定义·目的·范围·人员·风险）→ 方法与技术（怎么审）→ 流程（按什么顺序审）→ 内容（审什么）。全节没有计算，题型是「定义配对 + 阶段工作归属 + 类别归属」三类，数字型考点密集（4 目标 / 4 范围 / 4 风险 / 4 准则 / 6 方法 / 4 技术 / 5 证据特性 / 3+4+4 底稿 / 4 阶段 / 2 大类 3+6）。
考点地图（按考频排序）：① 四类审计风险定义配对（固有 / 控制 / 检查 / 总体）→ ② 审计流程四阶段工作清单归属（符合性·实质性测试在实施）→ ③ 组织的 IT 目标四条（数据三性 vs 系统三性）→ ④ 审计证据五特性 → ⑤ 内部控制审计三类（组织层面 / 一般控制 / 应用控制·入处出）→ ⑥ 专项审计六种 → ⑦ 审计底稿（分类综业备 + 三级复核）→ ⑧ 抽样两分法（属性有多少 / 变量值多少）→ ⑨ 审计准则四项归属（ISACA / COSO / SOX / COBIT）→ ⑩ 四范围「总组物逻」→ ⑪ 审计定义与目的句（落点 = 促进实现 IT 目标）→ ⑫ 审计人员要求六方面。
⚠️ 口径陷阱：① 34960 = 治理、34690.4 = 审计导则，编号别换位；② 目的句的落点是「促进组织实现 IT 目标」——「保护信息资产安全」是 IT 目标不是审计目的；③ 「符合性 / 实质性测试」只在实施阶段，别填进准备或终结；④ 「后续审计不是一次新的审计」是判断题常客；⑤ 抽样、计算机辅助、大数据是审计技术不是「常用方法」；⑥ 「输入 / 处理 / 输出控制」属应用控制审计；⑦ 属性抽样 = 频率估计（有多少）、变量抽样 = 金额估计（值多少）；⑧ 三级复核 = 机构负责人 → 部门负责人 → 项目负责人，由大到小；⑨ 第 3 章 2023 上以前旧真题无对应题，别拿旧题正确率评估掌握度。
