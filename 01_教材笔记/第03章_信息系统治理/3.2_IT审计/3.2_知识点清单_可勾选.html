一、必背清单

模块 A ｜ IT 审计基础（3.2.1）

IT 审计（GB/T 34690.4《信息技术服务 治理 第 4 部分：审计导则》）是指根据 IT 审计标准的要求，对信息系统及相关的 IT 内部控制和流程进行检查、评价，并发表审计意见。

• 引入句：为了有效控制 IT 风险，有必要对组织的信息系统治理及 IT 内控与管理等开展 IT 审计，充分发挥 IT 审计监督的作用
• 定位：IT 审计是 IT 治理的评估和监督工具（3.1 治理流程里的「评估、监督」由审计落地）
记法：定义抓四个词——标准 · 检查评价 · 内部控制流程 · 发表意见；出处记 GB/T 34690.4 = 审计导则（勿与 3.1 的 GB/T 34960 系列混：4960 = 治理，4690 = 审计）
• IT 审计重要性：指 IT 审计风险（固有风险、控制风险、检查风险）对组织影响的严重程度，如：财务损失、业务中断、失去客户信任、经济制裁等
• IT 审计的目的：通过开展 IT 审计工作，了解组织 IT 系统与 IT 活动的总体状况，对组织是否实现 IT 目标进行审查和评价，充分识别与评估相关 IT 风险，提出评价意见及改进建议，促进组织实现 IT 目标
⚠️ 判断题眼：目的句的落点是「促进实现 IT 目标」——「保护信息资产安全」是 IT 目标之一，不是审计目的本身（真题考过「不属于审计目的」选「保护信息资产的安全」）
#IT 目标
1组织的 IT 战略应与业务战略保持一致
2保护信息资产的安全及数据的完整、可靠、有效
3提高信息系统的安全性、可靠性及有效性
4合理保证信息系统及其运用符合有关法律、法规及标准等的要求
口诀：一致 · 安全 · 三性 · 合规（数据三性「完整可靠有效」≠ 系统三性「安全可靠有效」，别对调）
范围依据 / 内容
总体范围根据审计目的和投入的审计成本来确定
组织范围审计涉及的组织机构、主要流程、活动及人员等
物理范围具体的物理地点与边界
逻辑范围涉及的信息系统和逻辑边界
• 实施审计项目前，审计人员应先对组织与信息系统相关的总体情况进行了解和风险评估，确定主要 IT 风险，结合审计项目预计的时间、配备的审计力量等确定重点审计范围
口诀：总组物逻；「目的 + 成本」只配总体范围，其余按各自内容配对

根据 GB/T 34690.4，对 IT 审计人员的要求包括：职业道德、知识、技能、资格与经验、专业胜任能力、利用外部专家服务等方面

记法：六个词「德 · 知 · 技 · 资 · 胜 · 外」；出处仍是 34690.4（审计导则管审计人员）
风险定义关键特点
固有风险IT 活动不存在相关控制的情况下，易于导致重大错误的风险IT 活动本身所具有；审计人员只能评估，无法控制或影响；衡量是主观的、复杂的
控制风险与 IT 活动相关的内部控制体系不能及时预防或检查出存在的重大错误的风险与内部控制制度执行的有效性有关，与审计无关；审计人员只能评估其风险水平
检查风险通过预定的审计程序未能发现重大、单个或与其他错误相结合的风险影响因素：IT 审计规范不完善、审计人员自身或技术原因等
总体审计风险针对单个控制目标所产生的各类审计风险的总和= 固有 + 控制 + 检查三者的综合体现
口诀：固有 = 没控制就出错（活动自带）· 控制 = 内控没拦住 · 检查 = 审计没查出 · 总体 = 单目标总和
⚠️ 题眼：「内部控制体系」字样 → 控制风险；「不存在相关控制 / 活动本身」→ 固有风险；「预定审计程序未发现」→ 检查风险

模块 B ｜ 审计方法与技术（3.2.2）

IT 审计活动的开展需要结合相关法律法规、准则与标准。国际上发布的常用审计准则有四项：

准则说明
信息系统审计准则ISACA（国际信息系统审计协会）发布
《内部控制——整体框架》报告通称 COSO 报告（美国虚假财务报告委员会下属的发起人委员会）
《萨班斯法案》（SOX）美国政府出台的涉及会计职业监管、组织治理、证券市场监管等方面改革的重要法律
COBIT（信息及相关技术控制目标）目前国际上通用的信息及相关技术控制规范
记法：ISACA 出准则 · COSO 出内控 · SOX 是美国法 · COBIT 是控制目标（COBIT 在 3.1.4 是「治理框架」、在本节是「审计准则」——一个框架两处出场，不冲突）

访谈法、调查法、检查法、观察法、测试法、程序代码检查法

口诀：访调检观试码；干扰项常用「穿行法 / 抽样法 / 复核法」——抽样是「审计技术」不是「常用方法」
技术内容
风险评估技术①风险识别：德尔菲法、头脑风暴、检查表法、SWOT 技术及图解技术；②风险分析：定性分析 + 定量分析；③风险评价：单因素风险评价 + 总体风险评价；④风险应对：云计算、冗余链路、冗余资源、系统弹性伸缩、两地三中心灾备、业务熔断限流等
审计抽样技术①属性抽样（固定样本抽样 / 频率估计抽样）：估计总体中某种属性的发生率，回答「有多少」；②变量抽样（金额估计抽样 / 平均值估计抽样）：由样本估计总体的货币金额或其他度量单位
计算机辅助审计技术利用计算机软件工具辅助完成审计工作（提取、分析、比对数据等）
大数据审计技术大数据智能分析技术、大数据可视化分析技术、大数据多数据源综合分析技术
记法：技术四类「评抽辅数」；属性抽样答「有多少」、变量抽样答「值多少」；大数据三技术「智能 · 可视 · 多源」
• 定义：由审计机构和审计人员获取，用于确定所审计实体或数据是否遵循既定标准或目标，形成审计结论的证明材料；审计证据是审计意见的支柱，是审计人员形成审计结论的基础
• 特性（五条）：充分性、客观性、相关性、可靠性、合法性
口诀：充 · 客 · 相 · 可 · 合
• 定义：审计人员对制订的审计计划、实施的审计程序、获取的相关审计证据、得出的审计结论做出的记录
• 分类（三类）：综合类工作底稿、业务类工作底稿、备查类工作底稿
• 编制要求：①内容——资料翔实、重点突出、繁简得当、结论明确；②形式——要素齐全、格式规范、标识一致、记录清晰
• 作用（四条）：形成审计结论、发表审计意见的直接依据；评价考核审计人员的主要依据；审计质量控制与监督的基础；对未来审计业务具有参考备查作用
• 三级复核制度：审计机构负责人、部门负责人、项目负责人（或项目经理）为复核人
• 保密例外（两种情况查阅不属于泄密）：①法院、检察院及国家其他部门依法查阅并按规定办理了必要手续；②审计协会或其委派单位对审计机构执业情况进行检查
• 归档后由档案管理部门管理，确保安全、完整
口诀：分类「综业备」；内容四条「翔实 · 突出 · 得当 · 明确」对形式四条「齐全 · 规范 · 一致 · 清晰」；三级复核「机构 → 部门 → 项目」由大到小

模块 C ｜ 审计流程（3.2.3 · 流程阶段归属题主力）

• 作用（四条）：有效地指导审计工作；有利于提高审计工作效率；有利于保证审计项目质量；有利于规范审计工作
• 狭义的审计流程：审计人员在取得审计证据、完成审计目标、得出审计结论过程中所采取的步骤和方法
• 广义的审计流程：审计机构和审计人员对审计项目从开始到结束的整个过程采取的系统性工作步骤，分为审计准备、审计实施、审计终结及后续审计四个阶段
记法：考「四阶段」默认问广义；狭义只管「证据 → 结论」一段
阶段定位句工作清单
① 审计准备从计划开始到发出审计通知书为止；整个审计过程的起点和基础1 明确审计目的及任务；2 组建审计项目组；3 搜集相关信息；4 编制审计计划
② 审计实施将项目审计计划付诸实施；审计全过程的中心环节、整个流程的关键阶段1 深入调查并调整审计计划；2 了解并初步评估 IT 内部控制；3 进行符合性测试；4 进行实质性测试
③ 审计终结整理审计工作底稿、总结审计工作、编写审计报告、做出审计结论的期间1 整理与复核审计工作底稿；2 整理审计证据；3 评价相关 IT 控制目标的实现；4 判断并报告审计发现；5 沟通审计结果；6 出具审计报告；7 归档管理
④ 后续审计审计报告发出后一定时间内，检查被审计单位是否采取纠正措施并取得预期效果的跟踪审计不是一次新的审计，是前一次审计的有机组成部分；可不必遵守审计流程的每一过程和要求，但必须依法依规检查、调查、收集证据，写出后续审计报告
口诀：准备「目组搜编」→ 实施「调评符实」→ 终结七件事「稿证评报沟档」→ 后续「跟踪纠错不重审」
⚠️ 题眼：「符合性测试 / 实质性测试」只出现在实施阶段；「发出审计通知书」是准备阶段的终点；「后续审计不是一次新的审计」是判断题常客

模块 D ｜ 审计内容（3.2.4 · 两大类归属题主力）

IT 审计主要分为 IT 内部控制审计 和 IT 专项审计 两大类。

• IT 内部控制审计：聚焦组织 IT 内部控制的有效性，包括三类
• IT 专项审计：根据当前面临的特殊风险或者需求开展的 IT 审计，审计范围可为 IT 综合审计的某一个或几个部分，包括六种
口诀：内控三类 · 专项六种
类别审计对象
组织层面 IT 控制审计IT 战略、组织、架构、业务连续性、风险管理、外包管理、网络与信息安全、监督管理等
IT 一般控制审计与应用系统、数据库、操作系统、网络相关的策略和措施等
应用控制审计业务流程层面运行的人工或自动化程序，主要包括输入控制、处理控制、输出控制审计
记法：从上到下 =「组织 → 一般 → 应用」三层；组织层面八项「战组架连险包安监」；应用控制三控制「入 · 处 · 出」
⚠️ 题眼：「输入 / 处理 / 输出控制」是应用控制审计的内容，别答成一般控制；「操作系统、数据库的策略措施」是一般控制，别答成组织层面
#专项审计核心内容
1信息系统生命周期审计对信息系统的规划、设计、开发、测试、运行和维护等进行审计
2信息系统开发过程审计围绕信息系统的规划、设计、建设、实施是否符合 IT 架构和战略进行评估和监督
3信息系统运行维护审计针对 IT 运维能力、IT 运维流程（策划、实施、监控、改进）等情况；内容包括基础设施的运行、系统的运行、维护、质量保证及 IT 服务管理等
4网络与信息安全审计以网络与信息安全为核心，围绕安全相关的组织、人员、系统、设备和环境等；重点关注流程制度的执行情况、对相关法律法规的遵从性（含数据保护、个人隐私保护等合规要求）
5信息系统项目审计通过对信息系统项目管理过程的评价，向管理层提供项目管理过程得到控制、监督并遵循最佳实践要求的合理保证
6数据审计通过控制活动，负责定期分析、验证、讨论、改进数据安全管理相关的政策、标准和活动
口诀：六种 =「生命周期 · 开发 · 运维 · 网安 · 项目 · 数据」；「合理保证」句配项目审计；运维流程四词「策实监改」

信息系统项目审计聚焦项目管理全过程，示例四类别 + 三方法：

审计类别核心审计内容
组织管理项目管理机构设置、制度流程制定、团队组成与人员能力要求
项目启动与计划启动会规范性、项目目标清晰度、团队组建与职责分工、计划完备性
项目实施与控制干系人参与、沟通机制、资源利用、配置管理、采购规范、风险管理、绩效评价、文档真实性、进度与质量控制
项目收尾管理验收申请材料规范性、验收流程、验收及时性、项目质量、第三方检测机构合规性
• 常用审计方法：访谈项目管理相关人员；观察项目现场环境；检查项目审查记录、发布通知、安全事件记录、测试资料等
口诀：四类别「组 · 启 · 施 · 收」；方法就是 B1 六法中的「访 · 观 · 检」

• 本节全是概念 + 归属，无计算；最高频四块：三风险定义配对 / 审计流程四阶段 / 证据五特性 / 内部控制三类
对照差别
GB/T 34960 vs GB/T 34690.434960 系列 = IT 治理（3.1）；34690.4 = 审计导则（3.2，管定义、管审计人员要求）——「4960 治理 / 4690 审计」
符合性测试 vs 实质性测试都是实施阶段的工作：符合性测试测「控制有没有被有效执行」，实质性测试测「数据 / 事项本身的真实准确」；初步评估内控也在实施阶段（先评 → 符合 → 实质，三步别倒）
属性抽样 vs 变量抽样属性抽样 = 固定样本 / 频率估计，答「有多少（发生率）」；变量抽样 = 金额估计 / 平均值估计，答「值多少（金额）」
组织层面 vs 一般控制 vs 应用控制组织层面看治理管理事项（战略 / 架构 / 外包 / 监督…）；一般控制看系统平台策略（应用系统 / 数据库 / 操作系统 / 网络）；应用控制看业务流程的入处出
「审计常用方法」vs「审计技术」方法六法 = 访调检观试码；技术四类 = 评抽辅数。抽样、计算机辅助、大数据是技术不是方法，出题最爱在这调包

小节处理方式

参考答案（先自己答完再展开）
  1. IT 审计是根据 IT 审计标准的要求，对信息系统及相关的 IT 内部控制和流程进行检查、评价，并发表审计意见。角色：IT 治理的评估和监督工具
  2. IT 审计风险（固有、控制、检查）对组织影响的严重程度；后果：财务损失、业务中断、失去客户信任、经济制裁
  3. 通过开展 IT 审计工作，了解组织 IT 系统与 IT 活动的总体状况，对组织是否实现 IT 目标进行审查和评价，充分识别与评估相关 IT 风险，提出评价意见及改进建议，促进组织实现 IT 目标。落点 = 促进实现 IT 目标（「保护信息资产安全」是 IT 目标，不是审计目的本身）
  4. ①IT 战略与业务战略保持一致；②保护信息资产安全及数据的完整、可靠、有效；③提高信息系统的安全性、可靠性及有效性；④合理保证符合法律、法规及标准要求。「完整可靠有效」修饰数据；「安全可靠有效」修饰信息系统
  5. 总体范围（根据审计目的和投入的审计成本确定）/ 组织范围（组织机构、主要流程、活动及人员）/ 物理范围（具体的物理地点与边界）/ 逻辑范围（涉及的信息系统和逻辑边界）
  6. 职业道德、知识、技能、资格与经验、专业胜任能力、利用外部专家服务；出自 GB/T 34690.4《信息技术服务 治理 第 4 部分：审计导则》
  7. 固有风险（IT 活动不存在相关控制的情况下，易于导致重大错误的风险）；控制风险（与 IT 活动相关的内部控制体系不能及时预防或检查出存在的重大错误的风险）；检查风险（通过预定的审计程序未能发现重大、单个或与其他错误相结合的风险）；总体审计风险（针对单个控制目标所产生的各类审计风险总和）
  8. 固有风险与控制风险都只能评估、无法控制或影响（固有 = 活动本身所具有；控制 = 内控范畴、与审计无关）。检查风险的影响因素：IT 审计规范不完善、审计人员自身或技术原因等
  9. 「内部控制体系不能及时预防或检查出」= 控制风险；「预定审计程序未能发现」= 检查风险
  10. ①信息系统审计准则（ISACA 国际信息系统审计协会发布）；②《内部控制——整体框架》（COSO 报告）；③《萨班斯法案》SOX（美国法律，管会计职业监管、组织治理、证券市场监管）；④COBIT（目前国际上通用的信息及相关技术控制规范）
  11. 访谈法、调查法、检查法、观察法、测试法、程序代码检查法。抽样法属于审计技术（审计抽样技术），不是常用方法
  12. 风险评估技术、审计抽样技术、计算机辅助审计技术、大数据审计技术
  13. 风险识别：德尔菲法、头脑风暴、检查表法、SWOT 技术及图解技术；风险分析：定性分析 + 定量分析；风险评价：单因素风险评价 + 总体风险评价
  14. 属性抽样 = 固定样本抽样 / 频率估计抽样，回答「有多少」（总体中某种属性的发生率）；变量抽样 = 金额估计抽样 / 平均值估计抽样，由样本估计总体的货币金额或其他度量单位
  15. 大数据智能分析技术、大数据可视化分析技术、大数据多数据源综合分析技术
  16. 充分性、客观性、相关性、可靠性、合法性；审计证据是审计意见的支柱、审计人员形成审计结论的基础
  17. 审计人员对制订的审计计划、实施的审计程序、获取的相关审计证据、得出的审计结论做出的记录；分综合类、业务类、备查类三类
  18. 内容：资料翔实、重点突出、繁简得当、结论明确；形式：要素齐全、格式规范、标识一致、记录清晰
  19. 审计机构负责人、部门负责人、项目负责人（或项目经理）；归档后由档案管理部门管理
  20. 作用：有效指导审计工作 / 提高审计工作效率 / 保证审计项目质量 / 规范审计工作。狭义 = 取得证据、完成目标、得出结论过程中的步骤方法；广义 = 项目从开始到结束的整个过程的系统性工作步骤（四阶段）
  21. 准备（计划开始 → 发出审计通知书；起点和基础）：明确目的任务 / 组建项目组 / 搜集信息 / 编制计划。实施（中心环节、关键阶段）：深入调查并调整计划 / 了解并初步评估 IT 内部控制 / 符合性测试 / 实质性测试。终结（整理底稿、总结、编写报告、做出结论）：整理复核底稿 / 整理证据 / 评价控制目标实现 / 判断报告发现 / 沟通结果 / 出具报告 / 归档。后续（跟踪纠错）：不是一次新的审计，是前次的有机组成部分；依法依规收集证据、写后续审计报告
  22. IT 内部控制审计（组织层面 IT 控制审计 / IT 一般控制审计 / 应用控制审计）+ IT 专项审计（生命周期 / 开发过程 / 运行维护 / 网络与信息安全 / 信息系统项目 / 数据审计 六种）。组织层面审 IT 战略、组织、架构、业务连续性、风险管理、外包管理、网络与信息安全、监督管理；一般控制审与应用系统、数据库、操作系统、网络相关的策略和措施；应用控制审业务流程层面的人工或自动化程序（输入 / 处理 / 输出控制）。「得到控制、监督并遵循最佳实践要求的合理保证」配信息系统项目审计
