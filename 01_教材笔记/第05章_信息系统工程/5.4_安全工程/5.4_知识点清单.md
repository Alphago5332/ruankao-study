## 一、必背清单

### 模块 A ｜ 工程概述（5.4.1）

- [ ] **A0 · 信息安全系统工程的由来与定位** ⭕ 必背（总起 + 定位）
  随着互联网畅通与业务扩展，信息安全风险急剧增加。**由业务应用信息系统来解决安全性问题已不能胜任**，**由操作系统、数据库系统、网络管理系统来解决安全问题也不能满足实际需要**，于是不得不建立**独立的信息安全系统**。
  - **信息安全系统工程**就是要**建造一个信息安全系统**，它是整个信息系统工程的一部分，而且**最好是与业务应用信息系统工程同步进行**
  - 建设内容围绕「信息安全」：风险评估 / 策略制定 / 需求确定 / 总体设计 / 详细设计 / 设备选型 / 招投标 / 密钥密码机制确定 / 资源界定和授权 / 施工防泄密 / 测试·运营·维护的安全管理
  > 高频：题干出现「**独立的信息安全系统**」「**与业务应用信息系统工程同步进行**」→ 信息安全系统工程
- [ ] **A1 · 两组术语关系** ⭕ 必背（结构图 + 高频）
  | 上位概念 | 包含的两个部分 |
  |---|---|
  | **信息系统** | **业务应用信息系统** + **信息安全系统** |
  | **信息系统工程** | **业务应用信息系统工程** + **信息安全系统工程** |
  - **信息系统工程的两个部分是「独立且不可分割」的**
  - 信息安全系统**服务于**业务应用信息系统并与之密不可分，但**不能混为一谈**：二者的**功能、操作流程、管理方式、人员要求、技术领域都完全不同**
  - 信息安全系统**不能脱离业务应用信息系统而存在**（如国税 / 公安 / 社保信息系统，一定同时包含两部分）
  > 记法：**「信息系统 = 业 + 安」「信息系统工程 = 业工 + 安工」**——上面一对是「系统」，下面一对是「工程」，别串行
- [ ] **A2 · 四个关键术语的定义** ⭕ 必背（定义配对）
  - **业务应用信息系统**：**支撑业务运营**的计算机应用信息系统，如银行柜台业务信息系统、国税征收信息系统
  - **业务应用信息系统工程**：为达到建设好业务应用信息系统所组织实施的工程，**一般称为「信息系统集成项目工程」**，是信息系统工程的一部分
  - **信息安全系统工程**：为达到建设好信息安全系统的特殊需要而组织实施的工程，是信息系统工程的一部分；**作为信息系统工程的一个子集，其安全体系和策略必须遵从系统工程的一般性原则和规律**
  - 信息安全系统工程原理**适用于系统和应用的开发、集成、运行、管理、维护和演变，以及产品的开发、交付和演变**
  > 判别词：「一般称为**信息系统集成项目工程**」→ 业务应用信息系统工程；「**遵从系统工程一般性原则**」→ 信息安全系统工程
- [ ] **A3 · 术语澄清：讲的是「信息安全系统工程」不是「信息系统安全工程」** ⭕ 必背（辨析）
  教材专设术语澄清：本节讲述的是**信息安全系统工程**，而**不是信息系统安全工程**。
  - 「信息系统安全工程」从字面上会**误解为「安全地建设一个信息系统」**，从而**忽略信息系统中的信息安全问题**（可以安全地建成一个没有信息安全子系统的信息系统 → 留下隐患）
  - 「信息安全系统工程」明白无误地确定了：**这个工程就是建设一个信息安全系统**
  > 高频陷阱：题干若强调「**建一个信息安全系统**」→ 信息安全系统工程；强调「**把信息系统建安全**」是错误理解方向

### 模块 B ｜ 安全系统（5.4.2）

- [ ] **B0 · 信息安全系统的定位与信息安全空间三维** ⭕ 必背（三维坐标）
  **信息安全保障系统一般简称「信息安全系统」**，它是「信息系统」的一个部分，用于**保证「业务应用信息系统」正常运营**。现在人们已明确：要建立一个「信息系统」，就**必须建立一个或多个业务应用信息系统和一个信息安全系统**。信息安全系统是**客观的、独立于业务应用信息系统而存在**的信息系统。
  - 用「宏观」**三维空间图**反映信息安全系统的体系架构：
    | 轴 | 内容 |
    |---|---|
    | **X 轴** | **安全机制** |
    | **Y 轴** | **OSI 网络参考模型**（应用/表示/会话/传输/网络/数据链路/物理） |
    | **Z 轴** | **安全服务** |
  - 由 X、Y、Z 三轴形成的三维空间就是信息系统的「**安全空间**」
  > 记法：**X 机制 · Y OSI · Z 服务**；「许多技术技巧都是在网络各层面上实施的，离开网络信息系统的安全也就失去意义」
- [ ] **B1 · 安全空间五大属性** ⭕ 必背（数量 + 列举）
  随着网络的逐层扩展，安全空间范围逐步加大、内涵更丰富，达到具有**认证、权限、完整、加密和不可否认**五大要素，也叫「**安全空间」的五大属性**。
  > 记法：**「认 · 权 · 完 · 加 · 不可否认」**——注意是**五大属性**，别与安全技术 6 项混
- [ ] **B2 · 安全机制 9 项总览** ⭕ 必背（分类列举 + 高频）
  安全机制可以理解为**提供某些安全服务，利用各种安全技术和技巧，所形成的一个较为完善的结构体系**。包含 **9 项**：
  **基础设施实体安全、平台安全、数据安全、通信安全、应用安全、运行安全、管理安全、授权和审计安全、安全防范体系**。
  > 记法：**「实体 · 平台 · 数据 · 通信 · 应用 · 运行 · 管理 · 授权审计 · 防范体系」**（9 项）
  > ⚠️ 高频陷阱：题干若出现「**平台安全**机制 = 安全操作系统 + 安全数据库 + ……」→ 属安全机制；安全机制是 X 轴
- [ ] **B3 · 平台安全 / 数据安全 / 通信安全 的组成** ⭕ 必背（内容配对）
  - **平台安全**：操作系统漏洞检测与修复、网络基础设施漏洞检测与修复、通用基础应用程序漏洞检测与修复、网络安全产品部署
  - **数据安全**：介质与载体安全保护、数据访问控制、数据完整性、数据可用性、数据监控和审计、数据存储与备份安全
  - **通信安全**：通信线路和网络基础设施安全性测试与优化、安装网络加密设施、设置通信加密软件、设置身份鉴别机制、设置并测试安全通道、测试各项网络协议运行漏洞
  > 判别词：出现「**漏洞检测与修复**」→ 平台安全；出现「**介质与载体 / 访问控制 / 备份**」→ 数据安全；出现「**加密设施 / 安全通道**」→ 通信安全
- [ ] **B4 · 应用安全 / 运行安全 的组成** ⭕ 必背（内容配对）
  - **应用安全**：业务软件程序安全性测试（Bug 分析）、防抵赖测试、访问控制验证测试、身份鉴别检测、备份与恢复机制检查、数据唯一性与一致性及防冲突检测、保密性测试、可靠性测试、可用性测试
  - **运行安全**：应急处置机制和配套服务、网络系统安全性监测、网络安全产品运行监测、定期检查和评估、系统升级和补丁提供、跟踪最新安全漏洞及通报、灾难恢复机制与预防、系统改造管理、网络安全专业技术咨询服务
  > 判别词：出现「**业务软件 / 防抵赖 / 现场**」→ 应用安全；出现「**应急处置 / 监测 / 补丁 / 灾难恢复**」→ 运行安全
- [ ] **B5 · 授权和审计安全 / 安全防范体系（WPDRRC + EISRM）** ⭕ 必背（六环节 + 高频）
  - **授权安全**：以向用户和应用程序**提供权限管理和授权服务**为目标，提供用户身份到应用授权的**映射功能**，实现与具体应用系统开发和管理**无关**的访问控制机制
  - **安全防范体系**：**核心是实现组织信息安全资源的综合管理，即 EISRM（Enterprise Information Security Resource Management）**；其六项能力构成 **WPDRRC** 信息安全保障体系：
    | 环节 | 英文 |
    |---|---|
    | **预警** | Warn |
    | **保护** | Protect |
    | **检测** | Detect |
    | **反应** | Response |
    | **恢复** | Recover |
    | **反击** | Counter-attack |
  - 可结合 WPDRRC 从**人员、技术、政策（法律/法规/制度/管理）三大要素**构成宏观信息网络安全保障体系框架
  > 记法：**WPDRRC = 警 · 保 · 检 · 应 · 恢 · 反**；组织安全防范体系核心 = **EISRM**
- [ ] **B6 · 安全服务 6 项** ⭕ 必背（分类列举 + 高频）
  安全服务就是**从网络中的各个层次提供给信息应用系统所需要的安全服务支持**。包括 **6 项**：
  **对等实体认证服务、数据保密服务、数据完整性服务、数据源点认证服务、禁止否认服务、犯罪证据提供服务**。
  | 服务 | 作用 |
  |---|---|
  | **对等实体认证服务** | 两个开放系统同等层中的实体建立链接或传输数据时，对对方实体的**合法性、真实性**进行确认，**以防假冒** |
  | **数据保密服务** | 防止网络中各系统之间的数据被**截获或非法存取而泄密**，提供密码加密保护（链接/无链接两种方式） |
  | **数据完整性服务** | 防止非法实体对数据的**修改、插入、删除**及交换过程中的**数据丢失**（分 5 种：带/不带恢复功能的链接、选择字段链接、选择字段无链接、无链接） |
  | **数据源点认证服务** | 确保数据**发自真正的源点**，防止假冒 |
  | **禁止否认服务** | 防止发送方**否认发送**、接收方**否认收到或伪造接收**（由「不得否认发送」「不得否认接收」两种组成） |
  | **犯罪证据提供服务** | 为违反法律法规的行为提供**各类数字证据、信息线索** |
  > 记法：**「对 · 密 · 完 · 源 · 否 · 罪」**——注意「数据源点认证」≠「对等实体认证」
- [ ] **B7 · 安全技术 6 项** ⭕ 必背（列举）
  安全技术主要涉及：**加密、数字签名技术、访问控制、数据完整性、认证、数据挖掘**。
  > 记法：**「加 · 签 · 控 · 完 · 认 · 挖」**——⚠️ 教材原文含「**数据挖掘**」这一项（别漏）；「访问控制」（教材旧版 OCR 常误作「防控控制」）
  > 高频陷阱：安全技术 6 项 **≠** 安全服务 6 项 **≠** 安全空间五属性——三组数量都不同，别对调

### 模块 C ｜ 工程基础（5.4.3）

- [ ] **C0 · 工程基础 8 类相关工程** ⭕ 必背（列举 + 数量）
  信息安全系统的建设是在 **OSI 网络参考模型的各个层面**进行的，因此信息安全系统工程活动**离不开其他相关工程**，主要包括 **8 类**：
  **硬件工程、软件工程、通信及网络工程、数据存储与灾备工程、系统工程、测试工程、密码工程、组织信息化工程**。
  > 记法：**「硬 · 软 · 通 · 存 · 系 · 测 · 密 · 组」**（8 类）——「密码工程」是信息安全特色的一个，别漏
- [ ] **C1 · 工程协调** ⭕ 必背（一句话结论）
  信息安全系统建设遵从组织所制定的**安全策略**。而安全策略由**组织和组织的客户和服务对象、集成商、安全产品开发者、密码研制单位、独立评估者和其他相关组织共同协商建立**。
  - 因此信息安全系统工程活动**必须与其他外部实体进行协调**
  - 这些关系接口**遍布各种组织且相互影响**，所以信息安全系统工程与其他工程相比**更加复杂**
  > 高频：题干出现「**安全策略由多方共同协商建立 / 接口遍布各种组织**」→ 强调 ISSE 的**协调性 / 复杂性**
- [ ] **C2 · 安全管理规范 12 项** ⭕ 必背（列举）
  信息安全系统工程应吸纳**安全管理**的成熟规范部分，这些安全管理包括 **12 项**：
  **物理安全、计算机安全、网络安全、通信安全、输入/输出产品的安全、操作系统安全、数据库系统安全、数据安全、信息审计安全、人员安全、管理安全、辐射安全**。
  > 记法：**「物 · 计 · 网 · 通 · 输 · 操 · 库 · 数 · 审 · 人 · 管 · 辐」**（12 项）——注意含「**辐射安全**」

### 模块 D ｜ 工程体系架构 · ISSE-CMM 基础与 ISSE 过程（5.4.4）

- [ ] **D0 · ISSE-CMM 基础** ⭕ 必背（定义 + 三适用组织）
  **ISSE-CMM = 信息安全系统工程能力成熟度模型**（Information Security Systems Engineering Capability Maturity Model），是**信息安全系统工程实施的度量标准**，主要适用于 **3 类组织**：
  - **工程组织**
  - **获取组织**
  - **评估组织**
  > 记法：**「工程施工方 · 获取方 · 评估方」**；⚠️ 它是「**信息安全**系统工程」CMM，**别与软件 CMM / 国内 CSMM 混**
- [ ] **D1 · ISSE 过程三部分** ⭕ 必背（总览 + 高频）
  **ISSE 过程的目标是提供一个框架，每个工程项目都可以对这个框架进行裁剪以符合自己特定的需求。** 由**三个相互独立又有有机联系的基本部分**组成：
  | 过程 | 核心目标 |
  |---|---|
  | **工程过程** | 包括概念、设计、实现、测试、部署、运行、维护、退出的**完整过程**，与其他工程合作识别安全需求、创建解决方案 |
  | **风险过程** | 主要目标是**降低信息系统运行的风险** |
  | **保证过程** | 安全需求**得到满足的可信程度**（非常重要的部分） |
  > 记法：**「工 · 险 · 保」**（工程 / 风险 / 保证）
- [ ] **D2 · 工程过程** ⭕ 必背（八阶段）
  工程过程是一个包括**概念、设计、实现、测试、部署、运行、维护、退出**的**完整过程**；与其他工程合作，**识别安全需求、创建解决方案**。
  > 记法：八阶段「**概 · 设 · 实 · 测 · 部 · 运 · 维 · 退**」——是 ISSE 中涵盖全生命周期的那一部分
- [ ] **D3 · 风险过程** ⭕ 必背（有害事件三组成 + 高频）
  风险过程主要目标是**降低信息系统运行的风险**。**一个有害事件由「威胁、脆弱性和影响」三个部分组成**。
  - 流程：识别威胁 / 脆弱性 / 影响 → 评估风险并优先级排序 → 量化风险、建立风险承受级别 → 实施安全措施减轻风险 → **接受残留风险**
  > 高频陷阱：**有害事件三组成 = 威胁 + 脆弱性 + 影响**（不是「风险+威胁+脆弱性」）
- [ ] **D4 · 保证过程** ⭕ 必背（一句话）
  保证过程是指**安全需求得到满足的可信程度**，它是信息安全系统工程**非常重要的部分**；通过**证据构建保证论据**，确保安全措施**按需求运行**（来自于措施的**正确性和有效性**）。
  > 判别词：出现「**可信程度 / 保证论据**」→ 保证过程

### 模块 E ｜ 工程体系架构 · ISSE-CMM 体系结构（5.4.4）

- [ ] **E0 · ISSE-CMM 体系结构两维设计** ⭕ 必背（结构 + 高频）
  ISSE-CMM 的体系结构可以**在整个信息安全系统工程范围内决定信息安全工程组织的成熟性**；目标是**落实安全策略，从管理和制度化方面突出信息安全工程的基本特征**。采用**两维设计**：
  | 维度 | 名称 | 内容 |
  |---|---|---|
  | 一维 | **域（Domain）** | **域维 / 安全工程过程域**——汇集定义 ISSE 的所有实施活动（即过程域 PA） |
  | 另一维 | **能力（Capability）** | **能力维 / 公共特性**——代表组织能力（过程管理能力 + 制度化能力） |
  > 记法：**「一维域 · 一维能力」**；域维管「**做什么**」（过程域），能力维管「**做得多好**」（公共特性 / 级别）
- [ ] **E1 · 域维：11 个安全工程过程域（PA01~PA11）** ⭕ 必背（列举 + 高频）
  **ISSE 包括 6 个基本实施，这些基本实施被组织成 11 个信息安全工程过程域**（由基本实施组成）：
  | 编号 | 过程域 |
  |---|---|
  | PA01 | **实施安全控制** |
  | PA02 | **评估影响** |
  | PA03 | **评估安全风险** |
  | PA04 | **评估威胁** |
  | PA05 | **评估脆弱性** |
  | PA06 | **建立保证论据** |
  | PA07 | **协调安全** |
  | PA08 | **监控安全态** |
  | PA09 | **提供安全输入** |
  | PA10 | **确定安全需求** |
  | PA11 | **验证和证实安全** |
  > 记法：**「控(01) · 影(02) · 险(03) · 胁(04) · 脆(05) · 据(06) · 协(07) · 监(08) · 输(09) · 需(10) · 证(11)」**
  > ⚠️ 高频陷阱：PA 编号顺序别背串（评估三兄弟顺序 = **影响→风险→威胁→脆弱性**，教材就是这么排的）
- [ ] **E2 · 域维：另 11 个与项目和组织实施有关的过程域（PA12~PA22）** ⭕ 必背（数量 + 列举）
  ISSE-CMM **还包括 11 个与项目和组织实施有关的过程域**（PA12~PA22）：
  **保证质量、管理配置、管理项目风险、监测和控制技术工程项目、规划技术工程项目、定义组织的系统工程过程、改进组织的系统工程过程、管理产品线的演变、管理系统工程支持环境、提供不断更新的技能和知识、与供应商的协调**。
  > 记法：域维共 **22 个过程域** = 11 个**安全工程过程域**（E1）+ 11 个**项目/组织过程域**（E2）；教材重点考的是前 11 个
- [ ] **E3 · 能力维：公共特性（5 个级别）** ⭕ 必背（结构 + 数量）
  **通用实施（Generic Practices，GP）由被称为「公共特性」的逻辑域组成**。公共特性**分为 5 个级别，依次表示增强的组织能力**。
  - 与域维的基本实施不同：**能力维的通用实施按成熟性排序**，因此**高级别的通用实施位于能力维的高端**
  > 记法：能力维 = **公共特性 = 5 级**；「按成熟性排序、高级别在高处」
- [ ] **E4 · 5 级能力级别** ⭕ 必背（五级 + 高频）
  能力级别代表**工程组织的成熟度级别的 5 级模型**：
  | 级别 | 名称 | 公共特性（重点） |
  |---|---|---|
  | **Level 1** | **非正规实施级** | **执行基本实施** |
  | **Level 2** | **规划和跟踪级** | 规划执行、规范化执行、验证执行、跟踪执行 |
  | **Level 3** | **充分定义级** | 定义标准化过程、执行已定义的过程、协调安全实施 |
  | **Level 4** | **量化控制级** | 建立可测度的质量目标、对执行情况实施客观管理 |
  | **Level 5** | **持续改进级** | 改进组织能力、改进过程的效能 |
  > 记法：**「非 · 规 · 充 · 量 · 持」**（非正规实施 → 规划和跟踪 → 充分定义 → 量化控制 → 持续改进）
  > ⚠️ 高频陷阱：L2 叫「**规划和跟踪级**」、L3 叫「**充分定义级**」——别与软件 CMM 的 L3「已定义级」、L4「量化管理级」等名称混

### 模块 F ｜ 只通读（了解即可，不做挖空）

## 二、自检题（先做，再看答案）

<details>
<summary>1. 信息系统由哪两个部分组成？信息系统工程又由哪两个部分组成？</summary>

信息系统 = **业务应用信息系统** + **信息安全系统**；信息系统工程 = **业务应用信息系统工程** + **信息安全系统工程**（两个工程是「独立且不可分割」的）。
</details>

<details>
<summary>2. 教材特别强调本节讲的是「信息安全系统工程」，为什么不叫「信息系统安全工程」？</summary>

因为「信息系统安全工程」的字面会**误解为「安全地建设一个信息系统」**，从而忽略信息系统中的信息安全问题（可能建成一个没有信息安全子系统的信息系统）。而「信息安全系统工程」明白无误地确定了：这个工程就是**建设一个信息安全系统**。
</details>

<details>
<summary>3. 信息安全空间的三维坐标分别是什么？五大属性是哪五个？</summary>

三维：**X 轴 = 安全机制、Y 轴 = OSI 网络参考模型、Z 轴 = 安全服务**。五大属性：**认证、权限、完整、加密、不可否认**。
</details>

<details>
<summary>4. 安全机制包含哪 9 项？安全服务、安全技术各包含哪些？</summary>

- 安全机制 9 项：**基础设施实体安全、平台安全、数据安全、通信安全、应用安全、运行安全、管理安全、授权和审计安全、安全防范体系**
- 安全服务 6 项：**对等实体认证、数据保密、数据完整性、数据源点认证、禁止否认、犯罪证据提供**
- 安全技术 6 项：**加密、数字签名技术、访问控制、数据完整性、认证、数据挖掘**
</details>

<details>
<summary>5. WPDRRC 指的是哪六个环节？组织安全防范体系的核心是什么？</summary>

WPDRRC = **预警(Warn) / 保护(Protect) / 检测(Detect) / 反应(Response) / 恢复(Recover) / 反击(Counter-attack)**。安全防范体系的核心 = **实现组织信息安全资源的综合管理，即 EISRM**。
</details>

<details>
<summary>6. 工程基础涉及哪 8 类相关工程？</summary>

**硬件工程、软件工程、通信及网络工程、数据存储与灾备工程、系统工程、测试工程、密码工程、组织信息化工程**。
</details>

<details>
<summary>7. ISSE-CMM 是什么？主要适用于哪三类组织？</summary>

**信息安全系统工程能力成熟度模型**，是**信息安全系统工程实施的度量标准**，适用于 **工程组织、获取组织、评估组织**。
</details>

<details>
<summary>8. ISSE 过程由哪三个部分组成？「有害事件」由哪三部分组成？</summary>

三个过程：**工程过程、风险过程、保证过程**。有害事件由 **威胁、脆弱性和影响** 三个部分组成（风险过程的核心）。
</details>

<details>
<summary>9. ISSE-CMM 体系结构采用几维设计？两维分别是什么？</summary>

**两维设计**：**域（Domain）/ 安全工程过程域** 与 **能力（Capability）/ 公共特性**。域维管「做什么」（过程域），能力维管「做得多好」（公共特性 / 级别）。
</details>

<details>
<summary>10. 域维包含 11 个安全工程过程域，请说出至少 6 个；域维一共多少个过程域？</summary>

11 个安全工程过程域：**实施安全控制 / 评估影响 / 评估安全风险 / 评估威胁 / 评估脆弱性 / 建立保证论据 / 协调安全 / 监控安全态 / 提供安全输入 / 确定安全需求 / 验证和证实安全**。域维共 **22 个过程域**（11 个安全工程过程域 + 11 个与项目和组织实施有关的过程域）。
</details>

<details>
<summary>11. ISSE-CMM 的 5 级能力级别分别叫什么？</summary>

**非正规实施级（L1）→ 规划和跟踪级（L2）→ 充分定义级（L3）→ 量化控制级（L4）→ 持续改进级（L5）**（口诀「非规充量持」）。
</details>

<details>
<summary>12. 「能力维的通用实施按什么排序？高级别位于哪里？」</summary>

能力维的通用实施**按其成熟性排序**，因此**高级别的通用实施位于能力维的高端**（与域维的基本实施不同，基本实施无高低排序）。
</details>
