5.4.1 工程概述
1信息安全系统工程的定义、由来与两组术语
  • 由来：由业务应用信息系统或操作系统 / 数据库系统 / 网络管理系统来解决安全问题已不能满足需要 → 不得不建立独立的信息安全系统
  • 信息安全系统工程就是要建造一个信息安全系统，它是整个信息系统工程的一部分，最好与业务应用信息系统工程同步进行
  • 两组术语：信息系统 = 业务应用信息系统 + 信息安全系统；信息系统工程 = 业务应用信息系统工程 + 信息安全系统工程（两个工程独立且不可分割）
  • 信息安全系统服务于业务应用信息系统、密不可分，但二者的功能 / 操作流程 / 管理方式 / 人员要求 / 技术领域完全不同、不能混为一谈
记法：上面一对是「系统」、下面一对是「工程」——信息系统（业+安）/ 信息系统工程（业工+安工），别串行
2四个关键术语 + 术语澄清
  • 业务应用信息系统：支撑业务运营的计算机应用信息系统（如银行柜台业务信息系统、国税征收信息系统）
  • 业务应用信息系统工程：为建好业务应用信息系统所实施的工程，一般称为「信息系统集成项目工程」
  • 信息安全系统工程：为建好信息安全系统所实施的工程；作为信息系统工程的一个子集，其安全体系和策略必须遵从系统工程的一般性原则和规律
  • 术语澄清：讲的是信息安全系统工程，不是「信息系统安全工程」——后者字面会误解为「安全地建设一个信息系统」，从而忽略信息系统的信息安全问题
⚠️ 题干强调「建一个信息安全系统」→ 信息安全系统工程；强调「把信息系统建安全」是错误理解方向
5.4.2 安全系统
3信息安全系统定位 + 安全空间三维五属性
  • 信息安全保障系统一般简称为信息安全系统，是「信息系统」的一个部分，用于保证「业务应用信息系统」正常运营；它是客观的、独立于业务应用信息系统而存在的信息系统
  • 安全空间三维：X 轴 = 安全机制、Y 轴 = OSI 网络参考模型、Z 轴 = 安全服务
  • 五大属性（「安全空间」五要素）：认证、权限、完整、加密、不可否认
🚩 三维是「机制 / OSI / 服务」，不是「机制 / 技术 / 服务」；五属性口诀「认权完加不可否认」
4安全机制 9 项 + 三项组成
  • 安全机制 9 项：基础设施实体安全、平台安全、数据安全、通信安全、应用安全、运行安全、管理安全、授权和审计安全、安全防范体系
  • 平台安全：操作系统 / 网络基础设施 / 通用基础应用程序的漏洞检测与修复、网络安全产品部署
  • 数据安全：介质与载体安全保护、数据访问控制、数据完整性、数据可用性、数据监控和审计、数据存储与备份安全
  • 通信安全：通信线路与网络基础设施安全性测试与优化、安装网络加密设施、设置通信加密软件、设置身份鉴别机制、设置并测试安全通道、测试各项网络协议运行漏洞
「漏洞检测与修复」→ 平台安全；「介质与载体 / 备份」→ 数据安全；「加密设施 / 安全通道」→ 通信安全
5应用 / 运行安全 + 授权审计 + 安全防范体系
  • 应用安全：业务软件程序安全性测试（Bug 分析）、防抵赖测试、访问控制验证测试、身份鉴别检测、备份与恢复机制检查、数据唯一性与一致性及防冲突检测、保密性 / 可靠性 / 可用性测试
  • 运行安全：应急处置机制和配套服务、网络系统安全性监测、网络安全产品运行监测、定期检查和评估、系统升级和补丁提供、跟踪最新安全漏洞及通报、灾难恢复机制与预防、系统改造管理、网络安全专业技术咨询服务
  • 授权和审计安全：授权安全 = 提供权限管理和授权服务，实现用户身份到应用授权的映射，提供与具体应用开发和管理无关的访问控制机制
  • 安全防范体系：核心 = 实现组织信息安全资源的综合管理，即 EISRM；六项能力构成 WPDRRC = 预警(Warn)、保护(Protect)、检测(Detect)、反应(Response)、恢复(Recover)、反击(Counter-attack)
「业务软件 / 防抵赖」→ 应用安全；「应急处置 / 补丁 / 灾难恢复」→ 运行安全；WPDRRC = 警保检应恢反
6安全服务 6 项 + 安全技术 6 项
  • 安全服务 6 项：对等实体认证服务、数据保密服务、数据完整性服务、数据源点认证服务、禁止否认服务、犯罪证据提供服务
  • 对等实体认证服务：两个开放系统同等层实体建立链接或传输数据时，确认对方合法性、真实性以防假冒；数据源点认证服务：确保数据发自真正的源点（两者别混）
  • 禁止否认服务：防止发送方否认发送、接收方否认收到或伪造接收；由「不得否认发送」「不得否认接收」两种组成
  • 安全技术 6 项：加密、数字签名技术、访问控制、数据完整性、认证、数据挖掘
🚩 三组数量别对调：安全机制 9 / 安全服务 6 / 安全技术 6 / 五大属性 5；安全技术含「数据挖掘」这一项别漏
5.4.3 工程基础
7工程基础 8 类相关工程 + 协调 + 管理规范 12 项
  • 信息安全系统建设在 OSI 网络参考模型各个层面进行，离不开 8 类相关工程：硬件工程、软件工程、通信及网络工程、数据存储与灾备工程、系统工程、测试工程、密码工程、组织信息化工程
  • 工程协调：安全策略由组织和组织的客户与服务对象、集成商、安全产品开发者、密码研制单位、独立评估者和其他相关组织共同协商建立→ ISSE 必须与其他外部实体协调，因此比其他工程更复杂
  • 安全管理规范 12 项：物理安全、计算机安全、网络安全、通信安全、输入/输出产品的安全、操作系统安全、数据库系统安全、数据安全、信息审计安全、人员安全、管理安全、辐射安全
8 类记法「硬软通存系测密组」；12 项注意含「辐射安全」
5.4.4 工程体系架构
8ISSE-CMM 基础 + ISSE 过程三部分
  • ISSE-CMM = 信息安全系统工程能力成熟度模型，是信息安全系统工程实施的度量标准，主要适用于 工程组织、获取组织、评估组织（3 类）
  • ISSE 过程：目标是提供一个框架，每个工程项目都可以对这个框架进行裁剪以符合自己特定的需求
  • 三部分：工程过程（含概念 / 设计 / 实现 / 测试 / 部署 / 运行 / 维护 / 退出的完整过程，与其他工程合作识别安全需求、创建解决方案）· 风险过程（主要目标是降低信息系统运行的风险）· 保证过程（安全需求得到满足的可信程度）
⚠️ 它是「信息安全系统工程」CMM，别与软件 CMM / 国内 CSMM（5.1.6）混；三过程口诀「工险保」
9工程过程 / 风险过程 / 保证过程
  • 工程过程：八阶段 = 概念 → 设计 → 实现 → 测试 → 部署 → 运行 → 维护 → 退出（覆盖全生命周期的完整过程）
  • 风险过程：一个有害事件由 威胁、脆弱性和影响 三个部分组成；流程 = 识别三要素 → 评估风险并优先级排序 → 建立风险承受级别 → 实施安全措施减轻风险 → 接受残留风险
  • 保证过程：通过证据构建保证论据，确保安全措施按需求运行（来自措施的正确性和有效性）
🚩 有害事件三组成 = 威胁 + 脆弱性 + 影响（不是「风险+威胁+脆弱性」）；「可信程度 / 保证论据」→ 保证过程
10ISSE-CMM 体系结构两维设计
  • ISSE-CMM 的体系结构可在整个信息安全系统工程范围内决定信息安全工程组织的成熟性；目标是落实安全策略，从管理和制度化方面突出信息安全工程的基本特征
  • 采用两维设计：一维是 域（Domain），另一维是 能力（Capability）
  • 域维 / 安全工程过程域：汇集定义 ISSE 的所有实施活动（称为过程域，即「做什么」）
  • 能力维 / 公共特性：代表组织能力（过程管理能力 + 制度化能力，即「做得多好」）
域维管「做什么」（过程域），能力维管「做得多好」（公共特性 / 级别）
11域维：11 个安全工程过程域 PA01~PA11
  • ISSE 包括 6 个基本实施，被组织成 11 个信息安全工程过程域：
  • PA01 实施安全控制 · PA02 评估影响 · PA03 评估安全风险 · PA04 评估威胁 · PA05 评估脆弱性 · PA06 建立保证论据 · PA07 协调安全 · PA08 监控安全态 · PA09 提供安全输入 · PA10 确定安全需求 · PA11 验证和证实安全
  • ISSE-CMM 还包括 11 个与项目和组织实施有关的过程域（PA12~PA22）：保证质量、管理配置、管理项目风险、监测和控制技术工程项目、规划技术工程项目、定义组织的系统工程过程、改进组织的系统工程过程、管理产品线的演变、管理系统工程支持环境、提供不断更新的技能和知识、与供应商的协调
  • 域维合计 = 22 个过程域（11 个安全工程过程域 + 11 个项目 / 组织过程域）
🚩 评估三兄弟顺序 = 影响 → 安全风险 → 威胁 → 脆弱性（教材就是这么排，别背串）；域维共 22 个过程域
12公共特性 5 级能力级别
  • 通用实施（GP）由被称为「公共特性」的逻辑域组成；公共特性分为 5 个级别，依次表示增强的组织能力；能力维的通用实施按成熟性排序，高级别位于能力维的高端
  • Level 1 非正规实施级：执行基本实施
  • Level 2 规划和跟踪级：规划执行、规范化执行、验证执行、跟踪执行
  • Level 3 充分定义级：定义标准化过程、执行已定义的过程、协调安全实施
  • Level 4 量化控制级：建立可测度的质量目标、对执行情况实施客观管理
  • Level 5 持续改进级：改进组织能力、改进过程的效能
🚩 五级口诀「非规充量持」；L2 = 规划和跟踪级、L3 = 充分定义级——别套用软件 CMM 的「已定义级 / 量化管理级」名称
总结区 本节本质 + 考点地图
本节本质：安全工程 = 把「业务应用信息系统」之外的独立信息安全系统建起来，四小节一条线（工程概述 → 安全系统 → 工程基础 → 工程体系架构），上午 1~2 题，主流题型是数量型 + 分类配对 + 模型结构——记住三组数量、五级名称、两维设计就是分。
考点地图（按考频排序）：① ISSE-CMM 两维 + 11 个安全工程过程域（PA01~PA11）→ ② 安全空间三维（机制 / OSI / 服务）与五属性 → ③ 安全机制 9 / 安全服务 6 / 安全技术 6 三组数量 → ④ ISSE 过程三部分 + 有害事件三组成 → ⑤ 公共特性 5 级能力级别「非规充量持」→ ⑥ 两组术语（信息系统 / 信息系统工程）→ ⑦ 工程基础 8 类相关工程 → ⑧ 术语澄清（信息安全系统工程 ≠ 信息系统安全工程）→ ⑨ WPDRRC 六环节 + EISRM → ⑩ 安全管理规范 12 项。
⚠️ 口径陷阱：①讲的是「信息安全系统工程」（ISSE）不是「信息系统安全工程」；②信息系统工程 = 业务应用信息系统工程 + 信息安全系统工程（独立且不可分割）；③安全空间三维 = 机制 / OSI / 服务，五属性 = 认证 / 权限 / 完整 / 加密 / 不可否认；④安全机制 9 项、安全服务 6 项、安全技术 6 项（含数据挖掘）三组数量别对调；⑤WPDRRC = 警保检应恢反，核心是 EISRM；⑥工程基础 8 类相关工程（含密码工程、组织信息化工程）；⑦ISSE-CMM 适用工程 / 获取 / 评估三类组织；⑧ISSE 过程 = 工程 / 风险 / 保证；⑨有害事件 = 威胁 + 脆弱性 + 影响；⑩域维 22 过程域（安全工程 11 个 PA01~PA11 + 项目组织 11 个）；⑪公共特性 5 级「非规充量持」，高级别在能力维高端。
