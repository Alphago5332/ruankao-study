一、必背清单

模块 A ｜ 数据建模（5.2.1）

数据工程的主要研究内容包括数据建模、数据标准化、数据运维、数据开发利用和数据安全等理论和技术。

记法：五件套「建 · 标 · 运 · 开 · 全」——即本节五个小节的标题序列，小节目录本身就是答案

根据模型的应用目的不同，可以将数据模型划分为三类：概念模型、逻辑模型和物理模型。

• 概念模型也称信息模型，是按用户的观点来对数据和信息建模——把现实世界的客观对象抽象为某种信息结构，不依赖于具体的计算机系统，也不对应某个具体的 DBMS，是概念级别的模型
• 概念模型基本元素：实体、属性、域、键、关联
高频陷阱：别称「信息模型」；关键词「按用户观点」「不依赖 DBMS」→ 概念模型

逻辑模型是在概念模型的基础上确定模型的数据结构。目前主要的数据结构有：层次模型、网状模型、关系模型、面向对象模型和对象关系模型。其中，关系模型成为目前最重要的一种逻辑数据模型。

• 关系数据模型的数据操作主要包括查询、插入、删除和更新数据，这些操作必须满足关系的完整性约束条件
• 关系的完整性约束包括三大类型：实体完整性、参照完整性和用户定义的完整性
记法：逻辑五结构「层网关对对象关系」；约束三件「实参用」——「实」体完整「参」照完整「用」户定义

物理数据模型是在逻辑模型的基础上，考虑各种具体的技术实现因素，进行数据库体系结构设计，真正实现数据在数据库中的存放。

• 物理模型的基本元素包括表、字段、视图、索引、存储过程、触发器等（其中表、字段、视图与逻辑模型基本元素有一定对应关系）
关键词「考虑具体技术实现因素」「真正实现存放」→ 物理模型；六元素「表字视索存触」

数据建模过程包括数据需求分析、概念模型设计、逻辑模型设计和物理模型设计等过程：

步骤产出 / 任务
数据需求分析从用户需求出发 → 数据流图（DFD）
概念模型设计确定实体和数据及其关联 → E-R 图
逻辑模型设计把概念模型转换为 关系模式
物理模型设计针对具体 DBMS：命名、确定字段类型、编写必要的存储过程与触发器等
高频配对：E-R 图属概念模型设计（不是逻辑！）、关系模式属逻辑模型设计；「针对具体 DBMS」→ 物理模型设计

模块 B ｜ 数据标准化（5.2.2）

数据标准化是实现数据共享的基础。数据标准化的主要内容包括元数据标准化、数据元标准化、数据模式标准化、数据分类与编码标准化和数据标准化管理。

记法：地位一句话「共享的基础」；五内容顺口溜「元元模分管」（元数据 / 数据元 / 数据模式 / 分类与编码 / 标准化管理）

元数据最简单的定义是：元数据是关于数据的数据（Data About Data）。其实质是用于描述信息资源或数据的内容、覆盖范围、质量、管理方式、数据的所有者、数据的提供方式等有关的信息，是对信息资源的一种结构化描述。

关键词「关于数据的数据」——出现即选/即填

数据元是数据库、文件和数据交换的基本数据单元。数据库或文件由记录或元组等组成，而记录或元组则由数据元组成。数据元一般来说由三部分组成：① 对象　② 特性　③ 表示。

记法：「对特表」；对比记忆：元数据 = 关于数据的数据，数据元 = 基本数据单元——两个词别互串

常用的数据元提取方法有两种：自上而下（Top-Down）提取法和自下而上（Down-Top）提取法。

• 新建系统的数据元提取，一般适用「自上而下」提取法
• 已建系统的数据元提取，一般适用「自下而上」提取法
高频陷阱：新上旧下——「新建系统 → 自上而下」年年考年年错

数据模式是数据的概念、组成、结构和相互关系的总称。数据模式的描述方式主要有图描述方法和数据字典方法：

描述方式常用工具 / 内容描述对象
图描述方法IDEFIX 方法、UML 图数据集中的实体和实体之间的相互关系
数据字典方法摘要信息形式模型中的数据集、单个实体、属性的摘要信息
高频配对：看到「IDEFIX / UML」→ 描述实体及相互关系；看到「摘要信息」→ 数据字典。数据模式标准化的本质：规范化处理，减少冗余

数据分类有分类对象和分类依据两个要素。数据分类与编码的作用主要包括：

  1. 用于信息系统的共享和互操作
  2. 统一数据的表示法
  3. 提高信息处理效率
• 编码的意义：确立代码与事物或概念之间的一一对应关系，保证数据的准确性和相容性，为信息集成与资源共享提供良好基础

数据标准化阶段的具体过程包括四个阶段：确定数据需求 → 制定数据标准 → 批准数据标准 → 实施数据标准。

• 确定数据需求：产生数据需求及相关元数据、域值等文件
• 制定数据标准：现有标准不满足需求时，可建议制定新标准、修改或封存已有标准
• 批准数据标准：数据管理机构审查，一经批准将扩充或修改数据模型
• 实施数据标准：在各信息系统中实施和改进已批准的数据标准
记法：「需批施」——需求 → 制定 → 批准 → 实施

模块 C ｜ 数据运维（5.2.3）

数据存储是根据不同的应用环境，通过采取合理、安全、有效的方式将数据保存到物理介质上，并能保证对数据实施有效的访问。

• 存储介质是数据存储的载体和基础，类型主要有磁带、光盘和磁盘三种（并非越贵越好、越先进越好，要按应用环境合理选择）
• 存储管理的主要内容：资源调度管理、存储资源管理、负载均衡管理、安全管理四项

数据备份是为防止用户操作失误、系统故障等意外导致的数据丢失，将整个应用系统或一部分关键数据复制到其他存储介质上的过程。

分类内容
备份结构（四种）DAS 备份结构、基于 LAN 的备份结构、LAN-FREE 备份结构、SERVER-FREE 备份结构
备份策略（三种）完全备份、差分备份、增量备份
记法：策略三件「完差增」；结构四件按「备份流量走不走局域网」递进：DAS 直连 → LAN 走网 → LAN-FREE 走存储网 → SERVER-FREE 不占服务器

根据容灾系统保护对象的不同，容灾系统分为应用容灾和数据容灾两类：

• 应用容灾：克服灾难对系统的影响，保证应用服务的完整、可靠和安全，使用户在任何情况下都能得到正常服务
• 数据容灾：关注保证用户数据的高可用性，灾难发生时数据尽量少丢失或不丢失
• 数据容灾是应用容灾的子集，也是应用容灾最根本的基础（「得数据者得天下」）
• 容灾是一个工程，而不仅仅是技术
• 数据备份是数据容灾的基础；数据备份是数据高可用的最后一道防线，目的是系统崩溃时快速恢复数据
判断题三连：备份≠容灾 ✗（备份只是基础）；容灾=技术 ✗（是工程）；「最后一道防线」=数据备份 ✓

从技术上看，衡量容灾系统有两个主要指标：

• RPO（Recovery Point Objective）：代表当灾难发生时允许丢失的数据量
• RTO（Recovery Time Objective）：代表系统恢复的时间
记法：P=Point=丢点数据，T=Time=花点时间。「允许丢失的数据量」→ RPO；「恢复的时间」→ RTO。两个词年年对调

数据质量可以通过数据质量元素来描述，数据质量元素分为数据质量定量元素和数据质量非定量元素。

数据质量评价方法分为两种：

方法判别关键词
直接评价法将数据与内部或外部的参照信息（如理论值）进行对比，确定数据质量
间接评价法利用数据相关信息（如对数据源、采集方法等的描述）推断或评估数据质量
记法：「直比间推」——直接=拿参照比，间接=靠信息推

数据产品的质量控制分成前期控制和后期控制两大部分：

• 前期控制：数据录入前的质量控制 + 数据录入过程中的实时质量控制
• 后期控制：数据录入完成后的后处理质量控制与评价
• 依据建库流程可进一步分为：前期控制、过程控制、系统检测、精度评价

凡是有助于提高数据质量的处理过程，都可以认为是数据清理。数据清理主要包括数据分析、数据检测和数据修正三个步骤：

  1. 数据分析：从数据中发现控制数据的一般规则（字段域、业务规则等），定义清理规则并选择合适的清理算法
  2. 数据检测：根据预定义的清理规则及相关算法，检测数据是否正确、记录是否重复
  3. 数据修正：手工或自动地修正检测到的错误数据或重复记录
记法：析 → 检 → 修；数据清理又称数据清洗

模块 D ｜ 数据开发利用（5.2.4）

数据集成就是将驻留在不同数据源中的数据进行整合，向用户提供统一的数据视图（全局模式），使得用户能以透明的方式访问数据。

• 数据集成的目标：充分利用已有数据，在尽量保持其自治性的前提下，维护数据源整体上的一致性，提高数据共享利用效率
• 实现数据集成的系统称为数据集成系统，为用户提供统一的数据源访问接口
关键词：「统一的数据视图 / 全局模式」「透明访问」「保持自治性」

数据挖掘是指从大量的、不完全的、有噪声的、模糊的、随机的实际数据中，提取隐含在其中的、人们不知道的、却是潜在有用的知识——目标是发现隐藏于数据之后的规律或数据间的关系，服务于决策。

数据挖掘常见的主要任务包括：数据总结、关联分析、分类和预测、聚类分析和孤立点分析。

记法：五任务「总关分聚孤」；「购物篮分析」→ 关联分析；「啤酒尿布」→ 关联分析的经典梗

数据挖掘流程一般包括确定分析对象、数据准备、数据挖掘、结果评估与结果应用五个阶段。

记法：「定备挖评用」——对象 → 准备 → 挖掘 → 评估 → 应用

数据服务主要包括：数据目录服务、数据查询与浏览及下载服务、数据分发服务。

• 数据目录服务：建立目录方便检索服务
• 数据查询与浏览及下载服务：网上数据共享服务的重要方式，用户使用数据的方式有查询和下载两种
• 数据分发服务：数据的生产者通过各种方式将数据传送到用户的过程

可视化技术是指将抽象的事物或过程变成图形图像的表示方法。可视化可分为七类：

一维数据可视化、二维数据可视化、三维数据可视化、多维数据可视化、时态数据可视化、层次数据可视化和网络数据可视化。

记法：三维打底（一二三维）+ 多维 + 时态 + 层次 + 网络＝7；填空常挖「时态 / 层次 / 网络」后三样

信息检索的主要方法包括四种：全文检索、字段检索、基于内容的多媒体检索、数据挖掘。

信息检索的常用技术包括：布尔逻辑检索技术、截词检索技术、临近检索技术、限定字段检索技术、限制检索技术等。

⚠️ 两个坑：① 四方法里有「数据挖掘」——不是出题人手滑，是教材原口径；② 「临近检索」是临近（proximity），别记成「近似检索」

模块 E ｜ 数据库安全（5.2.5）

数据库安全是指保护数据库，防止不合法的使用所造成的数据泄露、更改或破坏。

数据库安全对策（十条）中的判别关键词：

对策关键词 / 要点
防止非法的数据访问数据库安全关键的需求之一；DBMS 根据用户或应用的授权检查访问请求
防止推导用户通过授权访问的数据经推导得出机密信息（其本身无权访问该机密信息）
保证数据库的完整性保护数据库不受非授权修改及病毒、系统错误导致的存储数据破坏
保证数据的操作完整性并发事务中保证数据的逻辑一致性（并发管理器子系统负责）
保证数据的语义完整性修改数据时保证新值在一定范围内符合逻辑上的完整性（完整性约束描述）
审计和日志有效的威慑和事后追查、分析工具
标识和认证授权、审计等的前提条件，是第一道安全防线
机密数据管理 / 多级保护 / 限界保密性控制 / 按保密级别划分访问权限 / 防止程序间非授权的信息传递
高频判断：「第一道安全防线」=标识和认证；「并发事务中的逻辑一致性」=操作完整性；「事后追查分析」=审计和日志

数据库安全机制包括用户的身份认证、存取控制、数据库加密、数据审计、推理控制等内容。

记法：五机制「身存密审推」；对应记忆——防推导的机制面 = 推理控制，认证的机制面 = 身份认证

二、通读清单（读一遍有印象即可）

一个互连、互通、互操作的开放系统互连环境（OSIE）有四个基本要素：硬件、软件、通信和数据——前三个要素的标准化已成熟，因此数据的标准化（数据元标准化）成为重点。

元数据标准化围绕信息对象展开，构成元数据体系；元数据被定义为提供关于信息资源或数据的一种结构化数据——描述的内容、覆盖范围、质量、管理方式、所有者、提供方式等即其描述维度。

① 描述 → ② 界定业务范围 → ③ 开展业务流程分析与信息建模 → ④ 借助信息模型提取数据元并规范其属性 → ⑤ 对代码型数据元编制值域（代码表）→ ⑥ 与现有国家标准或行业标准协调 → ⑦ 发布实施并建立动态维护管理机制。

① 数据量：数据挖掘所需数据量更大，数据量越大效果越好；② 分析方法：传统分析主要用统计学，数据挖掘综合运用统计、人工智能、可视化等技术；③ 分析侧重：传统分析是回顾型和验证型（分析已发生了什么），数据挖掘是预测型和发现型（预测未来、解释原因）；④ 成熟度：传统分析相当成熟，数据挖掘部分方法仍处于发展阶段。

主要运用计算机图形学和图像处理技术，将数据转换为图形或图像在屏幕上显示并进行交互处理，涉及计算机图形学、图像处理、计算机辅助设计、计算机视觉及人机交互等多个领域。

备份硬件基础：备份服务器、RAID、磁带机等；备份软件：操作系统自带备份工具 + 专业备份软件。

点击核对答案
  1. 数据建模、数据标准化、数据运维、数据开发利用和数据安全——即 5.2.1~5.2.5 五个小节标题本身。
  2. 概念模型别称信息模型；按用户的观点对数据和信息建模；基本元素实体、属性、域、键、关联。
  3. 层次模型、网状模型、关系模型、面向对象模型、对象关系模型；最重要的是关系模型；约束三大类型：实体完整性、参照完整性、用户定义的完整性。
  4. 数据需求分析 → 数据流图；概念模型设计 → E-R 图；逻辑模型设计 → 关系模式；物理模型设计 → 针对具体 DBMS 的命名 / 字段类型 / 存储过程与触发器。
  5. 元数据 = 关于数据的数据（Data About Data）；数据元 = 数据库、文件和数据交换的基本数据单元，由对象、特性、表示三部分组成。
  6. 新建系统 → 自上而下（Top-Down）；已建系统 → 自下而上（Down-Top）。
  7. 图描述（IDEFIX / UML）→ 描述数据集中的实体和实体之间的相互关系；数据字典 → 描述模型中的数据集、单个实体、属性的摘要信息。
  8. 结构四种：DAS / 基于 LAN / LAN-FREE / SERVER-FREE；策略三种：完全备份、差分备份、增量备份。
  9. RPO = 灾难发生时允许丢失的数据量；RTO = 系统恢复的时间。
  10. 数据分析 → 数据检测 → 数据修正。
  11. 五任务：数据总结、关联分析、分类和预测、聚类分析、孤立点分析；五阶段：确定分析对象、数据准备、数据挖掘、结果评估、结果应用。
  12. 五机制：用户的身份认证、存取控制、数据库加密、数据审计、推理控制；「第一道安全防线」= 标识和认证。
