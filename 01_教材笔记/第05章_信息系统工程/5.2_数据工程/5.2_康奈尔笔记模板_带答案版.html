5.2.1 数据建模
1三类数据模型与概念模型
  • 按模型的应用目的不同分三类：概念模型、逻辑模型、物理模型
  • 概念模型也称信息模型：按用户的观点建模，不依赖具体计算机系统、不对应具体 DBMS，是概念级别的模型
  • 概念模型基本元素五件：实体、属性、域、键、关联
「按用户观点」→ 概念模型；「不依赖 DBMS」→ 还是概念模型；别称「信息模型」是填空最爱
2逻辑模型五结构与完整性约束
  • 逻辑模型五种数据结构：层次模型、网状模型、关系模型、面向对象模型、对象关系模型
  • 关系模型是目前最重要的一种逻辑数据模型；数据操作四类：查询、插入、删除、更新（须满足完整性约束）
  • 关系完整性约束三大类型：实体完整性、参照完整性、用户定义的完整性（口诀「实参用」）
⚠️ 逻辑模型是在概念模型基础上确定数据结构——顺序：概念 → 逻辑 → 物理
3物理模型 + 建模过程四步产出
  • 物理模型：在逻辑模型基础上考虑具体的技术实现因素，真正实现数据在数据库中的存放
  • 物理模型基本元素六件：表、字段、视图、索引、存储过程、触发器
  • 建模四步产出配对：数据需求分析 → 数据流图（DFD）；概念模型设计 → E-R 图；逻辑模型设计 → 关系模式；物理模型设计 → 针对具体 DBMS 的命名 / 字段类型 / 存储过程与触发器
高频对调陷阱：E-R 图属概念模型设计、关系模式属逻辑模型设计——「先画 E-R 再转关系模式」
5.2.2 数据标准化
4数据标准化的地位与五大内容
  • 地位一句话：数据标准化是实现数据共享的基础
  • 五大内容：元数据标准化、数据元标准化、数据模式标准化、数据分类与编码标准化、数据标准化管理（口诀「元元模分管」）
OSIE 四要素：硬件、软件、通信、数据——前三者标准化已成熟，数据的标准化是重点（通读 F0）
5元数据 / 数据元 / 提取法
  • 元数据 = 关于数据的数据（Data About Data），是对信息资源的结构化描述
  • 数据元 = 数据库、文件和数据交换的基本数据单元；记录 / 元组由数据元组成
  • 数据元三要素：对象、特性、表示（口诀「对特表」）
  • 提取两法：新建系统 → 自上而下（Top-Down）；已建系统 → 自下而上（Down-Top）（口诀「新上旧下」）
⚠️ 元数据（关于数据的数据）与数据元（基本数据单元）两个词互串是本节第一大坑；「新上旧下」年年考年年错
6数据模式 / 分类编码 / 管理四阶段
  • 数据模式 = 数据的概念、组成、结构和相互关系的总称
  • 两种描述方式配对：图描述（IDEFIX 方法、UML 图）→ 描述实体和实体之间的相互关系；数据字典 → 描述数据集、单个实体、属性的摘要信息
  • 数据分类两要素：分类对象、分类依据；编码三作用：共享和互操作、统一数据表示法、提高信息处理效率
  • 标准化管理四阶段：确定数据需求 → 制定数据标准 → 批准数据标准 → 实施数据标准（口诀「需制批施」）
数据模式标准化的本质：规范化处理、减少冗余；「IDEFIX / UML」出现 → 图描述 → 实体相互关系
5.2.3 数据运维
7数据存储：介质与管理
  • 数据存储：按应用环境以合理、安全、有效的方式将数据保存到物理介质上，并保证有效访问
  • 存储介质三类：磁带、光盘、磁盘（不是越贵越好、越先进越好）
  • 存储管理四内容：资源调度管理、存储资源管理、负载均衡管理、安全管理
介质三件「带盘盘」；管理四件——调度 / 资源 / 均衡 / 安全，别与「安全管理」单件混
8备份四结构三策略 + 容灾两类
  • 备份结构四种：DAS 备份结构、基于 LAN 的备份结构、LAN-FREE 备份结构、SERVER-FREE 备份结构
  • 备份策略三种：完全备份、差分备份、增量备份（口诀「完差增」）
  • 按容灾系统保护对象分两类：应用容灾（保证服务的完整可靠安全）、数据容灾（保证数据高可用、尽量少丢失）
  • 三句判读：数据容灾是应用容灾的子集、也是其最根本的基础；数据备份是数据容灾的基础；数据备份是数据高可用的最后一道防线
  • 容灾是一个工程，而不仅仅是技术
判断题三连：备份 = 容灾？✗（备份只是基础）；容灾 = 技术？✗（是工程）；「最后一道防线」= 数据备份？✓
9RPO / RTO + 质量评价 + 清理三步
  • RPO = 灾难发生时允许丢失的数据量（Point=丢点数据）；RTO = 系统恢复的时间（Time=花点时间）
  • 数据质量元素分两分：定量元素 / 非定量元素
  • 评价两法：直接评价法 = 与内部或外部参照信息（如理论值）对比；间接评价法 = 利用数据相关信息（数据源、采集方法描述）推断或评估（口诀「直比间推」）
  • 质量控制：前期控制（录入前 + 录入过程实时）+ 后期控制（录入完成后的后处理）；建库流程口径：前期控制 / 过程控制 / 系统检测 / 精度评价
  • 数据清理三步骤：数据分析 → 数据检测 → 数据修正（口诀「析检修」）
⚠️ RPO / RTO 对调是本节第二大坑；「参照信息对比」= 直接评价、「推断评估」= 间接评价
5.2.4 数据开发利用
10数据集成：全局模式与透明访问
  • 数据集成：整合不同数据源的数据，向用户提供统一的数据视图（全局模式），以透明的方式访问
  • 目标：充分利用已有数据，在尽量保持自治性的前提下，维护数据源整体上的一致性，提高共享利用效率
  • 实现数据集成的系统 = 数据集成系统，提供统一的数据源访问接口
三个填空词：「统一的数据视图 / 全局模式」「透明」「自治性」——出现即数据集成
11挖掘五任务 / 服务三类 / 可视化七类 / 检索
  • 数据挖掘：从大量的、不完全的、有噪声的、模糊的、随机的数据中提取潜在有用的知识，服务于决策
  • 五任务：数据总结、关联分析、分类和预测、聚类分析、孤立点分析（口诀「总关分聚孤」）
  • 流程五阶段：确定分析对象 → 数据准备 → 数据挖掘 → 结果评估 → 结果应用（口诀「定备挖评用」）
  • 数据服务三类：数据目录服务、数据查询与浏览及下载服务、数据分发服务
  • 可视化七类：一维 / 二维 / 三维 / 多维 / 时态 / 层次 / 网络数据可视化（三维打底 + 多时层网）
  • 信息检索四方法：全文检索、字段检索、基于内容的多媒体检索、数据挖掘；常用技术：布尔逻辑 / 截词 / 临近 / 限定字段 / 限制检索
⚠️ 检索四方法里真的有「数据挖掘」（教材原口径，不是出题错误）；「临近检索」不是「近似检索」；挖掘 vs 传统分析四差异（数据量 / 方法 / 侧重 / 成熟度）在通读 F3
5.2.5 数据库安全
12数据库安全定义 / 机制五项 / 对策要点
  • 定义：保护数据库，防止不合法的使用所造成的数据泄露、更改或破坏
  • 安全机制五项：用户的身份认证、存取控制、数据库加密、数据审计、推理控制（口诀「身存密审推」）
  • 对策判读：标识和认证 = 第一道安全防线（授权、审计的前提）；防止推导 = 用户用授权数据推导出无权访问的机密信息；防止非法的数据访问 = 数据库安全关键的需求之一
  • 完整性三线：数据库完整性 = 防非授权修改与存储破坏；操作完整性 = 并发事务中的逻辑一致性；语义完整性 = 新值在范围内符合逻辑
  • 审计和日志 = 有效的威慑和事后追查、分析工具；限界 = 防止程序间非授权的信息传递
「防推导」的机制面 = 推理控制；三种完整性（库 / 操作 / 语义）判别词：非授权修改 → 库；并发事务 → 操作；新值范围 → 语义
总结区 本节本质 + 考点地图
本节本质：数据工程五小节一条线（建模 → 标准化 → 运维 → 开发利用 → 安全），上午 2~3 题，主流题型是定义挖空 + 数量分类 + 配对辨析——「X 类 / X 种 / X 步 / X 要素」的数字背准就是分。
考点地图（按考频排序）：① RPO vs RTO（对调重灾区）→ ② 数据元三要素 + 提取法「新上旧下」→ ③ 关系完整性约束三类型 → ④ 备份三策略「完差增」+ 备份与容灾关系三句 → ⑤ 数据清理「析检修」→ ⑥ 图描述 vs 数据字典配对 → ⑦ 数据挖掘五任务 + 流程五阶段 → ⑧ 可视化七类 → ⑨ 数据库安全机制五项 + 「第一道防线」→ ⑩ 概念模型别称「信息模型」+ 建模四步产出配对。
⚠️ 口径陷阱：①元数据（关于数据的数据）≠ 数据元（基本数据单元）；②E-R 图属概念模型设计、关系模式属逻辑模型设计；③新建系统=自上而下、已建系统=自下而上；④IDEFIX/UML=图描述=实体相互关系，摘要信息=数据字典；⑤数据备份是数据容灾的基础、是数据高可用的最后一道防线；⑥RPO 丢数据、RTO 恢复时间；⑦清理=分析→检测→修正；⑧信息检索四方法内含数据挖掘；⑨「第一道安全防线」=标识和认证；⑩容灾是工程不只是技术。
