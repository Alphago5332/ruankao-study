> ⚠️ **口径核对（2026-10-09）**：
> - 本节口径由**第 4 版纸质教材手敲整理（CSDN 两个独立版本）+ lufer 笔记 + 阿里云开发者社区重点汇总**多方交叉核对；样章 PDF 不含第 5 章，无法逐字比对
> - **元数据 = 关于数据的数据**；**数据元 = 数据库、文件和数据交换的基本数据单元**（三要素：对象 / 特性 / 表示）——两个相近词互串是本节第一大坑
> - **数据元提取「新上旧下」**：新建系统 → 自上而下（Top-Down）；已建系统 → 自下而上（Down-Top）
> - **图描述（IDEFIX / UML）→ 描述实体和实体之间的相互关系**；**数据字典 → 描述数据集、单个实体、属性的摘要信息**（真题原题式配对，方向别接反）
> - **数据备份是数据容灾的基础**、是**数据高可用的最后一道防线**；**数据容灾是应用容灾的子集**；容灾是一个**工程**而不仅仅是技术
> - **RPO = 允许丢失的数据量；RTO = 系统恢复的时间**（P 丢数据、T 恢复时间），年年对调
> - 备份策略三件的教材用词是「**差分备份**」不是「差异备份」——一字之差即错误项
> - 信息检索的四种方法**包括数据挖掘**（教材原口径，不是出题错误）；常用技术是「**临近检索**」不是「近似检索」
> - **标识和认证 = 第一道安全防线**；防「推导出机密信息」的对策是**防止推导**、对应机制是**推理控制**

## 易混防坑

1. **元数据 ≠ 数据元**：元数据 = 关于数据的数据；数据元 = 基本数据单元（三要素「对特表」）
2. **建模四步产出配对**：**E-R 图属概念模型设计、关系模式属逻辑模型设计**——「先画 E-R 再转关系模式」
3. **提取法「新上旧下」**：新建系统 → 自上而下；已建系统 → 自下而上
4. **图描述 vs 数据字典**：IDEFIX / UML → 实体和实体相互关系；摘要信息 → 数据字典——方向别接反
5. **备份 ≠ 容灾**：备份是容灾的**基础**、是数据高可用的**最后一道防线**；容灾是**工程**不只是技术
6. **RPO 丢数据、RTO 恢复时间**——P=Point 丢点数据、T=Time 花点时间
7. **差分备份**（教材用词）不是「差异备份」——一字之差即错误项
8. **清理三步骤「析检修」**：分析→检测→修正，顺序不能乱
9. **检索四方法含数据挖掘**（教材原口径）；「临近检索」不是「近似检索」
10. **「第一道安全防线」= 标识和认证**；「并发事务逻辑一致」= 操作完整性；「事后追查分析」= 审计和日志——三条判读各归各
11. 本节「关系的完整性约束三类型」（实体/参照/用户定义）≠ 5.2.5 的「三种完整性」（数据库/操作/语义）——两处「三完整」跨小节互串是最大陷阱
12. 旧真题（第 3 版第 3 章同源）可刷「数据工程」部分；**2023 下以后第 5 章真题优先**
