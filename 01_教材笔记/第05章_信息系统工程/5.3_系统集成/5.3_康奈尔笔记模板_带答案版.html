5.3.1 集成基础
1系统集成定义与三内容
  • 系统集成概念专指计算机系统的集成：含计算机硬件平台、网络系统、系统软件、工具软件、应用软件的集成，以及相应咨询、服务和技术支持
  • 三内容：技术环境的集成、数据环境的集成、应用程序的集成（「技·数·应」）
  • 实现手段五平台：硬件平台、网络通信平台、数据库平台、工具平台、应用软件平台
题干出现「专指计算机系统的集成」→ 就是系统集成本身；三内容别漏「应用程序的集成」
2四大原则与判别词
  • 四原则：开放性、结构化、先进性、主流化（「开·结·先·主」）
  • 开放性：系统硬软件平台 / 通信接口 / 软件开发工具 / 网络结构的选择要遵循工业开放标准；只有开放系统才能满足可互操作性、可移植性、可伸缩性
  • 结构化：自顶向下逐层模块化分解（复杂系统设计的最基本方法）
  • 先进性：两层意义 = 目前先进性和未来先进性；建立在技术先进性之上，还表现在系统设计先进性（先进技术的有机集成 / 问题的合理划分 / 应用软件符合认知特点）
  • 主流化：每个产品应属于该产品发展的主流，有可靠技术支持、成熟使用环境、良好升级发展势头
⚠️「工业开放标准」→ 开放性；「自顶向下逐层模块化」→ 结构化；「两层意义 / 目前·未来」→ 先进性
5.3.2 网络集成
3网络集成体系框架七子系统
  • 传输子系统（网络核心，「公路」「血管」）
  • 交换子系统（局域网 / 城域网 / 广域网交换技术）
  • 安全子系统（防火墙、数据加密、访问控制）
  • 网管子系统（监控运行、解决「瓶颈」）
  • 服务器子系统（为工作站提供资源和服务）
  • 网络操作系统（调度管理网络资源，提供统一透明使用手段）
  • 服务子系统（互联网服务、多媒体检索、信息广播、远程计算、事务处理）
⚠️ 高项第 4 版 = 七个；中级第 3 版 = 五大（传输 / 交换 / 网管 / 安全 / 服务）——两卷别混
4传输与交换子系统
  • 传输是网络的核心，是网络信息的「公路」和「血管」；带宽高低体现通信能力与现代化水平
  • 无线介质：无线电波、微波、红外线；有线介质：双绞线、同轴电缆、光纤
  • 交换子系统：按覆盖区域分局域网、城域网、广域网三类交换技术
「公路 / 血管」→ 传输；出现「局域网 / 城域网 / 广域网」→ 交换子系统
5.3.3 数据集成
5数据集成对象、关键与四层次
  • 处理对象：系统中各种异构数据库中的数据；数据仓库技术是数据集成的关键
  • 四层次：基本数据集成、多级视图集成、模式集成、多粒度数据集成（「基·多视·模·多粒」）
「数据仓库技术是数据集成的关键」是填空原句，别答成「数据标准化」「中间件」
6四层次各自要点
  • 基本数据集成：核心是通用标识符问题和数据丢失问题；解法 = 隔离和调和、生成接近实际估计值
  • 多级视图集成：底层（局部模型）→ 中间层（公共模型）→ 高层（综合模型），两级映射
  • 模式集成：解决命名、结构等语义冲突；设计好坏视设计者经验；三等价 = 属性等价、关联等价、类等价（归结为属性等价）
  • 多粒度数据集成：理想模式是自动逐步抽象；数据综合（高精度→低精度大粒度）/ 数据细化（低精度→高精度）
⚠️「局部 / 公共 / 综合」+「两级映射」→ 多级视图集成；「设计取决于设计者经验」→ 模式集成
7异构数据集成方法（★口径陷阱）
  • 教材原文：归纳起来主要有两种——过程式方法和声明式方法；另一类方法是利用中间件集成异构数据库
  • 过程式：点对点（Ad-hoc）设计，用 Wrapper 封装数据源 + Mediator 合并一致化数据
  • 声明式：用一套合适的语言建模，构建统一数据表示，通过推理机制存取数据源
  • 中间件：不改变原始数据的存储和管理方式；位于异构数据库系统（数据层）与应用程序（应用层）之间
🚩 别答「三种方法」——教材把中间件定位为「另一类」（不在「两种」之内），这是本节最容易被教辅带偏的点
5.3.4 软件集成
8五大构件标准 · CORBA · COM
  • 五大标准：CORBA、COM、DCOM 与 COM+、.NET、J2EE
  • CORBA（公共对象请求代理结构）：由对象管理组织（OMG）制定，1989 年建立；可自动匹配对象登记、定位、激活多路请求、组帧和错误控制、参数编排 / 反编排、操作分配等公共网络任务
  • COM：对象是二进制代码对象（DLL 或 EXE），直接注册在 Windows 系统库中，由系统平台直接支持
  • COM 的软件集成五特征：面向对象、客户机/服务器、语言无关性、进程透明性、可重复性（「对·客·语·进·可」）
「OMG 制定」→ CORBA；「二进制代码对象 + 系统库」→ COM；五特征顺序不用背，能认全即可
9DCOM/COM+ · .NET · J2EE
  • DCOM 与 COM+：作为 COM 的扩展，针对分布环境提供位置透明性、网络安全性、跨平台调用等新特性
  • COM+ 把 COM 组件软件提升到应用层而不再是底层软件结构——与操作系统结合更紧密
  • .NET：基于一组开放的互联网协议；涉及技术 VB、C++、C#、JScript、ASP.NET、ADO.NET
  • J2EE：Java 开发组织级应用事实上的工业标准；体系结构四层 = 客户端层、服务器端组件层、EJB、信息系统层；涉及技术 EJB、Java Servlets API、JSP 和 XML
⚠️ 最易混：C# / VB / ASP.NET → .NET；EJB / Servlet / JSP → J2EE。「提升到应用层」→ COM+
5.3.5 应用集成
10语法·语义·语用 + EAI 三要求 + 三组件
  • 网络集成解决语法的问题、数据集成解决语义的问题、应用集成解决语用的问题；应用集成在最上层，解决应用的互操作性
  • EAI = 将独立的软件应用连接起来实现协同工作；技术要求三项 = 应用间的互操作性、分布式环境中应用的可移植性、系统中应用分布的透明性
  • 可协调连接各种应用的组件三件 = 应用编程接口（API）、事件驱动型操作、数据映射
🚩 三句一一对应，考排序 / 配对——「语用」属于应用集成，别配给数据集成
11EAI 四层次 + 黑白盒 + 实现技术
  • 表示集成（界面集成）：黑盒集成，最原始最浅层次，用屏幕截取技术、输入模拟技术
  • 数据集成：白盒集成（唯一白盒），集成点在中间件；先标识并编成目录、确定元数据模型
  • 控制集成（功能集成 / 应用集成）：黑盒集成，在业务逻辑层集成；借助 RPC/RMI、面向消息的中间件、分布式对象技术、事务处理监控器，常用公开 API
  • 业务流程集成（过程集成）：超越数据和系统，由一系列基于标准的、统一数据格式的工作流组成
⚠️ 黑白盒配对是高频：「在业务逻辑层上进行黑盒集成」→ 控制集成；「白盒」只属于数据集成
12EDA 事件驱动的企业应用集成
  • 事件驱动架构（EDA）：事件触发消息在独立的、非耦合的模块之间传递（模块之间不需要知道对方）
  • 机制：事件源发送消息到中间件或消息代理，订阅者订阅该消息
  • 因采用发布 / 订阅方式，一个事件可以传送给多个订阅者；EDA 允许企业通过事件管理标识和响应事件
「发布 / 订阅」「事件源→消息代理→订阅者」「一事件多订阅者」三条同时出现 → EDA
总结区 本节本质 + 考点地图
本节本质：系统集成 = 把「硬软件 + 网络 + 数据 + 应用」拧成一个整体，五小节一条线（集成基础 → 网络集成 → 数据集成 → 软件集成 → 应用集成），上午 1~2 题，主流题型是原则辨析 + 层次配对 + 「X 类 / X 种」数量型——记住层次名称与黑白盒配对就是分。
考点地图（按考频排序）：① EAI 四层次与黑白盒配对（数据集成唯一白盒）→ ② 语法·语义·语用三对应 → ③ 异构数据集成「两种 + 另一类」→ ④ 系统集成四大原则判别词 → ⑤ 数据集成四层次 + 多级视图两级映射 → ⑥ 五大构件标准 + COM 五特征 → ⑦ .NET / J2EE 涉及技术配对 → ⑧ 网络集成七子系统 → ⑨ EAI 三要求 + 可连接组件三件 → ⑩ EDA 发布 / 订阅机制。
⚠️ 口径陷阱：①系统集成三内容 = 技术环境 / 数据环境 / 应用程序；②开放性 = 工业开放标准，三「可」= 互操作 / 移植 / 伸缩；③先进性是「目前 + 未来」两层意义；④异构数据集成教材说「两种」（过程式 / 声明式），中间件是「另一类」不是第三种；⑤「数据仓库技术是数据集成的关键」；⑥多级视图 = 局部→公共→综合（两级映射）；⑦COM = 二进制代码对象；⑧.NET 是 C#/VB/ASP.NET，J2EE 是 EJB/Servlet/JSP；⑨数据集成是唯一白盒集成；⑩网络集成解决语法、数据集成解决语义、应用集成解决语用。
