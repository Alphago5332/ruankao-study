## 一、必背清单

### 模块 A ｜ 集成基础（5.3.1）

- [ ] **A0 · 系统集成的定义与三内容** ⭕ 必背（总起挖空）
  系统集成概念**专指计算机系统的集成**，包括计算机硬件平台、网络系统、系统软件、工具软件、应用软件的集成，围绕这些系统的相应咨询、服务和技术支持。
  - **系统集成的内容**包括**技术环境的集成、数据环境的集成和应用程序的集成**
  - 实现手段：通过**硬件平台、网络通信平台、数据库平台、工具平台、应用软件平台**将各类资源有机、高效地集成到一起，形成一个完整的工作台面
  > 高频：题干出现「**专指计算机系统的集成**」→ 系统集成；三内容「**技 · 数 · 应**」；五平台「硬 · 网 · 库 · 工 · 用」
- [ ] **A1 · 系统集成四大原则总览** ⭕ 必背（分类列举）
  在技术上需要遵循的基本原则包括：**开放性、结构化、先进性和主流化**。
  > 记法：**「开 · 结 · 先 · 主」**——开放（跟谁都能连）· 结构（怎么搭才稳）· 先进（技术够不够新）· 主流（产品会不会被淘汰）
- [ ] **A2 · 开放性原则** ⭕ 必背（定义配对）
  **系统硬软件平台、通信接口、软件开发工具、网络结构的选择要遵循工业开放标准**，这是关系到**系统生命周期长短**的重要问题。
  - 一个集成的信息系统必然是一个开放的信息系统；只有开放的系统才能满足**可互操作性、可移植性以及可伸缩性**的要求，才可能与另一个标准兼容的系统实现「**无缝**」的互操作
  > 判别词：**「工业开放标准」**→ 开放性；三个「可」——可互操作 / 可移植 / 可伸缩
- [ ] **A3 · 结构化原则** ⭕ 必背（关键词）
  **复杂系统设计的最基本方法依然是结构化系统分析设计方法**。把一个复杂系统分解成相对独立和简单的子系统，每个子系统再分解成更简单的模块，**自顶向下逐层模块化分解**，直到底层每个模块都是**可具体说明和可执行**的为止。
  > 判别词：**「自顶向下逐层模块化分解」**→ 结构化；这一思想至今仍是复杂系统设计的精髓
- [ ] **A4 · 先进性原则 + 主流化原则** ⭕ 必背（两层意义 + 配对）
  **先进性**有两层意义：**目前先进性和未来先进性**。系统的先进性是**建立在技术先进性之上**的；系统的先进性还表现在**系统设计的先进性**：**先进技术的有机集成、问题的合理划分，以及应用软件符合人们认知特点**等。
  - **主流化**：系统构成的**每一个产品应属于该产品发展的主流**，有可靠的技术支持，有成熟的使用环境，并具有良好的升级发展势头
  > 判别词：「两层意义 / 目前·未来」→ 先进性；「产品属于发展主流 / 可靠技术支持 / 成熟使用环境 / 良好升级势头」→ 主流化

### 模块 B ｜ 网络集成（5.3.2）

- [ ] **B0 · 网络集成体系框架七个子系统** ⭕ 必背（列举 + 数量）
  网络集成不仅涉及不同厂家的网络设备和管理软件，也会涉及**异构和异质网络系统的互联**问题。计算机网络集成的一般体系框架包含**七个子系统**：
  | 子系统 | 核心作用 |
  |---|---|
  | **传输子系统** | 网络的**核心**，网络信息的「**公路**」和「**血管**」 |
  | **交换子系统** | 按覆盖范围分局域网 / 城域网 / 广域网交换技术 |
  | **安全子系统** | 防火墙、数据加密、访问控制 |
  | **网管子系统** | 监控网络运行、找出并解决「瓶颈」 |
  | **服务器子系统** | 为工作站提供资源和服务（高性能、大内存、大磁盘、高可靠） |
  | **网络操作系统** | 调度和管理网络资源，提供统一透明的使用手段 |
  | **服务子系统** | 网络应用的核心（互联网服务、多媒体检索、信息广播、远程计算、事务处理） |
  > ⚠️ **防坑**：高项第 4 版是**七个子系统**（含**服务器子系统**和**网络操作系统**）；中级第 3 版口径是「**五大子系统**」（传输 / 交换 / 网管 / 安全 / 服务）——两卷别混
- [ ] **B1 · 传输子系统** ⭕ 必背（介质分类）
  **传输是网络的核心**，是网络信息的「公路」和「血管」。传输线路带宽的高低不仅体现了网络的通信能力，也体现了网络的现代化水平；传输介质在很大程度上决定了通信质量，从而直接影响网络协议。
  - **无线传输介质**：无线电波、微波、红外线等
  - **有线传输介质**：双绞线、同轴电缆、光纤等
  > 记法：无线「**电 · 微 · 红**」/ 有线「**双 · 同 · 光**」
- [ ] **B2 · 交换子系统** ⭕ 必背（三分类）
  网络按所覆盖的区域可分为**局域网、城域网和广域网**，由此网络交换也可分为**局域网交换技术、城域网交换技术和广域网交换技术**。
  > 判别词：题干出现「局域网 / 城域网 / 广域网」→ 交换子系统（不是传输）
- [ ] **B3 · 安全 / 网管 / 服务器 / 网络操作系统 / 服务子系统** ⭕ 必背（归属配对）
  - **安全子系统**：解决网络安全问题，包括**防火墙技术、数据加密技术和访问控制**等
  - **网管子系统**：保证网络良好运行，**找出并解决网络「瓶颈」**问题
  - **服务器子系统**：为工作站提供资源和服务，需考虑 CPU、内存、总线、磁盘容量 / 性能 / 容错、接口等
  - **网络操作系统**：**调度和管理网络资源**，为用户提供统一、透明的网络资源使用手段
  - **服务子系统**：网络服务是**网络应用的核心**，包括**互联网服务、多媒体信息检索、信息广播、远程计算和事务处理**等
  > 高频配对：「防火墙 / 加密 / 访问控制」→ 安全；「瓶颈」→ 网管；「统一透明的资源使用手段」→ 网络操作系统

### 模块 C ｜ 数据集成（5.3.3）

- [ ] **C0 · 数据集成的对象与关键** ⭕ 必背（两句定位）
  数据集成处理的主要对象是系统中**各种异构数据库中的数据**；**数据仓库技术是数据集成的关键**。数据集成的目的是运用一定的技术手段将系统中的数据按一定规则组织成为一个整体，使得用户能有效地对数据进行操作。
  > 判别词：**「数据仓库技术是数据集成的关键」**——直接考填空
- [ ] **C1 · 数据集成四层次总览** ⭕ 必背（分类列举）
  数据集成是将参与数据库的信息**逻辑上集成为一个异构分布式数据库的全局概念模式**，以实现信息共享。数据集成包括**四个层次**：
  > 记法：**「基 · 多视 · 模 · 多粒」**——基本数据集成 / 多级视图集成 / 模式集成 / 多粒度数据集成
- [ ] **C2 · 基本数据集成** ⭕ 必背（两个问题 + 解法）
  基本数据集成面临诸多问题，最核心的是**通用标识符问题**（同一实体在不同数据源中标识不同）和**数据丢失问题**。
  - 解决方法包括**隔离和调和**，以及**生成接近实际估计值**的方式处理数据丢失
  > 判别词：「**通用标识符问题**」「数据丢失」→ 基本数据集成
- [ ] **C3 · 多级视图集成** ⭕ 必背（三级两级映射）
  多级视图集成利用**多级视图机制**对数据源之间的关系进行集成，实现从**局部数据库到综合视图的映射**：**底层（局部模型）→ 中间层（公共模型）→ 高层（综合模型）**，是一个**两级映射**过程。
  > 判别词：出现「**局部模型 / 公共模型 / 综合模型**」→ 多级视图集成
- [ ] **C4 · 模式集成** ⭕ 必背（冲突类型 + 三种等价）
  模式集成是**数据库设计中的重要问题**，其设计好坏**常视设计者的经验**而定，在实际应用中可参考的成熟理论较少。需要**解决命名、结构等语义冲突**。
  - 基本框架如**属性等价、关联等价和类等价**，可最终归结为**属性等价**
  > 判别词：「语义冲突 / 设计取决于设计者经验」→ 模式集成；三等价「**属 · 关 · 类**」
- [ ] **C5 · 多粒度数据集成** ⭕ 必背（综合 / 细化）
  理想的多粒度数据集成模式是**自动逐步抽象**。
  - **数据综合（数据抽象）**：由**高精度**数据经抽象形成**精度较低但粒度较大**的数据（对各局域数据综合、提取主要特征）
  - **数据细化**：通过一定精度的数据**获取精度较高**的数据，主要途径有**时空转换、相关分析或者由综合中数据变动的记录进行恢复**
  > 判别词：「高精度 → 低精度 / 粒度变大」→ 数据综合；「低精度 → 高精度」→ 数据细化
- [ ] **C6 · 异构数据集成的方法** ⭕ 必背（★教材「两种 + 另一类」）
  数据集成的目的是为应用提供**统一的访问支持**，因此集成后的数据必须保证一定的完整性，包括**数据完整性和约束完整性**；还**必须考虑语义冲突**问题。
  - **异构数据集成方法归纳起来主要有两种**：
    1. **过程式方法**：一般根据一组信息需求，采用**点对点（Ad-hoc）**的设计方法来集成数据。依赖 **Wrapper（封装数据源）** + **Mediator（合并和一致化数据）**，软件模块不需要关于完整数据模式的清晰概念
    2. **声明式方法**：通过**一套合适的语言**对多个数据源的数据进行**建模**，构建**统一的数据表示**，并**基于这一数据表示对整体系统数据进行查询**，通过一套有效的**推理机制**存取数据源
  - **另一类方法**：利用**中间件**集成异构数据库——**不需要改变原始数据的存储和管理方式**；中间件位于**异构数据库系统（数据层）和应用程序（应用层）之间**，向下协调各数据库系统、向上提供**统一的数据模式和数据访问的通用接口**
  > 🚩 **本节点睛**：教材原话是「**归纳起来主要有两种，分别是过程式方法和声明式方法**」+「**另一类**方法是中间件」——**别答「三种方法」**
- [ ] **C7 · 开放数据库互联标准与数据交换标准** ⭕ 必背（提取 + 全局模式）
  - **开放数据库互联标准（ODBC）**：实现异构数据源集成，**首先要解决原始数据的提取**；从异构数据库提取数据大多采用 ODBC（数据库系统之间存取数据的**标准应用程序接口**）。另一种提取方法是**针对不同数据源编写专用的嵌入式 C 接口程序**，可**提高提取速度**
  - **基于 XML 的数据交换标准**：使用中间件集成异构数据源时，需要为中间件选择一种**全局数据模式**，来统一异构数据源的数据模式。全局模式需满足：**① 能描述各种数据格式（结构化或半结构化）；② 易于发布和进行数据交换**
  - **基于 JSON 的数据交换格式**：随着 **AJAX 技术**的兴起，JSON 作为一种**轻量级的数据交换格式**，以其**易于阅读和编写**的优点被越来越多地应用
  > 高频：ODBC = 异构数据源提取的**标准 API**；全局模式两条要求；JSON ↔ AJAX

### 模块 D ｜ 软件集成（5.3.4）

- [ ] **D0 · 软件集成的五大构件标准** ⭕ 必背（列举）
  软件集成要实现不同软件的互操作，核心是**遵循构件标准**。有代表性的软件构件标准包括：**公共对象请求代理结构（CORBA）、COM、DCOM 与 COM+、.NET、J2EE 应用架构标准**。
  > 记法：**「CORBA · COM · DCOM/COM+ · .NET · J2EE」**五件
- [ ] **D1 · CORBA** ⭕ 必背（制定者 + 作用）
  **CORBA（公共对象请求代理结构）**：**对象管理组织（OMG）**是其规范的制定者，由 800 多个信息系统供应商、软件开发者和用户共同构成的国际组织，建立于 **1989 年**。OMG 的目的是**将对象和分布式系统技术集成为一个可相互操作的统一结构**，此结构既支持现有的平台也将支持未来的平台集成。
  - CORBA 可**自动匹配许多公共网络任务**：对象登记、定位、激活多路请求、组帧和错误控制、参数编排和反编排、操作分配等
  > 判别词：「OMG 制定」「面向对象的分布式对象计算标准」→ CORBA
- [ ] **D2 · COM 及软件集成五特征** ⭕ 必背（对象形式 + 五特征）
  **COM**：对象是一种**二进制代码对象**，其代码形式是 **DLL 或 EXE 执行代码**，对象都被**直接注册在 Windows 的系统库中**，是由**系统平台直接支持**的对象。
  - COM 具备了软件集成所需要的许多特征，包括**面向对象、客户机 / 服务器、语言无关性、进程透明性和可重复性**
  > 记法：五特征「**对 · 客 · 语 · 进 · 可**」——面向对象 / 客户机服务器 / 语言无关性 / 进程透明性 / 可重复性
- [ ] **D3 · DCOM 与 COM+** ⭕ 必背（扩展特性）
  **DCOM 与 COM+**：作为 COM 的**扩展**，针对分布环境还提供了一些新的特性，如**位置透明性、网络安全性、跨平台调用**等。
  - **COM+** 是 COM 的新发展（COM 更高层次上的应用），底层结构仍以 COM 为基础，几乎包容了 COM 的所有内容。COM+ 把 COM 组件软件**提升到应用层**而**不再是底层的软件结构**，把所有组件的底层细节留给操作系统——因此 **COM+ 与操作系统的结合更加紧密**
  > 判别词：「位置透明性 / 网络安全性 / 跨平台调用」→ DCOM；「提升到应用层」→ COM+
- [ ] **D4 · .NET 与 J2EE** ⭕ 必背（★技术清单配对）
  - **.NET**：是**基于一组开放的互联网协议**，推出的一系列产品、技术和服务。涉及的技术：**VB、C++、C#、JScript、ASP.NET、ADO.NET**
  - **J2EE**：使用 Java 技术开发组织级应用的一种**事实上的工业标准**，为搭建具有**可伸缩性、灵活性、易维护性**的组织系统提供了良好的机制。其**体系结构分为客户端层、服务器端组件层、EJB 和信息系统层**；涉及的技术：**EJB、Java Servlets API、JSP 和 XML**
  > ⚠️ **最易混**：C#/VB/ASP.NET/ADO.NET 属 **.NET**；EJB/Servlet/JSP 属 **J2EE**。四层 = 客户端层 / 服务器端组件层 / EJB / 信息系统层

### 模块 E ｜ 应用集成（5.3.5）

- [ ] **E0 · 语法 · 语义 · 语用三对应** ⭕ 必背（★教材点睛句）
  从信息系统集成技术的角度看，**网络集成解决语法的问题，数据集成解决语义的问题，应用集成解决语用的问题**；在集成的堆栈上，**应用集成在最上层**，主要解决**应用的互操作性问题**。
  > 高频：三句一一对应，考排序 / 配对，**别把「语用」配给数据集成**
- [ ] **E1 · 应用集成（EAI）的定义与技术要求** ⭕ 必背（定义 + 三项要求）
  **应用集成或组织应用集成（EAI）**是指将**独立的软件应用连接起来，实现协同工作**。借助应用集成，组织可以提高运营效率、实现工作流自动化，并增强不同部门和团队之间的协作。
  - 对应用集成的**技术要求**大致有：**① 具有应用间的互操作性；② 具有分布式环境中应用的可移植性；③ 具有系统中应用分布的透明性**
  > 记法：三要求「**互操作 · 可移植 · 透明性**」
- [ ] **E2 · 可协调连接各种应用的组件** ⭕ 必背（列举三件）
  可以协调连接各种应用的组件有：**应用编程接口（API）、事件驱动型操作、数据映射**。
  > 记法：**「API · 事件 · 映射」**三件——API 定义交互规则、事件驱动由触发器启动、数据映射统一不同系统数据字段
- [ ] **E3 · EAI 四层次与黑白盒配对** ⭕ 必背（★层次 + 黑白盒）
  从单个企业的角度，**EAI 可以包括表示集成、数据集成、控制集成和业务流程集成等多个层次**（也可以在多个企业之间进行应用集成）。
  | 层次 | 别称 | 黑白盒 | 核心定位 |
  |---|---|---|---|
  | **表示集成** | 界面集成 | **黑盒集成** | 最原始、最浅层次；把零散系统界面集中到新界面 |
  | **数据集成** | — | **白盒集成** | 集成点在**中间件**；先对数据标识并编成目录、确定元数据模型 |
  | **控制集成** | 功能集成 / 应用集成 | **黑盒集成** | 在**业务逻辑层**上集成；集成点存于程序代码中 |
  | **业务流程集成** | 过程集成 | — | 超越数据和系统，由一系列基于标准的、统一数据格式的**工作流**组成 |
  > 🚩 **本节点睛**：**数据集成是唯一的白盒集成**（其余黑盒）；「在业务逻辑层上进行黑盒集成」→ **控制集成**
- [ ] **E4 · 各集成层的实现技术** ⭕ 必背（技术归属）
  - **表示集成**：无需了解程序与数据库的内部构造，常用的集成技术主要有**屏幕截取技术和输入模拟技术**
  - **数据集成**：集成之前必须首先**对数据进行标识并编成目录**，然后**确定元数据模型**，保证数据在数据库系统中分布和共享
  - **控制集成**：集成点存于程序代码中，可借助**远程过程调用（RPC）或远程方法调用（RMI）、面向消息的中间件、分布式对象技术和事务处理监控器**来实现；集成处可能只需简单使用**公开的 API** 就可以访问
  - **业务流程集成**：企业必须对各种业务信息的**交换进行定义、授权和管理**，以便改进操作、减少成本、提高响应速度
  > 配对：「屏幕截取 / 输入模拟」→ 表示集成；「元数据模型」→ 数据集成；「RPC / RMI / 消息中间件」→ 控制集成
- [ ] **E5 · 事件驱动的企业应用集成（EDA）** ⭕ 必背（机制）
  **事件驱动架构（Event-Driven Architecture，EDA）**是一种设计和构建应用的方法：**事件触发消息在独立的、非耦合的模块之间传递**（模块之间不需要知道对方）。**事件源**通常发送消息到**中间件或消息代理**，**订阅者**订阅这个消息。
  - 因为事件消息用**发布 / 订阅**方式通过消息代理传输，**一个事件可以传送给多个订阅者**
  - EDA 的主要优势：允许企业通过**事件管理**来标识和响应一个或多个系统中的事件
  > 判别词：「发布 / 订阅」「事件源 → 消息代理 → 订阅者」「一个事件多个订阅者」→ EDA

## 二、只通读清单（知道即可，别背）

- [ ] **F0 · 系统集成的地位与价值**
  系统集成是信息系统实施中一项重要的工作，「**以计算机有关技术储备为基础，以可靠的产品为工具，用以实现某一特定的计算机系统功能组合的工程行为**」；**系统集成是开放系统驱动的**，顺应了计算机工业发展的潮流；系统集成工作的好坏对系统开发、维护有极大的影响。
- [ ] **F1 · 信息孤岛与 EAI 的意义**
  企业信息化建设中缺乏统一规划和总体布局，往往形成多个**信息孤岛**（数据一致性无法保证、信息无法共享和反馈、需重复采集输入）；其成因既有**技术因素**也有**管理因素**，还有**业务流程和标准**方面的因素。**EAI 技术可以消除信息孤岛**，将多个企业信息系统连接起来实现无缝集成，使它们像一个整体一样。
- [ ] **F2 · EAI 所连接的应用类型**
  EAI 所连接的应用包括各种**电子商务系统、ERP、CRM、SCM、OA、数据库系统和数据仓库**等。
- [ ] **F3 · 中级 vs 高项的网络集成子系统数（防坑提醒）**
  **高项第 4 版 = 七个子系统**（比中级多出**服务器子系统**与**网络操作系统**）；中级第 3 版（系统集成项目管理工程师）= **五大子系统**（传输 / 交换 / 网管 / 安全 / 服务）。两卷真题混刷时注意口径差异。
- [ ] **F4 · 数据集成的地位**
  数据集成是**最终实现数据共享和辅助决策的基础**；数据集成还必须考虑**语义冲突**问题——信息资源之间存在的语义区别可能引起各种矛盾（从简单的名字语义冲突到复杂的结构语义冲突）。

## 四、自检题（先自答，再展开对答案）

<details>
<summary>1. 系统集成的四大基本原则是什么？各自的关键判别词是什么？</summary>

**开放性、结构化、先进性、主流化**。
- 开放性 → 「工业开放标准」；满足可互操作性、可移植性、可伸缩性
- 结构化 → 「自顶向下逐层模块化分解」
- 先进性 → 两层意义（目前先进性 / 未来先进性），建立在技术先进性之上
- 主流化 → 「产品属于该产品发展的主流」，有可靠技术支持、成熟使用环境、良好升级势头

</details>

<details>
<summary>2. 计算机网络集成的体系框架包含哪些子系统？各自作用是什么？</summary>

**七个子系统**：**传输**（网络核心，「公路」「血管」）· **交换**（局域网/城域网/广域网交换技术）· **安全**（防火墙、数据加密、访问控制）· **网管**（监控运行、解决「瓶颈」）· **服务器**（为工作站提供资源和服务）· **网络操作系统**（调度管理网络资源，提供统一透明使用手段）· **服务**（互联网服务、多媒体检索、信息广播、远程计算、事务处理）。

⚠️ 中级第 3 版是「五大子系统」（无服务器子系统和网络操作系统）。

</details>

<details>
<summary>3. 数据集成分为哪四个层次？「多级视图集成」的映射关系是怎样的？</summary>

四层次：**基本数据集成、多级视图集成、模式集成、多粒度数据集成**。
多级视图集成 = **底层（局部模型）→ 中间层（公共模型）→ 高层（综合模型）** 的**两级映射**，实现从局部数据库到综合视图的映射。

</details>

<details>
<summary>4. 异构数据集成的方法有几种？分别是什么？</summary>

教材原文：**归纳起来主要有两种**——**过程式方法**和**声明式方法**；**另一类方法**是利用**中间件**集成异构数据库。
- 过程式：点对点（Ad-hoc）设计，用 **Wrapper 封装数据源 + Mediator 合并一致化数据**
- 声明式：用一套合适语言**建模**，构建**统一数据表示**，通过**推理机制**存取
- 中间件：**不改变原始数据存储和管理方式**，位于数据层与应用层之间

🚩 别答「三种方法」——教材把中间件定位为「另一类」（不在「两种」之内）。

</details>

<details>
<summary>5. 软件集成有哪些代表构件标准？COM 具备哪些软件集成特征？</summary>

五大标准：**CORBA、COM、DCOM 与 COM+、.NET、J2EE**。
COM 具备的特征：**面向对象、客户机/服务器、语言无关性、进程透明性和可重复性**（五特征）。

</details>

<details>
<summary>6. .NET 与 J2EE 各自涉及哪些技术？J2EE 体系结构分哪几层？</summary>

- **.NET**：VB、C++、C#、JScript、ASP.NET、ADO.NET
- **J2EE**：EJB、Java Servlets API、JSP 和 XML；体系结构分**客户端层、服务器端组件层、EJB、信息系统层**四层

</details>

<details>
<summary>7. EAI（企业应用集成）包括哪几个层次？各自是黑盒还是白盒集成？</summary>

四层次：**表示集成、数据集成、控制集成、业务流程集成**。
- 表示集成（界面集成）：**黑盒集成**
- 数据集成：**白盒集成**（集成点在中间件）——**唯一白盒**
- 控制集成（功能集成/应用集成）：**黑盒集成**（业务逻辑层）
- 业务流程集成（过程集成）：由一系列基于标准的、统一数据格式的工作流组成

</details>

<details>
<summary>8. 教材中「网络集成 / 数据集成 / 应用集成」分别解决什么问题？</summary>

**网络集成解决语法的问题，数据集成解决语义的问题，应用集成解决语用的问题**；应用集成在最上层，主要解决应用的互操作性问题。

</details>

<details>
<summary>9. 对应用集成的技术要求有哪些？可以协调连接各种应用的组件有哪几种？</summary>

技术要求三项：**应用间的互操作性、分布式环境中应用的可移植性、系统中应用分布的透明性**。
可协调连接各种应用的组件：**应用编程接口（API）、事件驱动型操作、数据映射**。

</details>

<details>
<summary>10. 什么是 EDA？它的消息传递机制是怎样的？</summary>

**事件驱动架构（EDA）**：事件触发消息在**独立的、非耦合的模块之间**传递（模块之间不需要知道对方）。**事件源**发送消息到**中间件或消息代理**，**订阅者**订阅该消息；采用**发布/订阅**方式，**一个事件可传送给多个订阅者**。EDA 允许企业通过**事件管理**来标识和响应一个或多个系统中的事件。

</details>

<details>
<summary>11. 表示集成、数据集成、控制集成各自常用的实现技术 / 关键动作是什么？</summary>

- **表示集成**：**屏幕截取技术、输入模拟技术**（无需了解程序与数据库内部构造）
- **数据集成**：先对数据**标识并编成目录**，确定**元数据模型**
- **控制集成**：借助 **RPC/RMI、面向消息的中间件、分布式对象技术、事务处理监控器**；集成处可能只需简单使用**公开的 API**

</details>

<details>
<summary>12. 「基本数据集成」要解决哪两个核心问题？「模式集成」的三类等价是什么？</summary>

基本数据集成：**通用标识符问题**和**数据丢失问题**；解决方法包括**隔离和调和**，以及生成接近实际估计值处理数据丢失。
模式集成三类等价：**属性等价、关联等价和类等价**（可最终归结为属性等价）。

</details>
