5.1.1 架构设计
1架构研究内容与根本目的
  • 研究内容四件套：软件架构描述、软件架构风格、软件架构评估、软件架构的形式化方法
  • 根本目的：解决好软件的复用、质量和维护问题（口诀「复质维」）
  • 软件架构设计的一个核心问题是能否达到架构级的软件复用
「核心问题 = 架构级复用」与「根本目的 = 复用质量维护」两句别互串
2五大架构风格及子风格（口诀：数调独虚仓）
  • 数据流风格：批处理序列（顺序执行）、管道/过滤器（输入输出数据流）——输出正确性不依赖过滤器执行顺序
  • 调用/返回风格：主程序/子程序、数据抽象和面向对象、层次结构
  • 独立构件风格：进程通信、事件驱动的系统
  • 虚拟机风格：解释器、基于规则的系统
  • 仓库风格：数据库系统、黑板系统、超文本系统
  • 面向对象风格缺点：对象调用需知道对象标识，标识改变须通知所有调用者
高频对位陷阱：「层次结构」属调用/返回（不是独立构件）；「事件驱动」属独立构件；「解释器」属虚拟机；「黑板」属仓库
3架构评估：敏感点 / 权衡点 / 三方式
  • 评估关注的是系统的质量属性
  • 敏感点：影响单个质量属性的构件特性
  • 权衡点：影响多个质量属性的特性 = 多个质量属性的敏感点（如加密级别：安全性↑性能↓）
  • 三类评估方式：基于调查问卷（检查表）、基于场景（最常用）、基于度量
  • 场景法三工具：ATAM（架构权衡分析法）、SAAM（软件架构分析法）、CBAM（成本效益分析法）
⚠️ ATAM / SAAM / CBAM 都是「基于场景」的方式；「影响多个质量属性」→ 必答权衡点
5.1.2 需求分析
4需求三层次 + QFD 三类需求
  • 业务需求：反映企业或客户对系统高层次的目标追求（来自投资人 / 客户 / 管理层）
  • 用户需求：描述用户的具体目标，或用户要求系统必须能完成的任务
  • 系统需求：从系统角度说明软件需求，包括功能需求、非功能需求和设计约束
  • QFD：将用户要求转化成软件需求的技术，目的是最大限度提升用户满意度
  • 常规需求：应该实现，实现越多用户越满意
  • 期望需求：用户想当然以为应具备但不能正确描述；不实现会不满意
  • 意外需求：也称兴奋需求，用户要求范围之外的功能或性能
三层次从「目标到具体、从整体到局部、从概念到细节」；「想当然」= 期望需求、「越实现越满意」= 常规需求
5需求过程四环节 + 获取方法 + 八特性
  • 需求过程：需求获取 → 需求分析 → 需求规格说明书编制 → 需求验证与确认
  • 需求获取：确定和理解不同项目干系人的需求和约束的过程
  • 获取方法五种：用户访谈、问卷调查、采样、情节串联板、联合需求计划
  • 好需求八特性：无二义性、完整性、一致性、可测试性、确定性、可跟踪性、正确性、必要性
八特性没有「可扩展性 / 经济性」这类干扰项；四环节顺序：先获取 → 再分析 → 后编制 → 终验证
6SA 三模型 + OOA + SRS
  • SA 建立的模型核心是数据字典
  • 三模型配对：数据模型=E-R 图 / 功能模型=DFD 数据流图 / 行为模型=STD 状态转换图
  • OOA 模型包括用例模型和分析模型；用例模型四阶段：识别参与者 → 合并需求获得用例 → 细化用例描述 → 调整用例模型
  • SRS 是需求开发活动的产物，软件开发过程中最重要的文档之一，任何规模和性质的项目都不应该缺少；编制目的是使干系人与开发团队对初始规定有共同理解，成为整个开发工作的基础
  • 需求评审就是对 SRS 进行技术评审
⚠️ SA 的核心是数据字典，不是 DFD；「数 E-R · 功 DFD · 行 STD」三对配对年年考
7UML：事物 / 关系 / 五视图
  • 事物（建模元素）四类：结构事物、行为事物、分组事物、注释事物
  • 关系四类：依赖（一个事物变化影响另一事物语义）、关联（对象间链接的结构关系）、泛化（一般化与特殊化）、实现（一个类制定由另一个类保证执行的契约）
  • 14 图中常考：顺序图强调消息的时间次序、通信图强调对象的组织结构、状态图描述对象生命周期、部署图描述软件到硬件的映射
  • 五视图：逻辑视图（也称设计视图）、进程视图、实现视图、部署视图、用例视图；用例视图是最基本的需求分析模型
⚠️ 教材口径是「UML 五视图」：逻辑 / 进程 / 实现 / 部署 / 用例——别与架构师考试的「4+1 视图」（逻辑 / 开发 / 进程 / 物理 / 场景）混
5.1.3 软件设计
8SD 与 OOD
  • 结构化设计（SD）：面向数据流；以 SRS 和 SA 产生的 DFD 和数据字典为基础；自顶向下、逐步求精、模块化
  • SD 两阶段：概要设计（又称总体结构设计）+ 详细设计；基本原则：高内聚、低耦合
  • OOD 是 OOA 的延续，基本思想：抽象、封装、可扩展性（可扩展性通过继承和多态实现）
  • 三大特征：封装、继承、多态
  • 七大原则口诀「单开李依接组迪」：单一职责 / 开闭 / 里氏替换 / 依赖倒置 / 接口隔离 / 组合重用 / 迪米特（最少知识）
「总体结构设计」就是概要设计的别称——别当成第三种设计
9设计模式：两类范围 + 三种用途
  • 按处理范围：类模式、对象模式
  • 创建型（用于创建对象）：工厂方法、抽象工厂、原型、单例、建造者
  • 结构型（处理类或对象的组合）：适配器、桥接、组合、装饰、外观、享元、代理
  • 行为型（描述交互及职责分配）：观察者、策略、命令、状态等 11 种
高频对位：单例 = 创建型、代理 = 结构型、观察者 = 行为型；「用途」口诀：创建建对象 · 结构管组合 · 行为交互职责
5.1.4 软件实现
10配置管理 + 编码 + 静态测试
  • 配置管理六项：配置管理计划、配置标识、配置控制、配置状态记录、配置审计、分布（发布）管理与交付
  • 编码三关注点：程序设计语言的选择、程序设计风格（源程序文档化 / 数据说明 / 语句结构 / 输入输出）、编码效率
  • 软件测试目的：验证软件是否满足合同 / 开发计划 / SRS / 设计说明等规定的质量要求
  • 静态测试：人工检测 + 计算机辅助静态分析，不实际运行程序；文档用检查单，代码三手段：桌前检查、代码走查、代码审查
  • 静态测试可发现约 30% ~ 70% 的逻辑设计和编码错误
代码三手段口诀「桌走审」；静态测试方法也可以实现白盒测试（易考判断）
11白盒 vs 黑盒（三线对齐）
  • 白盒 = 结构测试：了解程序内部结构和处理算法；主要用于单元测试；最常用技术 逻辑覆盖（另有控制流 / 数据流 / 程序编译测试）
  • 黑盒 = 功能测试：只检查功能能否按 SRS 正常使用；主要用于集成测试、确认测试和系统测试；方法：等价类划分、边界值分析、判定表、因果图、状态图、随机测试、猜错法、正交试验法
口诀「白盒单元逻辑覆盖 · 黑盒集成确认系统等价边界」——别名 / 阶段 / 方法三条线要能同时对上
5.1.5 + 5.1.6 部署与过程
12持续交付部署 / 蓝绿金丝雀 / CSMM
  • 软件部署与交付：生命周期重要环节、开发后期活动，通过配置、安装、激活保障制品运行
  • 持续交付：一系列开发实践方法，确保代码快速、安全部署到生产环境；完全自动化、一键部署；三阶段方案 = 需求用用户故事 / 开发测试持续集成 / 运维打通开发运维、环境统一
  • 持续部署：容器技术最流行（Kubernetes+Docker、Matrix）；部署层次 Build→Ship→Run；不可变服务器 = 除更新和安装补丁外不对服务器做任何更改
  • 蓝绿部署：新旧两版本 + 域名解析切换，可快速切回旧版本；金丝雀部署：先让少量用户试用观察，正常后稳步推广（灰度）
  • CSMM：《软件过程能力成熟度模型》，4 个能力域、20 个能力子域、161 个能力要求；五级：初始级 → 项目规范级 → 组织改进级 → 量化提升级 → 创新引领级（口诀「初规组量引」）
  • 四能力域：治理（战略与治理 / 目标管理）、开发与交付（需求设计开发测试部署服务开源应用）、管理与支持（策划监控结项质保风险配置供应商）、组织管理（过程人员资源过程能力）
⚠️ 蓝绿 = 两套环境整体切换、金丝雀 = 小流量灰度；CSMM ≠ CMMI（CMMI：初始 / 已管理 / 已定义 / 量化管理 / 优化）
总结区 本节本质 + 考点地图
本节本质：软件工程是第 5 章的技术骨架，六小节一条线（架构 → 需求 → 设计 → 实现 → 部署 → 过程），上午 2~3 题，主流题型是归属配对 + 关键词辨析。
考点地图（按考频排序）：① 白盒 vs 黑盒（别名 / 阶段 / 方法三线）→ ② 五大架构风格及子风格归属 → ③ SA 核心数据字典 + 三模型三图 → ④ 敏感点 vs 权衡点 + 场景法最常用 → ⑤ QFD 三类需求判别词 → ⑥ 蓝绿 vs 金丝雀 + build-ship-run → ⑦ UML 事物关系五视图 → ⑧ OOD 七原则 + 设计模式三型 → ⑨ CSMM 三数字 + 五等级 → ⑩ 需求过程四环节 + 获取方法五种。
⚠️ 口径陷阱：①SA 核心是数据字典不是 DFD；②层次结构属调用/返回、事件驱动属独立构件、解释器属虚拟机、黑板属仓库；③「影响多个质量属性」= 权衡点；④ATAM/SAAM/CBAM 都基于场景；⑤白盒=结构测试=单元=逻辑覆盖，黑盒=功能测试=集成/确认/系统=等价类/边界值；⑥UML 五视图（逻辑/进程/实现/部署/用例），用例视图=最基本需求分析模型，≠ 4+1 视图；⑦概要设计=总体结构设计；⑧蓝绿=整体切换、金丝雀=灰度；⑨CSMM 五级「初规组量引」≠ CMMI「初已定量化优化」；⑩部署层次 Build→Ship→Run 顺序别乱。
